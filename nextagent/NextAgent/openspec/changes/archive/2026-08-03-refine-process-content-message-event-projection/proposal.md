## Why

电信网络诊断任务通常包含多轮模型说明、工具调用和工具结果。用户在任务执行期间、重新打开历史会话以及从历史回复派生子会话时，需要看到语义一致、顺序一致且不重复的执行过程。当前系统同时在消息与时间线事件中保存部分过程正文，不同过程内容采用了不同的恢复方式；这使同一段公开内容可能被重复保存或重复显示，也使执行说明在刷新、历史加载或派生会话中存在丢失、错序或无法可靠关联的风险。

该问题已经影响用户对长任务是否按预期推进的判断，也增加了历史问题复盘和诊断证据追溯的不确定性。上一个 Change 已完成过程面板的活动状态和折叠交互优化；现在需要先统一其依赖的内容事实与时序事实边界，避免后续展示策略继续建立在不一致的数据来源上。

## 目标与非目标（Goals / Non-Goals）

**目标：**

- 对已经持久化为消息的公开过程内容，消息是唯一正文事实；对应事件只表达时序、状态和对消息的关联，不再重复保存正文。
- 同一过程内容在实时流、历史会话和派生会话中保持一致的顺序、内容与安全可见性，不重复、不串会话。
- Tool 轮次的公开执行说明从进行中待定状态开始就在用户界面中连接其前置思考与后续 Tool 调用，不先进入最终答案位置，也不被呈现为带独立状态图标、独立底色或独立边框的过程步骤；说明正文与展开后的 thinking 正文左边界对齐，并复用最终答案的公开正文排版与 Markdown 渲染语义。
- 关联缺失、越权、损坏或无法安全解析时，系统明确降级为仅显示过程状态，不回退读取不可信正文，也不把错误伪装成完整历史。
- 大数据量多轮会话加载过程内容时复用有界、批量的消息与事件读取；用户快速点击预览、拖动或点击滚动条、连续滚轮滚动时，不产生与跨越轮数成正比的历史请求。

**非目标：**

- 不改变最终 Assistant Message 的持久化和展示语义。
- 不把 reasoning/thinking 持久化为消息；相关演进由后续独立 Change 定义。
- 不新增集成方展示级别或工具输入输出披露配置；相关策略由后续独立 Change 定义。
- 除执行说明从独立过程步骤收敛为桥接正文外，不改变既有 thinking、Tool/PIU 卡片和普通过程步骤的视觉样式、折叠动效、活动图标或用户手工展开规则；执行说明不新增第二层 disclosure。
- 不新增 Gateway 公共 port、查询参数、Record、表或远端服务契约，也不改变 Owner Scope、Agent Scope、request lifecycle、terminal commit、ActiveContext 或 Provider 输入语义。
- 不新增 timeline event type、`SessionMessageRole` 或 `StreamEnvelope` 顶层字段。

## What Changes

- 修改过程内容的公共事件语义：当公开过程正文已经由消息持久化时，对应可恢复事件必须携带可校验的消息引用，并且不得再携带该正文副本；仅用于进行中反馈且尚未形成持久化消息的 live delta 保持现有临时投影语义。
- 修改实时和历史过程投影：系统在服务端按可信会话、请求和运行坐标关联事件与消息，向用户返回经过现有安全投影后的同一份过程内容；浏览器不得接收或自行遍历原始隐藏消息来重建关联。
- 修改执行说明的浏览器投影：尚未确定是否调用 Tool 的进行中公开输出先显示在无独立图标的待定桥接位置；同一 Tool 轮次的完成说明在原位置接管并位于关联 Tool 调用之前，且在实时与历史视图保持一致。待定正文、完成说明和最终答案复用同一公开正文排版，最终答案接管时保持既有答案对齐，并只允许不改变透明度、字体和换行的短距离位置过渡。
- 修改历史恢复失败语义：引用不存在、作用域不一致、消息类型不匹配或内容无法安全投影时，该过程项只能保留类型、顺序和状态，并显示安全的内容不可用结果；系统不得回退使用事件中的旧正文副本。
- 修改派生会话过程快照：需要保留的消息引用必须映射为子会话内的新消息标识；无法完成安全映射时，派生操作保持既有原子失败语义。
- 增加历史读取容量保证：过程历史关联必须使用既有有界查询完成，不得为每条事件或每条消息发起独立 Web 请求；单会话至少包含 10,000 个可见用户轮次且每轮包含多个 thinking 与 Tool 过程项时，快速导航不得触发与跨越轮数成正比的请求。

## Feature 影响（Features）

### 修改的 Feature

- `F-1.1 实时查看处理过程`：用户在实时执行期间看到的公开过程内容由消息事实与事件时序共同形成，且待定公开输出与 Tool 轮次执行说明连续连接思考与 Tool 调用，不会先出现在答案位置，也不会因双份正文或独立步骤表达产生误解。
- `F-1.2 断线重连恢复`：用户刷新、重连或重新打开会话时，可以按同一关联和呈现规则恢复已持久化的过程内容；关联失败时得到显式安全降级。
- `F-1.6 基于历史回复新建会话`：派生会话中的过程快照只引用子会话拥有的消息，不保留可解析到源会话正文的消息引用。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

无。

### 修改的 Function

- `FN-1.1 查看会话消息流` → `specs/ts-web-sse-ws-transports/spec.md`
  - 功能边界：实时过程事件对已持久化正文使用消息引用，SSE 与 WebSocket 通过同一服务端关联结果投影内容；尚未定性的公开输出先进入待定桥接位置，同轮执行说明连续连接前置 thinking 与后续 Tool 调用，关联失败时只返回安全状态。
  - 系统质量属性：安全。
  - 映射说明：canonical spec。
- `FN-1.2 断线后从上次位置继续` → `specs/ts-stream-history-consistency/spec.md`
  - 功能边界：过程历史按消息正文事实与事件时序事实恢复，并保持执行说明与 Tool 调用的连续呈现；采用有界批量读取并在大数据量快速导航中抑制过时请求。
  - 系统质量属性：性能/容量、可靠性/恢复。
  - 映射说明：canonical spec。
- `FN-1.11 从消息派生子会话` → `specs/session-fork-from-message/spec.md`
  - 功能边界：派生会话过程快照中的消息引用必须指向子会话消息；引用无法安全重映射时派生失败且不产生部分子会话。
  - 系统质量属性：安全、可靠性/恢复。
  - 映射说明：canonical spec。

## 影响范围（Impact）

- 最终用户：实时、历史与派生会话中的执行说明和工具过程内容更一致，缺失内容会显式降级而不是重复、错序或静默消失。
- 平台集成方：既有 Web stream 与历史 API 路径保持不变；过程内容的关联与安全投影由服务端完成，不要求浏览器读取隐藏消息。
- 公共契约：既有 timeline event payload 对部分事件增加消息引用语义并禁止正文副本；不增加事件类型或顶层传输字段。
- Gateway：复用既有消息与事件查询能力；公共 contract 和持久化模型不变，本地存储实现可能增加面向 run 范围读取的查询索引。
- 测试：增加消息优先写入、事件引用校验、实时/历史等价、派生引用重映射、失败降级、Owner/Agent Scope 隔离和 10,000 用户轮次容量验证。
