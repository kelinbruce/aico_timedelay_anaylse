目标：

- 由 `agent-model` 建立全局模型目录，统一拥有 provider binding、模型安全配置、可选调用默认值、上下文窗口、fallback index 和 provider-specific metadata 解析；合法子 profile 通过校验后即进入目录，Gateway metadata 由首次 safe query 按需解析。
- `modelProfiles[]` 父层以唯一 `providerId` exact lookup 已装配 provider registration；本 change 的产品配置清单恰好为 `openai-compatible | model-gateway`。`openai-compatible` 要求 `baseUrl`，`model-gateway` 禁止 `baseUrl`；两者都允许 optional `credentialRef`，缺失时不发送 credential。子层每个 `ModelProfile` 以全局唯一 `modelId` 同时作为 Agent 激活、选择、调用身份和实际传给 provider 的模型标识；可选 `displayName` 只用于人类阅读。
- Agent 使用 required non-empty ordered unique `AgentAssembly.modelIds` 激活模型；不存在 singular Agent `modelId` 配置。`defaultModelId` 可省略，存在时必须属于 `modelIds`；省略时 initial selection 使用顺序中的第一个 eligible model。assembly 不复制模型配置，也不拥有全局模型清单。
- 由 `agent-context-engine` 通过唯一 async/cancellable selection port 提供所有调用目的的初始与 fallback 模型选择；主 Agent loop、summary、memory extraction、suggested questions 和 workflow model nodes 都消费该 port。
- 由 `agent-core` 编排主 Agent loop 的 fallback 生命周期 gate、attempted ids 与 evidence，下一模型及其渲染输入来自 Context Engine；secondary consumers 保留既有失败/降级语义。
- `CapabilityInvocationResult.contextPatch` 使用 optional canonical `modelId` 和八字段 closed inference `modelOptions`；`providerOptions` 只接受已接受的受治理 Skill metadata mapping，合法 patch 只影响同一 request/run 的后续模型步骤。
- 同步 RESERVED plugin policy inventory：模型选择只标记 `agent-context-engine` owner；fallback 明确拆分为 Core lifecycle gate 与 Context Engine target selection，且两个 policy point 继续不可激活。
- 收窄 `ModelInvocationRequest` 为 selected `modelId`、trusted invocation scope、动态调用输入、扁平可选通用参数和受控 optional `providerOptions`；owning run-bound orchestrator 将 owning `stepId` 的同一值作为 scope `operationId` 与 accepted run coordinates 原子写入单一 scope，locale 属于 selection/prompt assembly，provider identity、header、endpoint、credential reference 与 transport 由 `agent-model` 内部绑定解析。
- 使用 `ai` 与 `@ai-sdk/openai-compatible` 的 AI SDK 6 标准路径适配 OpenAI-compatible Chat Completions、thinking、tool call、stream、总时限内同模型 recoverable retry 和 best-effort usage；环境相关 fetch 由通用 optional `FetchGateway` 经 app composition 适配给模型 registration，当前 change 不迁移其他 REST client，也不建立 outbound header policy。
- model observation 保留 duration、usage、first-visible、failure 和 stable refs，不把 step/model/provider identity 投影到 trace/log/metric；6 个 model metrics 删除 `provider_kind` label，不使用 canonical identity 或固定 `OTHER` 替代。

规格输入：

- 全局 catalog 是 ready 后唯一模型配置权威，safe query、selection 和 invocation authorization 分别由其 owning contract 协作。
- safe catalog query 暴露封闭 `AVAILABLE | UNAVAILABLE` `ModelCatalogEntry`。`AVAILABLE` entry 携带 `ResolvedModelConfiguration`，模型身份只在 `configuration.modelId` 出现；`UNAVAILABLE` entry 因没有 configuration 而携带顶层 `modelId` 和低基数安全原因。selection 原样复用 available entry 的 frozen configuration，query 与 selection 不维护两种模型配置 shape。exact matching 和 provider 调用使用同一 `modelId`；`providerId` 与 provider registration facts 不进入目标公共目录契约。
- 命中 OpenAI-compatible registration 的模型，其 `contextWindowTokens` 来自子 profile 静态正整数；命中 Model Gateway registration 的模型，其窗口来自 trusted gateway model-information capability。Gateway 模型不允许静态 override 或静态 fallback。
- ready 前冻结 locally valid configured profiles、配置顺序和 private provider binding；compatible metadata 从本地配置解析，Gateway profile 只建立未解析 slot，不发起远程模型信息查询。
- startup compile 和受控 Agent hot reload 在发布 assembly 前直接通过同一个 frozen `systemConfig.modelProfiles` 校验全部激活 id；不建立 configured ids、membership port 或第二套存在性权威，非法 reload 保留当前 active assembly，不刷新 global catalog。
- 首次 `get(modelId, signal)` 只解析目标 Gateway profile，首次 `list(signal)` 并发解析全部尚未解析 profiles；同模型并发查询 single-flight，取消不冻结 `UNAVAILABLE`，完成结果逐模型冻结到进程重启。unknown `get` 不调用 provider，公共目录不暴露未解析或解析中状态。
- 启动顺序固定为 validated/frozen system model definitions → Agent activation validation → Gateway bindings/private provider binding → invocation authorization → ready；safe query 在 ready 后由模型消费者触发。
- `NextAgentApp` 的模型相关顶层 public shape 恰好为不可变 `systemConfig`；`systemConfig.modelProfiles` 原子迁移为父层 provider access + 子层 models 的 closed contract，validation evidence 留在同一冻结配置，重复的 `modelProfileRegistry` 与 `productModelProviderKind` 删除且不保留 alias；Context Engine 通过 app-private composition 直接获得 `agent-model` query。
- Context Engine 只从 accepted Agent 的 `modelIds` 查询安全目录，并信任 publication 已完成模型引用校验；已知但 `UNAVAILABLE` 的 id 被排除，其他可用模型仍可选择，全部候选不可用时返回 `NO_AVAILABLE_MODEL`。
- `ModelSelectionRequest.mode` 只允许 `INITIAL | FALLBACK`：`INITIAL` 表示首次选择且禁止 `attemptedModelIds`；`FALLBACK` 表示显式跨模型重选，要求非空 attempted ids、排除已尝试模型并要求候选 `fallbackEligible=true`。该字段不表示 provider、stream、模型能力或 routing mode。初始选择依次应用 activation order、runtime/customer availability、显式 `modelId`、prompt/capability compatibility 和 Agent default。
- fallback 由 Core 在 visible-output、deadline/budget、cancellation 和 safe failure gate 通过后请求 trusted Context Engine reassembly；Context Engine 返回下一模型的新 `RenderedModelInput`。
- `ModelInvocationRequest` 是封闭对象：required 顶层字段恰好为 `invocationScope`、`modelId`、`messages` 和 `tools`；optional 顶层字段恰好为 `temperature`、`maxOutputTokens`、`topP`、`topK`、`presencePenalty`、`frequencyPenalty`、`thinking`、`providerOptions`、正整数 `timeoutMs` 和非负整数 `maxRetries`。locale 在上游 selection 与 prompt rendering 后停止传播。
- `ModelInvocationScope` 在当前 `agent-contracts/model` 基线中已经存在，本 change 对其执行 breaking refinement。目标是单一 flat closed object：required fields 为可信 `tenantId/subjectId/agentId/agentVersion/agentAssemblyRef/operationId`；optional `sessionId/requestId/runId` 必须 all-or-none。run-bound owner 将 owning `stepId` 同值映射为 `operationId`；recommendation service 在 terminal 预计算或 Web 按需路径的每次实际模型调用前建立 fresh `operationId` 并保留 completed-run causal coordinates；memory extraction 将 scheduler/cycle-owned `cycleId` 同值映射为 `operationId` 并省略不存在的 run coordinates。可信调用路径决定 lifecycle。
- 前七个 provider-neutral 推理参数按 profile → selected Prompt Template → governed Capability patch → trusted request → governed hook 的固定 precedence 解析；`providerOptions` 使用相同层次但 Capability layer 只接受 governed Skill metadata mapping；timeout 和 max retries 只允许 profile、trusted request 和 governed hook 覆盖。全部适用层均缺失时，`temperature=0.55`、`maxOutputTokens=32,000`、`topP=1`，其他通用推理参数保持 optional 并使用 provider 缺省语义，`providerOptions` 不发送且不合成空对象，`timeoutMs=30,000 ms`，`maxRetries=2`。`ResolvedModelConfiguration` 始终投影前三个 effective defaults，Context budget 使用 effective `maxOutputTokens` 预留输出空间；`timeoutMs` 覆盖 initial request、全部 retry 和 backoff 的 logical-invocation 总墙钟时限，runtime budget 是最终硬上限。
- 固定推理默认值只由 `agent-model` catalog resolution 填充；bundled `default-system.yaml` 把现有 flat profiles 迁移为父层 `providerId/baseUrl/credentialRef/models` 与子层单一 `modelId`，把现有 `modelOptions` 展开为目标扁平字段并省略 `temperature/maxOutputTokens/topP`。子 profile 可配置 `temperature/maxOutputTokens/topP/topK/presencePenalty/frequencyPenalty/thinking`、`providerOptions`、`timeoutMs/maxRetries`；env projection 同步解析父层 `baseUrl/credentialRef` 和子层 `modelId`。Prompt Template、Skill、Capability 和 hook 均只表达显式 override，不维护第二份默认常量。
- profile、已编译且选中的 Prompt Template、已接受的受治理 Skill metadata、可信 Agent 调用和受治理 hook 可以提供 inner `providerOptions`；Context Engine 只合并 Prompt Template → Skill → trusted request 的 call-level 对象，不读取 private profile defaults，模型调用边界再把 private profile defaults 置于 call-level composite 之前、把 governed hook 置于其后，并由 selected adapter schema/allowlist 校验。顶层 `thinking` 是 thinking/reasoning input control 的唯一 authority；`providerOptions` 拒绝 `reasoning/thinking/reasoningEffort` 或其他重复控制。Web/client、RuntimeCommand、Capability 参数、非 Skill Capability result、Skill input/body、模型输出和其他不可信 metadata 不得提供该字段，且该字段不得覆盖身份、接入、执行或 transport 事实。
- `openai-compatible` 非流式和流式成功终态尽量保留 provider usage；每个有效非负整数值原样保留，缺失、不支持或非法字段省略，且不得把其他方面成功的结果改为失败。
- `ModelFinalResult` required field 为 `content`，optional fields 恰好为 `reasoning/finishReason/usage/toolCalls/providerResponseId/safeError`；模型身份由对应 request 持有，`providerResponseId` 只用于安全 response correlation。

契约输入：

- `agent-contracts/model` 提供唯一 canonical `ModelInferenceOptions` type/runtime schema，恰好包含七个 provider-neutral inference fields 和 optional `providerOptions`；Capability patch、Prompt Template 和 Skill metadata 复用该结构，source authority 仍由各 owner 单独治理，profile/request 保持 flat fields。
- 新增 app-private `ModelCatalogQueryService`，提供 async/cancellable `list(signal)` / `get(modelId, signal)`；它返回封闭 `AVAILABLE | UNAVAILABLE` `ModelCatalogEntry`、available entry 的 `ResolvedModelConfiguration` 和 exact unavailable reason vocabulary，负责目标范围内的 lazy metadata resolution、single-flight 和逐模型 freeze，不成为 `NextAgentApp` public API。available entry 不在 `configuration.modelId` 外重复顶层 `modelId`，selection 原样复用同一 frozen configuration；null、unknown field 和混合判别分支全部拒绝。
- 真实 lifecycle scope 只用于内部授权、correlation、observability 和 audit；`agent-model` 从已校验 scope 集中生成固定的既有 `X-NextAgent-Agent-Id`、`X-NextAgent-Session-Id`、`X-NextAgent-Request-Id` 和 `X-NextAgent-Run-Id`。Agent header 始终存在，后三个只在完整 run coordinates 存在时一起生成；request、hook 和 provider options 均不能注入或覆盖 headers，本 change 不建立其他 header policy。`traceparent/tracestate/baggage` 只能由独立 observability/transport instrumentation 传播。
- `ModelInvocationScope` 为既有 contract 的必填单一 flat 封闭目标 shape；它携带 accepted Owner/Agent facts、required `operationId` 和 all-or-none optional run coordinates，可信调用路径拥有 lifecycle authority。
- `ContextEnginePort.assemble(request, options, signal)` 增加 optional closed `ContextAssemblyOptions` 和 required cancellation signal；options 缺失表示 `INITIAL`，显式 `INITIAL` 不携带 attempted ids，`FALLBACK` 要求非空、有序且唯一的 `attemptedModelIds`。
- `ModelInputRenderRequest.providerOptions` 和 `RenderedModelInput.providerOptions` 收敛为 optional call-level carry；Context Engine 只合并 selected Prompt Template、governed Skill metadata mapping 和 trusted request，三者均缺失时保持字段缺失且不合成空对象，private profile defaults 不离开模型边界。
- `CapabilityInvocationResult.contextPatch.modelName` 原子替换为 canonical `modelId`；`modelOptions` 只允许 `temperature`、`maxOutputTokens`、`topP`、`topK`、`presencePenalty`、`frequencyPenalty`、`thinking` 和 `providerOptions`，其中 `providerOptions` 只接受已接受 `SkillMetadata.modelOptions` 经受治理 Skill Tool mapper 产生的值；拒绝其他 Capability 来源、provider access、timeout、retry、null、non-object 和 unknown fields。`modelId` 或 `modelOptions` 缺失只表示不覆盖，Capability patch 不建立独立默认值。
- Prompt template 直接把 canonical `modelId` string 赋值给 `match.model`，不再使用单字段 nested object；内部兼容性只产出 canonical compatible `modelId` 集合，最终模板装配只消费唯一模型选择结果。
- Prompt template `modelOptions` 的 compiler/type/handoff 同步使用上述八字段 closed inference schema；省略字段不合成默认值，compiler 拒绝 provider access、timeout、retry、null 和 unknown fields，`providerOptions` 在最终模型确定后由 selected adapter 校验。
- `BEFORE_MODEL_INVOKE` mutation 删除 `commonOptions`，使用与目标调用 request 相同的扁平 provider-neutral 推理字段、`providerOptions`、`timeoutMs` 和 `maxRetries`；selected model/scope、provider access/transport/framework-owned headers、Owner/Agent scope 和 execution budget 不可修改。省略 optional mutation field 表示保持 hook 前 effective value，hook 不合成默认值；prompt locale 不属于 request/mutation 字段。
- Suggested questions 与 memory extraction 统一消费 `ModelSelectionService`；两者均使用可信单一 scope。recommendation 的 terminal 预计算与 Web 按需生成汇入同一服务，在每次实际模型调用前通过 session service 自有的 cryptographically secure UUID generator 建立 `operationId` 并保留 completed run 的完整 causal coordinates；App composition 不注入或感知该 generator，`SuggestedQuestionRequest` 与三参数 `postTerminalCallback` 保持不变。memory extraction 将 scheduler/cycle-owned `cycleId` 映射为 `operationId` 并省略不存在的 run coordinates；两者均不自行读取 main/default/first profile。
- Skill Tool 把 `SkillMetadata.model` 原样映射为 canonical `contextPatch.modelId`，由统一治理校验，不再返回 `modelName` 或按 provider/display name 反查；Skill manifest parser、`SkillMetadataSchema`、typed metadata 和 mapper 的 `modelOptions` 同步使用上述八字段 closed inference schema，`providerOptions` 只来自 source-admitted、manifest-validated、已接受的 Skill metadata。
- 新增 context-owned `ModelSelectionService.select(request, signal)`；request 复用既有 `identityContext` 并显式携带 `agentId/agentVersion/agentAssemblyRef`、purpose、locale/flow variables、governed optional `modelId`、required `INITIAL | FALLBACK` mode 与 attempted model ids。result 使用封闭 `SELECTED | FAILED` union、原样复用 catalog available entry 的 immutable safe `ResolvedModelConfiguration` 和 exact success/failure reason code。
- `ModelGatewayProvider` composition contract 同时提供 invocation service 和 provider-private `get(modelId, signal)` model-information service；result 只允许封闭 `FOUND | NOT_FOUND | UNAVAILABLE` union，`FOUND` 携带 `{ modelId, contextWindowTokens }`，`UNAVAILABLE` 只携带 exact safe reason；capability 在 bootstrap 时只装配，由 ready 后首次 safe catalog query 调用。
- started/completed/failed 三个 `MODEL_INVOCATION_*` event 的安全 identity 原子使用相同 `stepId/modelId`。owning run-bound orchestrator 在 accepted orchestration step 建立 `stepId`，并把同一值作为 scope `operationId` 与 session/request/run coordinates 原子写入；wrapper 由可信 call path 选择，读取 scope 并与 accepted run/context 原子校验，不再接收独立 step context，也不从 optional run coordinates 推断 lifecycle。`stepId` 只是 run 内 orchestration grouping key，同一步骤的多个顺序调用由 event identity/sequence 区分。同模型 retry 只形成一个事件对，cross-model fallback 复用 `operationId` 的同一投影值并使用新 `modelId`。producer、persisted schema、历史读取、`agent-observability` timeline mapper/trace projector 和 dev workbench server/browser projector 同一发布单元删除 `modelProfileId/providerKind/modelName`，不保留 compatibility alias、dual write 或 dual read；duration、usage、first-visible、failure/trace 语义保持，background 调用不产生 request-run timeline/workbench event。
- observability mapper 以 `stepId/modelId` 校验 model event，并只用 `runId + stepId` 做进程内 duration/first-visible pairing；step/model/provider identity 不进入 diagnostic candidates、trace attributes、structured-log detail 或 metric labels。6 个 model metrics 保留 name/value/dedup 和 outcome/token labels并移除 `provider_kind`。
- NextAgent-owned optional inner `providerOptions` 由 profile、selected Prompt Template、governed Skill metadata、可信 Agent 调用或 governed hook 提供，render/Capability patch/lifecycle 只 carry 已授权值，并由 selected adapter 校验。
- selected resolved configuration 向 Context Engine 提供完整上下文窗口、effective timeout、effective max retries 和可选通用参数。
- public contract、ready/assembly publication/primary health 前零 Gateway metadata I/O、lazy catalog resolution/single-flight/freeze、model-scoped Gateway degradation、开放但保留字段受控的 provider options、总时限同模型 retry、通用 optional `FetchGateway` composition、无额外 header policy、closed terminal result、canonical timeline identity 与 best-effort usage 记录在 active change 的 `references/model-provider-options-contract-confirmation.md`；记录中的 supplemental refinements 已于 2026-07-29 完成群内确认，全员同意且无异议。
- SecretReference、最底层 encrypted-envelope 处理、独立 key source 和 raw secret 不泄漏逻辑保持不变；本 change 只迁移混合 Requirement 的规范归属，不修改 Secret production path，也不新增 ENC 支持。
- `agent-plugin-sdk` 的变更范围为 RESERVED policy inventory 的 owner metadata。

实现约束：

- `agent-app` 保留 raw config 加载、runtime validation、`DefaultSystemConfig` 派生与冻结、`ConfigValidationEvidence` 生成、Agent assembly 模型引用校验和全部 dependency composition；其配置/composition helper 可以读取完整配置来生成窄投影。它直接以 frozen 两层 `modelProfiles[]` 校验 startup/hot-reload assembly publication，并把这些 profiles 与可信 provider/transport contribution 或 `ModelGatewayProvider` 交给 `agent-model`，后者按 `providerId` exact lookup 唯一 runtime registration。Gateway bindings 完成后，`agent-model` 交付既有 `ModelCatalogQueryService` 与独立 `ModelInvocationService` 两个 app-facing owning ports；app 分别注入 Context Engine/health 与其他 model consumers，不构造 registration、平行 catalog 接口、mega-interface 或 recommendation operation identity。`NextAgentApp.systemConfig` 是唯一模型 Host projection。被装配的 owner package implementation 只接收窄配置投影或 owner-owned port。
- `agent-model` 内部维护 private lazy catalog slots、safe `ModelCatalogEntry`、available entry 的 `ResolvedModelConfiguration`、private `modelId → providerId` binding 与按唯一 `providerId` 装配的可信 provider runtime registry；子 profile 提供模型身份和默认画像，registration 私有持有 provider implementation、接入配置 validator、metadata resolver，以及 app 从 optional `FetchGateway` 适配出的 private fetch function。
- `agent-model` 只读取 accepted assembly 来验证 selected `modelId` 的 activation；该检查是 invocation authorization，不是模型选择。
- `agent-context-engine` 通过 model-owned query port 获取模型默认值和限制，并只依赖该 provider-neutral contract。
- production app surface 只暴露走真实 provider 的 `createNextAgentApp`/host entrypoints；`agent-app/testing` 的 scripted-model factories 把脚本化 `ModelInvocationService` 包装成测试 `ModelGatewayProvider` 后复用正常 provider composition，production/internal composition 不接受最终 invocation service。channel auth/frontend hosting 的内部变体 contract 使用 `HostCompositionSelection`，不使用易与模型或完整产品选择混淆的 `ProductCompositionSelection`。
- `agent-memory`、`agent-session` 和 `agent-workflow` 通过 `ModelSelectionService` 获得 selected model；它们保留各自 prompt、输入投影、输出解析和生命周期，不读取 catalog 或 access binding。
- startup readiness、primary health 和 Capability startup graph validation 只读取本地 frozen system model definitions/private binding，不解析 Gateway metadata；应用 ready 后显式 deep `model_provider` health 使用 evaluator signal，通过 safe `get` 查询 default-route Agent 的 default/first activated model，因此可以成为首次解析 consumer，但不读取 Host 配置投影。
- `agent-core` 使用同一 `ContextAssemblyRequest` 加 trusted fallback options 重新装配，并仅消费 Context Engine 返回的 selected model 与渲染输入。
- `agent-core` 只把治理通过的 Capability `modelId` / `modelOptions` 保存在 request-local state 并交给后续 Context Assembly；producer/schema/consumer 在同一发布单元删除 legacy `modelName`。
- `agent-model` 使用 `ai@6.0.235` 和 `@ai-sdk/openai-compatible@2.0.62`，唯一兼容模型创建路径为启用 usage 的 `createOpenAICompatible(...).chatModel(modelId)`；可选 private fetch 只由 app 从 `GatewayBindings.fetch` 适配到可信 provider registration，模型包不依赖 gateway contract，也不拥有 header policy。
- 非流式使用 `generateText`，流式消费 `streamText().fullStream` 并显式处理 SDK `error`/`abort`/`tool-error`/`finish` parts 与终止型异常；共同使用 SDK `abortSignal`、logical-invocation absolute deadline 与标准 message/tool/result API。同模型 retry 只由模型边界一处拥有，只处理明确 recoverable、尚未产生 public stream delta且总时限仍有剩余的失败；summary 等 caller 删除外层 retry。
- transport、request、stream、tool、usage 和 timeout 由 SDK 公共 API 形成唯一 compatible adapter 实现路径。
- raw provider response/error、endpoint、credential、SDK type 和 provider-native metadata 不得离开 `agent-model`。
- `agent-observability` 的 context wrapper 与所有 caller 必须原样透传新增 assembly options/cancellation signal；timeline mapper 必须从 `stepId/modelId` 校验 observation，并只在进程内完成 duration/first-visible pairing，trace/log/metric 不导出模型或 operation identity；6 个 model metric descriptors/projector 删除 `provider_kind`，保留 name/value/dedup。`agent-core` 的 run-bound wrapper 从已校验 scope 取得 `operationId`，与 accepted run/context 原子校验后投影为 canonical timeline/workbench `stepId/modelId` identity；compatible outbound request 由 `agent-model` 集中生成既有四个 correlation headers。

非目标：

- compatible adapter 的 endpoint capability 为 Chat Completions，依赖版本线为 `ai` 与 `@ai-sdk/openai-compatible` 6.x 对应版本。
- NextAgent global catalog 独立拥有 Agent activation、模型可用性、窗口和 fallback eligibility。
- `NextAgentApp.systemConfig` 服务可信 App Host并包含 frozen canonical 模型配置/evidence；运行期模型能力使用 app-private dependency，production 不维护重复 registry。
- 模型目录 slots、配置顺序和 provider binding 在启动期冻结；Gateway 安全目录项在首次查询时逐模型解析并冻结到下次启动，不提供后台预热、周期刷新或运行期配置热变更。
- 模型注册和接入配置由可信应用装配边界拥有。
- runtime request lifecycle、terminal commit、Agent Scope、Owner Scope、Web stream 和 frontend 保持不变；persistence 只原子迁移 `MODEL_INVOCATION_*` payload identity 字段。
- `MODEL_GATEWAY` 的 provider-neutral invocation/usage 语义保持不变，新增 safe model-information composition capability。
- reasoning 保持输出归一化与既有展示/时间线用途；模型输入消息、工具轮续接、跨轮上下文和 provider continuation 回传由独立 change 定义。
