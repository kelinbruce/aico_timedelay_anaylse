## 描述

系统在 Local、Immersive 和 Collaborative/PIU 宿主中，以统一 Header、Content、可选 docked Footer、内容宽度和单一纵向滚动边界呈现 Agent Web 主内容页面；会话、定时任务和收藏使用统一布局。定时任务、收藏列表、记忆管理、知识导入和投诉历史的既有入口使用统一的本地化名称、无障碍名称、图形语义和页面级标题，三个宿主已有的新建会话入口使用统一主题图形语义；页面操作、宿主菜单集合与顺序、宿主导航和会话滚动策略继续由原有能力决定。

## 前置条件

- Agent Web 宿主已提供可用的主内容容器和当前主题。
- 目标页面已声明标题、内容宽度和滚动归属，并提供自身需要的页面操作。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| 页面标题 | 是 | Header 左侧展示的单行标题 |
| 页面操作区域 | 否 | 由目标页面声明并在 Header 右侧原样展示 |
| 页面内容 | 是 | 在 Content 区域展示的目标页面内容 |
| 内容宽度 | 否 | `contained` 或 `fluid`，默认 `contained` |
| 滚动归属 | 否 | 由布局 Content 或页面业务内容区域提供唯一纵向滚动边界，默认由布局 Content 提供 |
| docked Footer | 否 | 固定在页面底部且不随 Content 滚动的普通页面 Footer |
| 返回操作 | 否 | 使用统一结构和样式的可选返回入口；首批适用页面均不提供 |

## 输出

主题一致、窄视口单行可用、内容边界确定且只在声明区域纵向滚动的 Agent Web 页面布局。

## 处理过程

1. 系统按照目标页面声明确定 Header 内容、Content 宽度、滚动归属和可选 docked Footer。
2. Header 在同一行展示标题与页面操作；可用宽度不足时截断标题，但不改变页面操作结构。
3. Content 使用目标宽度模式占据 Header 与可见 Footer 之外的剩余高度，并只在页面声明的区域提供纵向滚动。
4. local、immersive 和 collaborative/PIU 对同一页面投影相同的 Header、内容边界和滚动结果；宿主入口只决定导航或容器关闭方式。

## 结果

- 正常：页面以统一 Header 和目标 Content 宽度显示，页面级纵向滚动条只出现在声明区域。
- 无 Footer：Content 使用 Header 下方的全部剩余高度。
- docked Footer：Footer 保持在页面底部，Content 不被遮挡。
- 窄视口：标题以省略号截断，Header 保持单行且页面操作结构不变。
- 会话兼容：overlay composer、跟随底部、用户滚动意图、历史分页和锚点定位结果保持既有语义。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| Header 几何与标题字体 | Header 高 `48px`、左右内边距各 `16px`，无底部分隔线、阴影或独立背景渐变；标题字号 `16px`、字重 `500`、行高 `28px` | `agent-web-page-layout`：`页面 Header 保持一致且在窄视口可用` |
| Content 宽度模式 | `contained` 默认最大宽度 `1080px` 并居中；`fluid` 无最大宽度；两者左右水平安全内边距均为 `16px` | `agent-web-page-layout`：`页面 Content 支持 contained 与 fluid 宽度` |
| 首批页面滚动归属 | 会话为消息 viewport，定时任务为 Content，收藏仅在展开内容超高时为收藏内容区域；不产生第二个页面级纵向滚动条 | `agent-web-page-layout`：`适用页面保持单一纵向滚动边界` |
| 首批页面与宿主范围 | 会话、定时任务、收藏使用统一页面布局；定时任务、收藏列表、记忆管理、投诉历史的已有入口在 Local、Immersive 和 Collaborative/PIU 中使用统一名称、无障碍名称和图形语义；三宿主已有的新建会话入口使用统一主题图形语义，宿主入口集合与顺序保持独立 | `agent-web-page-layout`：`Agent Web 页面使用统一三段式布局`、`统一布局在三个宿主中保持一致`、`内置业务页面的导航标识与页面标题保持一致`、`新建会话入口跨宿主使用统一图形语义` |
