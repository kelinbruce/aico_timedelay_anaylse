## 描述

开发者通过网关边界集成外部存储、远端服务、业务 API 和前端托管，保持边界清晰。集成方还可以为 LOCAL 或 REMOTE 部署注册用户查询 Gateway provider，为共享知识等消费场景提供可读用户名展示。

系统集成方可以在纯 IPv6 或 IPv4/IPv6 双栈部署环境中启动并访问 NextAgent：通过监听环境变量覆盖本次进程的监听地址和端口，使用 IPv6 loopback 或双栈 wildcard 入站地址，并依赖首批关键出站路径（模型提供方调用、api-call、task callback）连接 IPv6 literal 目标的可用性保证；该保证由真实 socket 验证提供证据，不构成全局 IP 族选路策略。

## 边界

- 网关调用经统一边界，本地原子事务以一致性为先。
- Web API 只暴露公共数据对象，内部对象不外泄。
- 前端经构建后 npm 包托管，不直接依赖前端源码。
- 监听配置覆盖和 IPv6 地址支持不得放宽产品入口已选择的认证或网络暴露边界；本地配置认证只接受 loopback 监听地址。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| 网关调用超时 | 30,000 ms 默认，120,000 ms 硬上限 | 建议评审值 |
| API 最大分页大小 | 200 | 建议评审值 |
| 前端托管模式 | 仅后端、含前端 | `fullstack-packaging-boundary` |
| 默认监听地址 | 未提供监听环境变量时为 `127.0.0.1:3000` | `network-connectivity` |
| 入站 IPv6 范围 | `::1` IPv6 loopback；`::` 双栈（需主机允许 IPv4-mapped IPv6） | `network-connectivity` |
