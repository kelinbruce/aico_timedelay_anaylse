# FN-10.34 配置网络连通性

> 能力域 D10 二次开发与平台集成 · 子域 [D10.2 集成与定制](.) · 返回 [功能树](../../index.md)

| 项 | 值 |
|---|---|
| 主规格 | `network-connectivity` |
| 接口 | 进程环境变量 `NEXTAGENT_CHANNEL_HOST`、`NEXTAGENT_CHANNEL_PORT`；首批关键出站路径既有的 HTTP/HTTPS URL 输入 |

## 描述

系统校验并应用进程监听配置的环境变量覆盖，提供可连接的 IPv6/双栈入站端点与启动提示，并保证首批关键出站集成路径（模型提供方调用、api-call、task callback）能够连接 IPv6 literal 目标。本能力复用既有 `channel.host`/`channel.port` 配置事实和 Node.js 默认网络栈，不创建 IP 族选路策略或全局 HTTP transport 抽象。

## 前置条件

- 部署环境启用目标 IP 协议栈；双栈 wildcard（`::`）场景要求主机网络栈允许 IPv4-mapped IPv6。
- 启动配置和所选产品入口的安全边界有效。
- 出站目标已提供有效且获准访问的 URL。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| YAML 监听配置 | 是 | `channel.host`、`channel.port`，内置默认 `127.0.0.1:3000` |
| `NEXTAGENT_CHANNEL_HOST` | 否 | 覆盖 YAML `channel.host`，须为非空字符串 |
| `NEXTAGENT_CHANNEL_PORT` | 否 | 覆盖 YAML `channel.port`，须匹配 `^[1-9][0-9]{0,4}$` 且位于 `1..65535` |
| 出站 URL | 按路径 | 首批关键出站路径接收的 HTTP/HTTPS URL，可含方括号 IPv6 literal |

## 输出

- 冻结的有效监听结果和可连接的启动地址（启动提示）。
- 入站服务结果；首批关键出站路径的既有成功或安全失败结果。

## 处理过程

1. 两条 config load path（application config 与 local runtime package config）在既有 env-ref 解析之后、schema validation 之前应用同一 channel 环境变量覆盖，字段级独立判定。
2. 非法环境变量值保留为 schema-invalid，由既有安全配置诊断在 ready 前阻断启动，不静默回退 YAML 或默认值。
3. CLI 启动提示把 `::` 与 `0.0.0.0` 映射为 `localhost`，IPv6 literal（如 `::1`）输出方括号 URL。
4. 本地配置认证（LOCAL_CONFIGURED_AUTH）入口在 channel route registration 前校验最终 host 为 `localhost`、`127.0.0.1` 或 `::1`，其他 host 安全失败且错误不包含原始值；DEFAULT_WEB 不受该限制。
5. 出站路径保持默认 fetch / `https.request` 行为；insecure HTTPS callback 在构造私有 request options 时移除 IPv6 外层方括号。

## 结果

- 正常：有效输入产生 IPv6/双栈网络可用结果，并由真实 socket 验证形成合规证据。
- 非法监听输入、安全边界冲突或不可达目标：按对应安全失败契约结束，不泄露原始环境变量值或 transport error。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| 监听环境变量 | `NEXTAGENT_CHANNEL_HOST`、`NEXTAGENT_CHANNEL_PORT`；分别独立覆盖对应 YAML 结果，非法值在 ready 前失败 | `network-connectivity`：`监听地址和端口支持进程环境变量覆盖` |
| 默认监听地址 | 未提供监听环境变量时为 `127.0.0.1:3000` | `network-connectivity`：`监听地址和端口支持进程环境变量覆盖` |
| 入站 IPv6 范围 | `::1` 提供 IPv6 loopback；`::` 在支持的 Windows/Linux release package 目标且主机允许 IPv4-mapped IPv6 时提供 IPv6 与 IPv4 loopback | `network-connectivity`：`IPv6 入站监听提供可连接的启动地址` |
| 首批 IPv6 出站范围 | 模型提供方调用、api-call、task callback 支持 IPv6 literal HTTP/HTTPS 目标（Node.js `22.22.0` 默认网络配置） | `network-connectivity`：`首批关键出站路径可连接 IPv6 literal 目标` |

## 当前状态

稳定。

IPv6 可用性验收必须由真实 socket 测试提供证据；release gate 环境若禁用 IPv6，视为无法提供该平台验收证据，而不是跳过后仍声明支持。
