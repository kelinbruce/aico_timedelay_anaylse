# 为 Skill 投影失败添加安全诊断与锁恢复

## 背景与问题（Why）

当 Skill 资源投影失败时，模型可见结果必须保持安全和通用。但运维人员目前对不同的根因看到的是同一条 safe 消息，例如路径拒绝、资源上限、source 路径缺失、目标目录繁忙、本地权限失败或投影锁竞争。

既有行为保护了敏感细节，但让生产排障变慢，因为日志没有为投影边界提供稳定的失败分类器。

并发激活期间还存在一个可靠性缺口。多个 session 或本地进程可能尝试把同一 Skill 身份投影到同一执行 scope。一个激活获得投影锁，而其他激活可能在观察到并复用已提交投影之前超时。锁超时随后以不可重试的内部失败暴露，即使重试或复用已提交投影是安全的，也可能终止请求。

## 目标（Goals）

- 保持模型可见的 Skill Tool 失败不变且安全。
- 在 Skill 资源投影失败时新增低基数的 runtime 诊断事件。
- 包含稳定的分类器、失败阶段、原因码和有界数值证据，帮助区分权限、路径缺失、文件系统繁忙、路径拒绝、资源上限、锁竞争、source 不匹配、读取方可用性和校验失败。
- 当并发 Skill 激活观察到投影锁竞争时复用有效的已提交投影。
- 为有界的投影锁超时返回可重试的 safe failure 语义。
- 避免记录原始路径、Skill 参数、模型输出、prompt 文本、原始异常消息、堆栈、credential 或文件内容。

## 非目标（Non-Goals）

- 不向模型、Web API、stream、timeline、audit、metric 或 SafeError 暴露额外细节。
- 不改变 Skill 投影授权或可写路径策略。
- 不新增自动的请求级重试。
- 不改变 Skill Tool 输入校验或 Skill 参数语义。

## Function 影响（OpenSpec Capabilities）

- **Function**：Skill 资源访问。
- **Function 变更类型**：修改。
- **主规格**：`openspec/specs/skill-resource-access/spec.md`。
- **边界**：Skill Tool 投影失败处理在返回既有 safe failure 之前发出一个安全的 runtime 诊断事件；并发投影竞争可以复用已提交投影或返回可重试的锁超时失败。
- **系统质量**：可诊断性和并发激活可靠性得到改进，同时安全性和数据最小化保持不变。
- **验证**：聚焦 Skill Tool 测试验证诊断分类器、允许清单内的阶段/原因证据、可重试锁超时语义以及原始文件系统路径的缺失；聚焦投影测试验证跨 port 的并发复用。
