# NextAgent 功能树

> 定位：功能树以目录结构承载。能力域（D{n}）→ 子域（D{n}.{m}）→ 功能（叶子文件 FN-{n}.{m}）。Function 是系统提供的一个黑盒能力单元，主角是系统；每个功能文件描述名称、描述、前置条件、输入、输出、处理过程、结果、规格、接口、覆盖特性和当前状态。
>
> 与 `docs/NextAgent-function-list.md` 的关系：扁平 list 为概览速查；本树为目录化详情版。
>
> 功能粒度：一个 Function = 系统提供的一个能力单元。同一系统能力的成功、失败、边界和降级结果不拆分为多个 Functions；黑盒输入、目标或主要契约边界不同的系统能力应拆分。Function 的“处理过程”仅表示契约可见的校验、状态判定、状态转换、可见性变化和产出，不包含 owner、内部模块协作、调度、持久化路径、事务、锁、CAS 或私有状态表示。
>
> 行为契约关系：OpenSpec capability 等同 Function。新 Function 必须且只能导航到一个 `openspec/specs/<capability>/spec.md`；该主规格是 Function 行为、系统质量属性和规格边界的唯一规范来源。既有一 Function 对多个 specs 或未映射 spec 属于 legacy baseline；其中与 Function 黑盒边界最匹配的标为主规格，其他尚有未迁移 Requirements 的标为遗留规格，不得新增多对多映射。
>
> 规格：每个 Function 必须提供简短、非空的关键黑盒规格摘要，通常为 1–4 项；规格可以是数值、默认值、枚举、精确能力清单、支持范围或简短规则，但不承载字段级接口和实现细节。规范目标仍以主规格中的 Requirement 为准。
