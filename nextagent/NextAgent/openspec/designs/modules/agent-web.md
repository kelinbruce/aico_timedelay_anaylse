# agent-web

## 职责

`frontend/agent-web` owns the packaged frontend source for local, immersive, and collaborative host modes. It owns AICOConfig validation and consumption, host shell selection, shared chat workspace rendering, PIU injection containers, frontend-only panel/layout state, long-term memory file projection, and component-level UI behavior described by agent-web specs.

## 非职责

不拥有后端 API、stream truth、runtime lifecycle、Session Activity 派生/持久化/消费真相、pending-input timeout、owner scope、agent scope、capability authority、gateway persistence、auth security boundary 或 frontend artifact hosting。`agent-app` 和 `agent-app-frontend-hosting` 只消费构建后的 artifact 和 hosting manifest，不 import `frontend/agent-web` source and do not interpret PIU handler semantics.

## 核心设计落点

- 浏览器对 Capability result 只做统一 chat workspace 投影：成功、降级、失败、超时和外置结果引用共用 renderer；失败只显示一个安全原因及可选技术详情。前端不拥有 retry、loop budget、authorization control、canonical transcript 或 terminal truth，三种宿主不得形成不同失败语义。
- `systemEventPresentation.ts` 是普通 Agent Web 对 `DEGRADATION_NOTICE`、`CONTEXT_COMPACTED` 和前端兼容 `HOOK_DEGRADED` 的集中业务呈现入口。它只按 event type 与当前语言返回固定标题、摘要和 `warning | info` 严重程度；任意 payload 文本、Hook 身份和宿主配置不得覆盖基础语义。只有 `DEGRADATION_NOTICE` 顶层显式非空 `code` 可进入默认收起的技术详情。折叠过程、完整运行图和上下文整理短暂提示复用该 resolver；durable 事件保持 live/history 一致，transport notice、短暂动画与 `HOOK_DEGRADED` 保持 live-only，请求终态仍由独立 terminal presenter 负责。

- `TurnBlock` 的回答收藏操作保持本地与远端宿主可用：local 依赖 gateway 事务内 `FAVORITE_LIMIT_EXCEEDED` 安全错误并回滚乐观状态；immersive/PIU 在净新增收藏前读取一次 `listFavoriteTurns(limit=100)` 作为受控前端兜底，达到 100 条时不发送 upsert 并显示本地化上限提示，预检查失败则继续走 upsert。取消收藏不触发预检查；该兜底不改变远端持久化 owner，也不提供并发强一致保证。
- `AppProviders` owns theme、locale、runtime bootstrap、host context and global UI providers. `HostModeShell` owns local / immersive / collaborative differences. `ChatWorkspace` remains the single shared conversation core for session/history、stream、composer、request control、attachment and process view.
- `MemoryManagePage` 是 immersive/PIU Shell 内 `#/memory` hash pathname 拥有的记忆管理主内容视图，不绕过 Shell：LEFT 保持 Sidebar 常驻、RIGHT 保持顶栏常驻，只替换主内容区；local 模式不暴露记忆管理入口。页面只拥有 Shell 主内容区，标题与 Chat 同形（54px/18px/600），字号只使用 12/14/16px，不渲染指标卡；三个 Tab（我的记忆/共享记忆库/已归档）分别显示各自未过滤服务端 `total`。页面跟随 immersive `site.theme`/`site.locale`，不建独立主题或语言切换。反馈消息由 Shell 提供 Ant Design `App` context message，顶部偏移=主内容区 `getBoundingClientRect().top + 12px`，避开 RIGHT 顶栏。列表/搜索/分页使用服务端 `total`/`limit`/`offset`，`queryText` ≤128 Unicode code point 由后端分页前过滤；Ant Design 分页器+首页/尾页/页码跳转/10·20·50 页大小。详情调用 `GET /{memoryId}/record` 不记录访问，`accessCount` 只在详情展示。新增/编辑调用 `manualSaveLongTermMemory` 原子保存类型/置信度/摘要/正文/标签，置信度 0..1 最多两位小数；个人设定 50 条容量。状态变更 PATCH 按字段组执行。发布用 `publishedMap` 追踪原记忆→副本 ID，FORK 副本禁用共享。记忆只读展示在 Chat 通用敏感内容规则后单独隐藏绝对路径（`[REDACTED_PATH]`），Chat 正文保留绝对路径；IP/相对路径/URL 保持原文。已删除记录操作返回 404/`LTM_MEMORY_NOT_FOUND`/`INVALID_BRAND_VALUE` 时显示本地化已删除反馈。`MemoryManagePage` 与 `memoryTransfer` 共同拥有浏览器长期记忆 JSON 导入和筛选 CSV 导出。文件解析、preview、容量提示和下载只属于 transient UI state；列表与 batch 写入继续通过既有 `memoryService` route。三宿主复用同一页面。导入在写入前完成 5 MiB、1..50 条、字段 allowlist 和 fatal UTF-8 校验；每次文件成功解析生成新的随机导入批次标识，幂等键由 JSON 契约版本、批次标识和原文件元素序号稳定派生，重新选择相同文件建立新批次而未知结果原样重试复用当前批次。容量提示读取 ACTIVE 与 ARCHIVED 的 `CONFIGURED` 总数之和，排除 `LEARNED` 等非个人设定记忆，显示上限 50、已有数和可导入数，只用于反馈不替代服务端裁决。导出按当前个人记忆 Tab 区分：“导出我的记忆”固定 ACTIVE、“导出归档的记忆”固定 ARCHIVED，从 offset 0 读取完整筛选结果，生成 locale-backed 17 列 UTF-8 BOM CSV，并对半角/全角公式前缀及前导控制字符执行文本化防护；共享记忆库不呈现个人导出操作。删除成功后重载当前页和 Tab 数量，当前页变空时由既有空页校正回退到最后一个有效页。
- `conversationStore` 是页面内 conversation projection lifecycle 的唯一 owner。session-scoped 状态固定为 `historyMessagesBySession`、`historyEnvelopesBySession`、`activeLiveBySession`、`settledLiveBySession` 和 `nextLiveOrdinalBySession`；active/settled bucket 以 root 为索引，并显式携带 `rootMessageId`、`attemptId`、`firstSeenOrdinal`、有序 envelopes 和 `nextCompactionAt`。组件不得保存第二份 settled cache，也不得维护 history + active + settled 的扁平 product mirror 或缓存派生 `TurnBlock`。
- `shareService.ts` 集中实现分享权限 ops hash 变换，对 `ShareSettingsModal` 和 `SharedConversationPage` 透明。`hashOps(ops)` 规则为：去重（`new Set`）→ `.sort()` 字典序 → `JSON.stringify` → `crypto.subtle.digest("SHA-256")` → 64 字符 lowercase hex。`createShare` 和 `loadSharedConversation` 内部调用 `hashOps` 把用户完整 ops 数组变换为长度 1 的 `[hash]` 后再经 channel transport 下沉到后端，绕过远端后台存储接口的 200 元素数组传输约束。前端只做确定性数据变换，不做权限决策；hash 相等比对仍由后端 `ConversationShareService` 完成。`keepPermissions` UI 开关语义不变（开=带权限分享存 `[hash]`，关=公开分享存 `null`）。
- `appendEnvelopes` 按可信 envelope 的 session/root/attempt 更新唯一 bucket。匹配 active attempt 的 terminal 在一次 Zustand transition 中纳入 terminal、最终压缩、写入 settled 并删除 active；identity reconcile 在同一 transition 中重键 optimistic root 并保留 `firstSeenOrdinal`。重复 terminal 不新建空 active bucket，settled attempt 的迟到 detail 只能补入同一 attempt，旧 attempt 不得覆盖较新 attempt。
- session projection 固定分为 `buildSessionHistoryProjection`、settled overlay 和 active overlay。visible history 拥有用户内容、最终 assistant answer、最终 capability result、order 和 visibility；settled 只补 thinking、capability lifecycle、process timeline、terminal detail 和 live-only structured detail，或在 history 尚无 root 时提供当前页面临时完整 Turn；active 覆盖当前 attempt。`visible=false` 抑制 retained live，同 root 只能产生一个 Turn 和一个最终 answer，`isLatest` 不得决定 settled process detail 是否仍可展开。
- anchored mode 始终接收并保存 active/settled bucket，但 selector 只给当前 anchored history roots 补 detail；窗口外 root 仅在恢复连续 recent window 后加入投影。普通 history load、terminal、session list refresh 和后续 submit 不清理 settled。`clearConversation` 和现有 10-session LRU 必须在同一 store action 中清除该 session 的 history、active、settled、ordinal、runtime、preview、window 和分页状态；页面刷新自然清空页面缓存并从 visible history 重建最终内容。
- 输入护栏拦截轮（`GUARD_INPUT_BLOCKED` HTTP 400）不再在前端伪造 `local-optimistic` 信封或 mirror 到 `sessionStorage`。该轮的权威来源是后端持久化的 `visible=true` 用户输入与拒答消息（`metadata.modelVisibility.excluded=true`），`requestStore` 的 `GUARD_INPUT_BLOCKED` 分支只保留 400 错误的即时 `submitError`/`requestStatus="failed"` 提示，不构造 `tempUserEnvelope`/`guardBlockedEnvelope`、不 `appendEnvelope`、不调用 `saveGuardInputBlockTurn`。`conversationStore.loadConversation`、`loadAnchoredConversation` 与 older/newer 游标分页路径统一从 conversation history 读取该轮：它作为普通 `visible=true` 消息按真实时序位置返回，刷新、关闭重开、锚定与分页后均可见，不依赖任何 `sessionStorage` 重灌。`guardInputBlockPersistence.ts` 已删除，`useChatComposerController` 的 `isInputGuardBlockedTurn` 编辑/重试特例已删除，拦截轮的编辑/重试统一走正常 `editLatest`/`retryLatest`。
- active bucket 的 `ACTIVE_LIVE_COMPACTION_WATERMARK=500` 只是无损压缩触发点。`streamCompaction` 继续拥有 accumulated snapshot、capability correlation 和 sequence-gap lane 规则；只有同一精确 lane 的等价 snapshot/text delta 可以替换或合并，其他事件不做 destructive trim。压缩后下一 watermark 为当前保留长度加 500；terminal 强制执行最终压缩。
- `useStreamConnection` 继续拥有 validation、cursor 和 animation-frame batching；`useChatSessionStream` 只按精确 session/root/attempt 从 active 或 settled 补结算 pending request；ChatPage 分阶段 memo history、settled 和 active projection，使新 active batch 不重建未变化的 historical/settled Turns。`latestEnvelopeCursor` 仍只是 viewport 内容增长信号，不是 stream resume cursor。
- `useChatViewportController` 是 conversation viewport 的唯一滚动策略 owner，并分离 `conversationView.mode`、`isFollowingBottom` 与 `isAtBottom`：`recent` 只在用户退出 following 且物理未到底时显示普通置底入口，`anchored` 复用同一入口表达“回到最新”。真实上滚必须同步退出 following、取消待执行置底并保留阅读锚点；程序性定位、分页布局变化或异步内容增高不得自行恢复 following 或退出 anchored。显式置底保留 220ms 过渡，物理到底只在真实到达后提交，动画帧不得逐帧发布页面级 scroll state。
- `ChatPage` 汇总 wheel、pointer、scroll 和 keyboard 的方向意图，并只在 `newerCursor` 耗尽且用户主动到达连续消息段物理底部后调用 `conversationStore.completeAnchoredConversation(sessionId, expectedAnchorMessageId)`。`conversationStore` 以 session、窗口 generation、mode、active anchor 和 originating cursor 校验 older/newer 响应；latest load、另一 anchor、session switch 或 clear 使旧响应失效。recent 非 following 和 anchored 回看期间的普通提交、编辑提交及迟到完成回调都保持当前窗口、anchor、following 策略和阅读位置；anchored 不暴露第三个通用 reload-latest 入口，也不新增独立新消息提示。
- 高频 live delta 继续按现有 animation-frame 边界进入浏览器投影，request lifecycle 与 terminal 保持即时处理；frontend 不建立 stream activity timeout 或 stuck-run 本地收敛 owner。最终答案在每次 Web stream 帧中直接显示已经接收并合并的完整累计正文，不使用独立 interval、字符 backlog 或第二份逐字投影；terminal 直接收敛到最后累计正文。活动且未终止的 process explanation 使用 `streaming` Markdown cache policy，不写入稳定 cache；同一内容转为 settled 时不因 policy 变化强制重渲染，后续真实重新挂载 settled/history 内容时再自然写入稳定 cache。历史、settled 和 active 投影必须结构共享，未变化的历史 Turn、Composer 和 footer observer 不得因 live、following 或 at-bottom 更新重复工作；同一 stream batch 只构建一次 session 工作集，following 内容增长按帧合并并复用 `ResizeObserver` 已测几何。报告/分享候选只在对应选择模式开启时计算，未选择详情目标时直接使用空结果，active root 同步只依赖最新 root 标识；Composer 编辑/重试回调通过最新 Turn 快照引用在动作触发时解析目标，不因完整 Turn 数组替换而更新函数身份。
- `SessionActivityConnectionController` 在每个浏览器 app instance 中只按后端 bootstrap 的 `transportKind` 建立一条 Owner + Agent 全 scope Activity connection；SSE 与 WebSocket 不并行。首帧严格 `SNAPSHOT` 原子替换 `sessionActivityStore`，后续 `DELTA` 按 `sessionId` 更新或以 `NONE` 删除；协议损坏、缺首帧、连接失败或重连都不得伪造空状态。session switch、列表分页/搜索、History/Favorites/Memory/custom panel 和 detail execution stream 不重建该连接。
- 浏览器自动重连的 SSE 流连接（Session Activity Projection Stream 和 Request Execution Stream）和 stream 断连时的 auth probe HTTP 请求 MUST 携带 `x-non-renewal-session: true` 请求头，告知后端或外部网关该请求属于自动维持的流式连接或探针，不得续期当前会话超时计时器。`connectStream` 的 `headers` 参数只作用于 SSE fetch（`createSseConnection` 合并到 `headers: { Accept: 'text/event-stream', ...(headers ?? {}) }`），不作用于 WebSocket（浏览器 `new WebSocket(url)` API 不支持自定义 HTTP header，作为受控例外）。`authProbe.ts` 的 `apiClient.get` 调用同样携带该头。该头值固定为字符串 `true`，不从客户端请求体、模型输出、capability 参数或用户 metadata 派生，不携带 credential、owner scope、agent scope 或高基数字段，不进入 stream event payload、timeline event、audit log 或 safe error。用户主动请求（submit、retry、edit、cancel、answer pending input）不携带该头，确保后端正常续期会话超时。
- local/immersive Sidebar、`SessionHistorySearchDialog`、immersive History CardList 与 collaborative History Popover 复用 `SessionActivityTrailingSlot` 和同一 store/selector。状态显示固定为等待输入 tag、运行 indicator、未读失败 marker、未读结果蓝点或既有时间；支持行操作的入口在 hover、focus-within 或菜单打开时稳定显示既有 More，SearchDialog 保持无 More。local/immersive Sidebar 的 trailing content 按实际宽度参与布局，标题使用剩余空间单行硬裁切且不显示省略号；不得固定预留 140px、绝对覆盖或用渐变遮罩。
- active session 只有在 host 提供 `isConversationSurfaceVisible=true` 时才在列表本地抑制 marker并显示时间；route active 但 conversation 被 immersive History/Favorites/Memory/custom panel 覆盖时仍显示 Activity。Collaborative History trigger 只在存在至少一个当前未被可见 conversation surface 排除的非 `NONE` session 时显示 locale-backed 聚合蓝点；不显示数量、不按状态变色、不是独立点击目标，打开 History、hover、分页或选行都不清除。
- frontend 只有在 route/host 仍指向该 session、matching terminal presentation 已成功进入 shared conversation projection、activity store 仍保存同一 terminal unread、document visible 且 `isConversationSurfaceVisible=true` 时，才提交 `{ activityId, observedRunId }` consume。滚动位置、anchored mode、列表底部或 terminal block viewport intersection 都不是额外门槛；仅选 route、收到 delta/terminal frame、打开列表/菜单、内容加载失败或 surface 隐藏不得消费。marker 本身不可点击，frontend 不从 activity payload 猜 `observedRunId`。
- `backgroundTaskStore` 独立拥有 session-scoped、按 `taskId` 合并的后台任务浏览器投影。Header monitor 的任务列表面板使用 portal 挂载的 Popover（mount 到 `document.body`，不指定 `getPopupContainer`，受控 open + Escape 关闭），宽度 `min(440px, calc(100vw - 32px))`、`maxHeight min(520px, calc(100vh - 80px))`，不被 PageHeader `overflow:hidden` 裁剪。`BackgroundTaskMonitorPanel` 进入 session 时执行一次 list seed，`useChatSessionStream` 在 conversation attempt 过滤前只路由三类 `BACKGROUND_TASK_*` envelope；普通 stream envelope 不发布 task state，seed 不覆盖较新的 live terminal 或本地 `KILLED`，header monitor 不订阅或扫描 conversation history/active/settled buckets。
- AICOConfig is stored in an independent external store consumed through `useSyncExternalStore`. Local and immersive modes share one host-neutral loader that reads `sessionStorage["AICOConfig"]` once at startup and validates it through the same path. Collaborative `loadAIAgent` validates the payload and fully replaces the previous config on each emit. The store never polls `storage` events and never caches a second snapshot.
- AICOConfig validation is hand-written in frontend TypeScript. It filters invalid fields, keeps defaults for absent fields, warns for invalid top-level values or invalid array elements, and never lets unknown fields affect behavior. The `operators` array is validated per-element. AICOConfig no longer carries Capability business names（`capabilityBusinessNames` 已删除，unknown key 按 unknown field 静默忽略）；三宿主 Capability 过程标题使用 Session-scoped Provider-backed presentation resources，按 current locale、`en-US`、stable `displayName`、id 顺序选择纯文本名称，失败保留 last-good 或按 id 降级。
- `PiuRenderer` owns AICOConfig PIU injection lifecycle: generate container id, call `Prel.autoLoad`, emit to the configured render function, render placeholder when Prel is unavailable, and clean the container on unmount. It is separate from structured answer `PiuMessage`, which owns stream-rendered PIU content.
- `ProcessPanel` and `useProcessEntryDisclosure` own Process Detail visibility and React render membership. They derive PIU-only persistent keys from the current `processDisplayEntries`; only a PIU Detail that has already entered `renderedKeys` remains mounted while its entry or the whole panel is visually collapsed. The hidden panel and Detail subtree must be both `aria-hidden` and `inert`. Non-PIU Detail keeps the normal unmount policy, and an unviewed PIU Detail is never pre-mounted. `rootMessageId + displayRunId` is the render-owner scope, so entry removal or scope replacement unmounts the old PIU even when a new entry reuses the same local key.
- Structured `PiuMessage` stabilizes its load effect by the JSON-safe PIU content value. An equal-value parent rerender must not repeat `Prel.autoLoad` or `piu.emit`; a real content-value change may reload through the existing path. Unmount cancels the component-owned late emit and clears the captured DOM container. The browser does not invent `dispose` or `destroy` host semantics; resources created outside the owned container remain the external PIU's responsibility.
- Process projection treats `completed`, `capability completed` and `<toolName> completed` as lifecycle-only text. Those values do not replace a message-derived structured PIU Detail; explicit `safeResult`, non-empty `safeSummary`, `contentUnavailable`, or non-generic completion content remains canonical and may replace it.
- Active lane 完成合并非破坏性：同一 occurrence 已渲染的非空过程正文（执行说明、Tool 结果、structured segments）在收到完成事件时原位收敛为完成态，不被空的 `contentUnavailable=true` 完成态覆盖；完成投影优先复用本订阅已交付内容，消息关联仅在无可复用内容时参与。浏览器不回传缓存正文、不把本地 view state 作为持久化或历史恢复事实。
- 用户输入分段 occurrence 因果归属：相同模型步骤只在同一已接受用户输入分段内累计更新，输入分段前后的执行说明分别保留自身时序，不得互相替换；同一 `toolCallId` 的 lifecycle、结构化过程、普通安全结果和终态形成一张以 started 时序定位的卡片（started-anchor 单卡片恢复）。browser accumulated lane 只消费输入边界之后发生的分段，不跨输入分段归属执行说明。
- 远程只读用户（无 `AICOService.Write`）下，定时任务页面写操作入口（手动创建、从会话创建、编辑、删除、执行）和记忆管理页面写操作入口（导入、新建、编辑、置顶、发布/取消发布、归档/取消归档、删除、复制共享、取消发布共享、确认导入）禁用并展示权限提示；只读操作保持可用。local 模式和有 Write 权限用户行为不变。该 UI gate 不是 trusted authorization boundary，后端仍执行权威校验。
- 浏览器诊断输出与 HTML 挂载约束：Agent Web 浏览器生产源码与 mock server 运行时源码分别通过所属诊断 reporter 输出，业务/route/data/server 源码禁止直接调用 `console.*`；block Markdown、inline Markdown 与 Mermaid 输出先维持既有净化，再经统一 parser mount 挂载，生产源码禁止 `dangerouslySetInnerHTML` 与直接 `innerHTML` 赋值，更新时清除旧节点。
- Portal ability 入口开关：active Agent package `config/config.json` 顶层 `portal-ability-config` 支持 `cron-tasks-enabled`、`long-term-memory-management-enabled`、`knowledge-import-enabled`、`full-process-enabled` 四个 boolean 字段，默认均为 `true`，仅明确 `false` 时关闭对应入口；字段独立解析，非法或缺失回退 `true`。前端只消费 runtime bootstrap public DTO，不读取 Agent package raw config。
- 完整过程入口 gate：`portalAbilityConfig.fullProcessEnabled=false` 只隐藏 ProcessPanel 摘要行右侧的“完整过程”按钮，不移除执行详情摘要、折叠过程条目或最终答复，也不改变 Run Graph、timeline 和 history API。该 gate 与过程数据可还原性、`AICOConfig.showThinkingChain !== false` 按 AND 组合；任一条件不满足时按钮不可见。

- Capability Result 只消费后端 `StreamEnvelope` 中的 `resultPresentationLevel`、闭合 `safeSummaryCode`/有界 `safeSummaryArgs`、兼容 `safeSummary`、`safeResult`、截断与安全失败字段。`STATUS_ONLY` 不补写“暂无摘要”或空详情入口，`SUMMARY` 仅按当前 locale 渲染摘要，`DETAIL` 才提供安全详情 disclosure；locale 切换只重渲染既有 envelope。浏览器不得从 conversation raw content、Tool 参数、本地 Tool state 或未知 descriptor 恢复详情。
- Grep 的前端 parser 只接受闭合 `grepResult` variants：文件模式渲染有界 `filenames`，内容模式渲染有界 `filePath` 与 1-based `lineNumber`。摘要只解释后端提供的两个 Grep summary code；未知或非法 shape 不产生详情，浏览器不得恢复 matched line、pattern、glob filter 或调用参数。
- RAG 成功结果的过程面板展示只消费 `kind="ragRetrieval"` 安全摘要：显示召回总数、每个 `displaySource` 及其 `contentPreview`，`sourceMissing=true` 的条目显示本地化的来源缺失标签，`contentTruncated=true` 时在预览末尾追加 `...`。每个 `displaySource` 渲染为与内容预览视觉分离的紧凑来源标签；`contentPreview` 中连续空白字符（包括换行和空行）替换为单个空格并去除首尾空白后再展示。预览上限按原始 `content` 中汉字与拉丁字母数量确定：汉字数量大于拉丁字母数量时最多 40 个 Unicode code point，其他内容最多 100 个 Unicode code point。`processDetails.ts` 不读取原始结果正文、`provenance`、`score`、`rankHint` 或诊断对象。实时 stream 投影与历史重建为同一 RAG 结果生成同形摘要，三宿主复用同一实现。
- Capability 失败在三档成功结果策略下均显示同一公开身份、失败状态和唯一事实性原因；安全 code/category/本地化调用状态默认收起，展开后也不得出现 raw exception、路径、参数、结果正文、provider error、credential、token 或 correlation id。`safeErrorCode`、category 和 retryable 不能单独生成 Capability CTA、自动恢复承诺或 request terminal 结论。
- `CAPABILITY_STARTED` 只按结构化 Capability 公开身份和本地化运行状态呈现；输入归一化和过程投影都忽略未受治理的启动自由文本、Event type、内部状态枚举与未知摘要 descriptor。模型调用工具前的公开执行说明继续位于独立的 icon-free bridge lane。
- Capability 过程标题由共享前端 process projection 集中生成：名称解析按平台固定 `kind + id` 映射、当前 AICOConfig 中当前界面语言的集成名称、当前前端产物当前界面语言的构建期集成映射、合法技术标识或中性标题降级的固定优先级命中后停止查找，当前语言缺失时继续到下一优先级且不借用另一语言。普通 Tool 的映射值是完整标题；Agent、Skill、Workflow 的目标名称由平台固定模板包装。AICOConfig 集成名称由 `TurnBlock` 从已订阅 snapshot 与当前 locale 派生的 `${kind}:${id} → name` lookup 显式传入 process builder 与 `capabilityProcessTitle` resolver；resolver 与 process helper 保持纯函数，不 import AICOConfigStore 或 React hook。平台固定映射优先于全部集成名称来源；AICOConfig 中与平台固定身份相同的条目不改变平台名称。名称按纯文本渲染，不解释 HTML 或 Markdown。历史记录只保存执行身份，当前有效 AICOConfig、前端产物或界面语言变化后按当前优先级重新渲染。标题不读取参数、结果、模型输出、描述或浏览器缓存，locale 切换只重渲染既有公开身份，且名称适配不改变过程条目、状态或结果呈现级别。
- Agent Web 增加同格式防御性 reader 消费 optional `capabilityTargetName`：合法名称与 wrapper 组合为 `<wrapper> · <target>`，并按同一 `toolCallId` 在后续结果与完成事件中保留已观察到的名称；后续事件未携带名称时优先保留条目已有标题，没有先前名称时回退到 wrapper 标题。非法字段按缺失处理。legacy 单事件描述与主聚合路径复用同一标题形成 helper。completion-only 历史、关联无法唯一证明或格式非法的步骤继续使用 wrapper 身份和状态，不为恢复名称新增网络请求。该行为在 live、刷新后的 run-event history、SSE、WebSocket 以及 local、immersive、collaborative 三种宿主中一致。

## Page Layout 组件职责

`PageHeader`、`PageContentFrame` 和 `PageLayout` 位于既有 `frontend/agent-web/src/components`，共同承载 `agent-web-page-layout` 的浏览器实现，不形成新的目录层级、后端契约或运行时依赖：

- `PageHeader` 唯一拥有共享 Header DOM、透明背景、标题截断、可选结构化返回操作和右侧操作区域位置。其 `actions` 是页面提供的不透明 `ReactNode`；布局层不读取操作数量、业务优先级或回调状态，不生成 action descriptor、自动菜单或任意 leading slot。
- `PageContentFrame` 唯一拥有 `contained | fluid` 内容宽度和水平安全内边距。`PageLayout` 组合 Header、main Content 和可选 docked Footer，并以 `scrollOwner: 'layout' | 'content'` 区分普通布局拥有 viewport 与业务内容拥有 viewport 两种结构；它不接收 conversation viewport handlers、overlay、footer surface 测量或 following/anchor/pagination 状态。
- `RightPaneLayout` 是会话专用适配器而不是通用页面模板。它只复用 `PageHeader` 和 `PageContentFrame`，继续拥有完整 main viewport、scrollbar gutter 补偿、overlay composer、footer surface 高度测量、浮动置底入口、免责声明和 `headerSlot`。测得的 footer 高度只转换为内容 bottom safe area，不得决定是否追底或写入绝对 `scrollTop`；会话滚动意图继续由 `useChatViewportController` 唯一拥有。
- `CronTaskDashboardPage` 使用 `contained + layout`，并自行提供两个创建操作及其顺序、样式和回调；`FavoriteTurnsPanel` 使用 `fluid + content`，保留 `.favorite-turns-scroll` 作为展开超高时的唯一滚动区域且不提供页内返回。local、immersive 和 collaborative/PIU 直接复用页面组件，宿主只通过已有导航或扩展容器关闭入口退出页面，不添加布局 wrapper。
- 定时任务、收藏列表、记忆管理、知识导入和投诉历史分别以 `cronTasks.title`、`favorites.title`、`memoryManagement.title`、`knowledge.importTitle` 和 `complaint.historyTitle` 作为唯一页面名称来源。各宿主只把自身既有入口投影为同名 Tooltip、无障碍名称和对应浅色/暗色主题 SVG，不统一菜单集合、顺序、容器或可见性 gate；三个宿主已有的新建会话入口复用同一组 `new-session` 主题 SVG，但保留各自按钮、handler 和导航生命周期。
- `ComplaintHistoryView` 只拥有投诉 PIU 内容、探针关闭和 `window.Prel` 不可用时的既有降级；`ComplaintHistoryPage` 只组合共享 `PageHeader` 与剩余高度容器。`KnowledgeImportView` 只拥有知识导入 PIU 内容（`MCSemanticPIU / loadDataSet`）和 `window.Prel` 不可用时的既有降级，不依赖 probe 探针；`KnowledgeImportPage` 只组合共享 `PageHeader` 与剩余高度容器。主内容和 Collaborative/PIU 左侧扩展内容使用页面投影，模态弹框继续使用纯内容投影，避免重复标题或第二个纵向滚动 owner。

共享布局没有网络、持久化或业务失败路径；宽度不足时由 CSS 截断标题，业务页面负责其操作区域在受支持容器内的可用性。禁止把 overlay Footer、会话滚动策略、业务 API、route state、Owner Scope、Agent Scope、宿主菜单 authority 或页面操作收纳决策下沉到 `PageLayout`。记忆管理、最近历史和自定义扩展页面尚未整体迁入该模板；投诉历史只复用共享 Header 和页面高度结构，不把 PIU 内容职责迁入布局层。

## 验证关注点

- No AICOConfig and empty AICOConfig must be visually and behaviorally equivalent to the existing defaults.
- Invalid AICOConfig must fail soft to defaults without crashing.
- Process history must remain semantic-result Message-first and true-viewport driven, with the closed bounded structured-presentation Event transition described above, 16 automatic targets、16 explicit intents、four active identities、session-teardown-only abort and atomic whole-run cache bounds; invalid pages or non-advancing cursors fail only the affected run with a safe retry state.
- Completed live and cold-history turns must project one equivalent inspectable process; cumulative thinking must not remount, flash or duplicate.
- Local, immersive and collaborative process-history journeys must use the same service/store/projection/disclosure implementation.
- Local mode must read `sessionStorage["AICOConfig"]` once at startup through the same host-neutral loader as immersive; missing, malformed, or partially invalid config must not block startup or other customization.
- Collaborative repeated `loadAIAgent` must fully replace config and reset active PANEL state.
- PiuRenderer must cover Prel available/unavailable paths and cleanup.
- Process Detail PIU lifecycle tests must cover automatic, manual, whole-panel and reduced-motion collapse; stable DOM identity and interaction state; hidden `aria-hidden` plus `inert`; no pre-mount for unviewed PIU; ordinary Detail unmount; equal-content rerender; owner/scope removal cleanup; and suppression of late emit.
- Operators, answerOperator, quickInfo, inputOperator, guideInfo, operatorPosition, modalSize, declaration, clearStorage, showAskTime, showThinkingChain, and icon/name/welcome overrides need component or unit coverage.
- Composer、根路由会话建立、attachment、edit/title projection、Run Graph、assistant Markdown/table、Mermaid 和 Pending Input 切换/过期显示/取消委托分别使用 focused frontend tests；浏览器旅程变化追加对应 Playwright/e2e 证据，不能用根目录 asset-copy build 代替 frontend package build。
- Conversation projection 必须覆盖 terminal 原子迁移、accepted identity 后到、重复/旧 attempt 事件、history/settled source precedence、canonical invisibility、anchored window、edit/retry/rollback、clear/LRU、超过 500/1000 个有效事件、旧 Turn 引用稳定和 settled execution detail 跨后续 Turn 保留。
- Conversation viewport 必须覆盖 short recent、recent 非 following、anchored 有/无 `newerCursor`、真实与程序性滚动、异步布局增长、双向分页、回看期间提交、过期分页响应、220ms 置底取消与物理到底提交；验证入口包括 `useChatViewportController.test.tsx`、`chat-page.route-state.test.tsx`、`conversationStore.test.ts`、`useChatSessionStream.test.tsx`、`MessageList.render-stability.test.tsx` 和 `right-pane-layout.scroll-shell.test.tsx`。
- Skill Modal 必须覆盖首次请求、搜索 loading、结果、空结果和分页期间外框几何不变，并由 `SkillSelector.test.tsx` 验证固定列表视口与内部滚动。
- AskUserQuestion 必须覆盖 1/4/20 题分页、草稿返回修改、单次原子提交、提交失败保留、active-to-settled、后续 Turn、refresh/gap recovery、orphan/received-only fallback、duplicate 和跨 attempt 隔离，并断言翻页无额外网络请求、回答不从 raw content 或浏览器 request body恢复。
- Capability Result 必须覆盖三档成功呈现、双语摘要、失败唯一原因与技术详情、未知 descriptor fail closed、活动 status-only 状态、刷新等价、500 个混合步骤零逐结果请求，以及 local/immersive/collaborative 复用同一 renderer。
- Capability 标题必须覆盖平台映射、集成构建期映射、普通 Tool/通用入口回退、非法身份中性降级、双语重渲染和 live/history/三宿主等价，并断言名称适配不增删过程条目或改变结果策略。
- Background task projection 必须覆盖 seed/live 到达顺序、普通 stream no-op、session 隔离、本地 `KILLED` 优先级和 retry/edit 后旧 attempt 终态更新。性能验收以相同 fixture 的 browser trace 和 Turn render/reference counter 证明跨 Turn 放大消失；不得只用 `[Violation]` 日志是否出现作为结论。
- Session Activity 必须覆盖 strict snapshot-first/delta store、SSE/WS 单连接互斥与重连、四个列表入口共享 trailing semantics、active-visible 抑制、More/键盘嵌套交互、collaborative 聚合蓝点、matching terminal presentation consume、hidden/overlay/load-failure/迟到 consume negative cases，以及 local/immersive/collaborative 共用同一实现。
- Page Layout 必须通过组件测试验证 Header 几何、页面 actions 原样投影、`contained | fluid`、docked Footer 与负向禁止项；通过 RightPane characterization 验证会话 viewport、overlay footer 和 bottom safe area；通过页面及宿主测试验证 Cron、收藏和三宿主没有重复 Header 或第二滚动容器，并覆盖四组页面名称、两种语言、两种主题、业务入口 `20px`/`16px` 尺寸、新建会话 `20px` 主题图标、投诉页面/模态单标题和宿主特有菜单不变；真实页面切换与 following/回看行为使用 Playwright 验证。
- 前端行为改动至少运行 focused Vitest 与 `frontend/agent-web` 的 `npm run build`；涉及三宿主 artifact 或共享 ChatWorkspace 时追加 `npm run build:vite:modes`，涉及真实用户旅程时追加对应 Playwright gate。
- 长期记忆文件转换测试必须覆盖 JSON 不可信边界、确认前零写、容量 normal/boundary/failure、稳定幂等重试、当前筛选全分页、本地化列和 CSV 注入 negative cases。

## Capability 失败处置协作

浏览器只显示后端投影的最终安全状态、唯一事实性原因、可选技术详情和受治理结果引用；不得从 raw conversation、Tool 参数或本地状态恢复错误详情，也不得发起自动 retry、推断授权控制或改变 terminal truth。local、immersive、collaborative 三种宿主复用同一 renderer 和语义，完整安全边界见 `openspec/designs/architecture/capability-invocation-and-failure-disposition.md`。
