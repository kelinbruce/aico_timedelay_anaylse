## 背景与问题（Why）

当前 TS 后端把 runtime diagnostic、observation-derived trajectory 和部分 metric sample 分别写入硬编码日志文件，`agent-common` 中的产品 logger 仍使用手写 stdout / synchronous append。与此同时，audit 的权威记录写进共享 SQLite `audit_events` 表，又通过 `RuntimeLogger` 镜像到 `nextagent-audit.log`。这些实现混淆了三种不同责任：运行日志用于问题定位，audit 是 gateway-owned 治理证据输出，metrics 是聚合遥测并应通过 OpenTelemetry Metrics SDK 的 reader/exporter 输出。

运行日志本身并不天然依赖业务 event。当前代码只是已经存在一条可复用的 event-derived trajectory 主链：`agent-runtime` 持久化并发布 `RunTimelineEvent`，`agent-app/request-runtime-composition` 调用 `TimelineObservationMapper`，再由 `ObservabilityProjectorHost` 和 `StructuredLogProjector` 生成 trajectory log。已有 canonical lifecycle fact 应继续优先走这条链；没有对应业务 event 的组件诊断、边界失败和运维状态可以直接通过 `agent-common/getLogger` 获取的 component-scoped `RuntimeLogger` 输出结构化日志，不得为了打印日志伪造 observation 或新增 lifecycle event，也不得为了新增一个需要日志的类修改 app 装配参数。

当前运行日志还缺少统一文件归口、公共 envelope、开发态 console 策略、异步非阻塞写入、按大小或最长 active 周期轮转、压缩归档和 7 天自动老化。仅统一 writer 也不能证明请求、模型、能力、sandbox、stream、terminal 或恢复问题实际留下了安全且可关联的定位证据，因此本 change 同时收敛重复 producer，并补齐最小基础诊断 coverage。

当前异常日志还存在另一类重复：model、tool、context、gateway、app listen 等中间层 catch 在记录 `err` 后继续抛出，外层终止边界又可能记录同一异常。外层无法可靠地从异常对象、指纹或进程内标记判断“是否已经打印”，而包装异常时如果没有稳定 `cause` 链又会丢失原始失败位置。因此本 change 同时冻结异常传播、包装、消费和打印规则：是否记录由执行根的终止责任决定，而不是由“首次 catch”决定。

## 黑盒目标

1. 所有启用的非审计 application operational log 都以结构化 JSON 写入一个 operational JSONL file family；runtime direct diagnostic 与 observation-derived trajectory 共享物理 writer，但通过 `surface` 保留不同事实责任。audit、metrics、trace、health 和 developer-owned trace artifact 不属于 operational log file。
2. 开发态可以通过冻结配置启用结构化 console 输出，不要求业务 package 改变日志调用方式。
3. active operational log 达到默认 30 MiB 大小阈值或持续到进程本地每日零点边界时自动轮转，任一条件先满足即生效；closed segment 自动 gzip 压缩；默认保留 7 天且最多保留 10 个 committed gzip archive，并在到期或超出数量上限后的一个 maintenance 周期内自动老化，重启时补做 reconciliation。任何 retained operational entry 都不得因低流量 active file 永不轮转而超过该目标窗口加一个 daily active 周期；数量淘汰只处理 operational owner 精确证明归属的 archive。
4. 通过 app-composed 公共机制补齐基础运行日志：已有 canonical `RunTimelineEvent` 的生命周期事实优先且唯一地通过 timeline -> observation -> projector 输出；timeline 未表达但属于 approved trajectory fact 的边界使用 typed adapter；普通组件诊断和 owner-private 运维状态直接使用 component-scoped `RuntimeLogger`。普通直接诊断必须有稳定 code-owned log `event`；唯一例外是 Fastify 原生 final access record，它使用 Fastify 固定 `msg` 和原生 access fields，不伪造 operational event。
5. 日志调用不改变业务结果且不在业务路径执行同步文件 I/O、gzip、retention、等待 sink 或无界缓冲。业务路径只做有界 level check、字段规范化/redaction、JSON serialization 和异步 enqueue；每个 destination 使用 implementation-owned 4 MiB buffer 上限，单条 normalized entry 上限 16 KiB，饱和时丢弃新 entry 并聚合 bounded degradation evidence，绝不向业务路径施加 backpressure。writer、rotation、compression、retention 与 bounded shutdown flush 在独立异步生命周期中完成；app 先停止全部 producer，再分别关闭 audit gateway 与 metrics pipeline，最后关闭 operational writer。
6. 业务 metrics 继续复用同一 descriptor inventory、labels、bounded recent-fact dedup、OTel MeterProvider 和 `PeriodicExportingMetricReader`；HTTP server metrics 则由官方 `@opentelemetry/instrumentation-http` 在同一 MeterProvider 上按稳定 semantic conventions 原生产出 `http.server.request.duration`。生产 registry 只流式记录业务 OTel instrument，不保存或重放原始 `MetricSample`；test 才注入有界 in-memory registry/exporter。LOCAL deployment 每 60 秒向独立的 daily metrics NDJSON file family 追加一个 cumulative 聚合快照，达到 30 MiB 或跨日即轮转，closed segment gzip 并保留 7 天且最多保留 10 个 committed gzip archive；因此任一 entry 的目标上界是一个 daily active 周期、7 天 closed retention 和一个 maintenance interval。REMOTE/PaaS deployment 只使用 OTLP metric exporter。metrics 文件不是 operational log，不含原始 MetricSample、业务内容或高基数关联字段。
7. local Agent Dev Workbench 继续通过现有 bounded log-evidence API 查看当前 transport-owned active operational segment：按 entry 的 `surface` 区分 runtime diagnostic 与 observation-derived evidence，而不是按旧文件名猜测。Workbench 不读取 closed source 或 `.gz` archive；历史归档由运维通过文件工具查看，日志仍不得成为业务事实来源。
8. audit 不进入 operational log、metrics 或共享 SQLite。`AuditEventStoreGateway` 作为 `agent-contracts/gateway` 的 write-only deployment port：LOCAL 将完整 `AuditEventRecord` 追加到独立 audit NDJSON file family，按 30 MiB 或 daily 边界轮转、原子 gzip，并在 original closedAt 后固定保留 7 elapsed days且最多保留 10 个 committed gzip archive；REMOTE/PaaS 上报 audit service。LOCAL audit 使用稳定 `auditId` 的 duplicate-tolerant append 语义，不提供产品查询接口，也不宣称 exactly-once。
9. operational log 必须支持从失败现象收敛到可执行的根因定位：已知错误通过 code/category/stage/correlation 定位；未知内部异常只有在所属执行根的异常终止边界才保留一条与 canonical failure 可关联的安全异常诊断。异常包装必须使用 `cause` 保留原始异常，writer 以最多 4 个 Error 节点、整条链最多 5 个 NextAgent-owned frame refs 和 64 KiB 总检查预算投影有界异常链，并安全处理循环或超深 cause。每条 operational entry 必须携带 app-owned `serviceVersion`，以便 frame ref 与实际部署代码对应。原始 error message、raw stack、provider body、non-Error 原值和 host path 继续禁止。
10. operational physical schema 必须面向维护检索而非暴露 logger 实现细节：`level` 使用 `debug|info|warn|error` 文本；普通 operational entry 使用唯一稳定 `event` 表达机器语义。Fastify final access record 作为受控例外保留原生 `request completed|request errored` message 与 access field shape，不增加 `event`；其中 `req` 只保留 method 和 validated route template（未匹配固定为 `unmatched`），足以定位接口但不记录 raw URL/query。公共 writer 统一执行 reserved-field ownership、敏感键过滤、值与 message 脱敏、限长和 non-throwing 降级。
11. exception handling SHALL 按执行根而不是按 package 建立 owner-scoped 终止边界：accepted request 归 `agent-runtime`，同步 Web/Task transport 归各 channel，composition/start/close 归 deployment/app lifecycle，后台 callback 归调度 owner，逃逸到进程的 fatal exception 归 deployment entrypoint。继续抛出同一异常或用 `cause` 包装后抛出的中间层 MUST NOT 记录该异常；吃掉异常、返回 fallback/degraded、转换为 safe terminal/HTTP response 或终止进程的边界 MAY/MUST 按 catalog 记录。实现 MUST NOT 增加 `alreadyLogged` 字段、异常对象标记、全局 WeakSet、指纹去重或 AsyncLocalStorage 去重来弥补 owner 不清。
12. Tool 原始输入和原始输出可作为本地 runtime diagnostic 记录。Tool 执行 owner 可以通过 canonical `toolInput` / `toolOutput` 字段记录实际输入和有效输出；集中 writer 只对 credential 与认证类 token 做窄匹配脱敏，保留 prompt、path、command 和业务内容，并避免误伤 credential reference/status、usage token counts、token count/length 与 tokenization diagnostics。writer 仍执行有界递归、单值截断和 16 KiB entry fallback。该例外只属于本地 runtime direct diagnostic，不改变 observation、audit、metric、trace、stream、timeline、SafeError 或 public DTO 的数据最小化规则。

## 变更范围（What Changes）

- 新增 Node-only technical foundation package `agent-local-file-roll`，只封装 async line destination、size+daily rotation、active identity、atomic gzip、closedAt 保真、startup reconciliation、elapsed retention、single maintenance lane和 bounded close；不理解 operational/audit/metrics schema、deployment config、readiness 或业务失败语义。新增 `agent-log` implementation package，owning Pino operational envelope、console sink、component-scoped RuntimeLogger和 operational policy，并使用一个独立 local-file-roll handle。
- `agent-common` 保留 structural Pino-compatible `RuntimeLogger`、`getLogger` lazy facade、单 active provider 绑定 contract、noop logger、runtime log level 和 operational surface vocabulary；facade 不拥有 I/O、sink policy、Pino instance 或 archive lifecycle。`agent-log` 的同一 logger 实现通过可信 binding 固定 `runtime_diagnostic` 或 `observation_derived`，不得为 trajectory 维护第二套 transport API、字段净化或 level 路由。
- `agent-app` 只解析并冻结统一的 `observability.logging`：`level`、`console`、`file` 控制 operational writer，`diagnosticDetail=normal|debug` 只控制已经过安全策略批准的诊断细节；旧 `observability.runtimeLogging` 和语义误导的 `observability.logging.redaction` 均被拒绝，不保留兼容别名或第二套解析路径。app 在启动时把 `agent-log` provider 装配到 facade 一次；各 owner 自行通过 `getLogger` 获取 Pino child facade，不要求新增构造注入。
- 普通 operational physical envelope 至少包含 writer-owned `timestamp`、文本 `level`、`surface`、app-bound `component`、app-owned `serviceVersion` 和稳定 code-owned `event`。Fastify final access record 保留相同 writer-owned envelope，但用固定 native `msg` 取代 `event`。两者都不持久化 `operation` 或 `outcome`。
- 扩展并重新归位现有 `TimelineObservationMapper`，覆盖当前实际产生的 request、model、capability、policy/hook、context degradation/compaction、pending-input 和 background-task canonical timeline 事件；live delta 只允许生成不含内容的一次性 milestone。
- 删除 generic runtime-log-to-observation bridge、重复 model invocation wrapper、runtime internal observation 和同语义 owner outcome 日志；运行日志共享 writer 不等于所有日志都从 event 派生。
- typed wrapper 范围冻结为 `ContextEnginePort.assemble` 和 `AppSandboxGatewayPort.execute/executeWithStdoutChunks`；不 blanket-wrap persistence gateway、`ContextEnginePort.render`、readiness query 或已由 capability timeline 覆盖的 RAG/SkillHub/workflow call。
- 建立基础诊断 coverage catalog。catalog 只冻结 change 承诺必须出现的定位里程碑及唯一 producer，不试图枚举或禁止所有合法 component diagnostic。
- Fastify server boundary 直接使用默认 `LogController` 的原生 access pair：`incoming request` 携带安全 `req`，随后 `request completed|request errored` 携带 `res` 与 `responseTime`，两条记录通过 Fastify server-generated 原生 `reqId` 关联。`agent-app` 不实现 access logger facade、custom LogController 或 access 字段拼装，只把 `agent-log` 从同一个 Pino root 派生且配置了安全 serializers/hook 的 child 作为 `loggerInstance`。`req` serializer 只保留 method 和 validated route template（未匹配固定为 `unmatched`）；raw request/response/header/URL/query/client request id不得进入输出。HTTP server metric 由官方 OTel HTTP instrumentation 在 Node HTTP boundary exact-once 记录，不参与 access log 生成；`agent-app` 不保留手工 `onResponse` metric observer。
- 默认 logical base 为 `logs/nextagent-operational.log.jsonl`。pino-roll 同时使用默认 `size=30m` 和固定 `frequency=daily`，在大小阈值或进程本地每日零点任一条件先满足时生成新的 numbered operational segment；archive maintenance 只压缩 transport 明确关闭的 segment。
- operational、plugin diagnostic、LOCAL metrics 与 LOCAL audit 的 daily 文件名和轮转边界统一使用 Node.js 进程本地时区；四个文件族都使用 30 MiB size threshold、daily OR 轮转和最多 10 个 committed gzip archive；该时区在进程生命周期内固定且不可由 runtime input 或 app logging config 覆盖。DST 只影响 calendar-day 长度；各 owner 的 retention 都按各自 `closedAt + retentionDays * 24h` 的 elapsed time 计算。
- `agent-log`、`LocalMetricHistoryExporter` 与 `agent-platform-gateway-local` 的 file audit gateway 分别用自己的 frozen family policy 创建独立 `agent-local-file-roll` handle。三个 handle 共享机制代码但不共享 destination、active identity、buffer、timer、maintenance lane、状态或 close；压缩都采用 `.gz.tmp -> atomic .gz -> delete source`，archive 保留原始 closed/rotation timestamp，失败保留 source 并由所属 handle 重试。
- operational 默认 `retentionDays=7`，plugin diagnostic 固定 3 天，LOCAL metrics 与 LOCAL audit 固定 7 天。四个文件族均最多保留 10 个 committed gzip archive；elapsed retention 与 archive count 独立生效，超出数量时按 `mtime`、文件名最旧优先删除。各自的 startup reconciliation、每分钟 archive scan 和每小时 retention aging 都在独立异步 maintenance lane 中执行；每个 owner 只按精确 selector 清理自己证明归属的文件。audit 长期合规归档仍属于外部部署治理，本地文件不得因此无限增长。
- development 默认 console enabled/file disabled；local runtime package 默认 console disabled/file enabled；test composition 默认 silent。
- transport 初始化、write、rotation、compression、retention、buffer overflow 和 flush/close 失败均不得阻止 app ready、改变 request lifecycle 或触发 logger-owned shutdown。共享 writer 不可用或 destination overload 时只允许 app-owned、异步且按状态转换限频的安全 stderr emergency diagnostic；调用者不等待它，不得回显被丢弃 entry；emergency reporter 自身失败时静默终止，不再建立同步 fallback。
- audit 不进入 operational writer。`AuditProjector` 只调用 observability-owned `AuditEventWriter` output port；`AuditEventRecord`、write-only `AuditEventStoreGateway.appendAuditEvent(...)` 及顶层 `GatewayBindings.audit` 明确归 `agent-contracts/gateway`（agent gateway contract module）。删除 `AuditEventRecordQuery`、`listAuditEvents(...)` 和 `SqliteGatewayStoreBindings.audit`；app adapter 显式完成 `AuditEvent -> AuditEventRecord` 映射并调用 deployment-selected gateway port。LOCAL implementation 位于 `agent-platform-gateway-local`，写 `<paths.logDirectory>/nextagent-audit.<YYYY-MM-DD>.<sequence>.ndjson[.gz]`，按固定 30 MiB 或 daily 边界轮转、原子 gzip closed segment、最多 10 个压缩归档并独立执行固定 7 elapsed-day aging，同时删除 SQLite `audit_events` 表/store；PaaS implementation 属于 `agent-platform-gateway-remote`。移除 logger-based `nextagent-audit.log` mirror，不让 gateway implementation 反向依赖 observability DO，也不在 `agent-log` 中建设 audit logger。
- metrics 不进入 operational writer。移除默认和显式的 metric-to-log sink；建立单一 `MetricDescriptor` inventory，并由它共同 owning kind、unit、allowed labels、value/acquisition source 和 OTel instrument creation。所有 seconds-duration histogram 使用冻结 explicit bucket vector；生产 registry 为 streaming-only，不保存/重放 raw sample；projector 使用容量 `16_384` 的 FIFO recent-fact dedup，test composition 才注入有界 in-memory registry/exporter。`agent-observability` 建立单一 OTel SDK pipeline，固定 `PeriodicExportingMetricReader(exportInterval=60s, exportTimeout=10s, cumulative temporality, cardinalityLimit=200/instrument)`；LOCAL 注入 rolling NDJSON history exporter，REMOTE/PaaS 注入 official OTLP metric exporter。
- `LocalMetricHistoryExporter` 把每次 OTel cumulative collection 规范化为一条 UTF-8 serialized bytes（含换行分隔符）不超过 4 MiB 的 `NextAgentMetricSnapshotV1` JSON line，并 owning metrics schema/policy、single-flight 和 export failure mapping；它通过独立 `agent-local-file-roll` handle 使用 8 MiB async buffer、30 MiB 或 fixed daily 任一轮转、gzip、最多 10 个压缩归档、7-day retention、startup reconciliation 和 bounded close，不使用 RuntimeLogger/Pino envelope，也不进入 operational file family。
- metrics serialize/enqueue/write/rotation/gzip/retention failure 不影响业务结果，也不回退成 per-sample log；只允许 `metrics.export.degraded/recovered` 各状态转换一次的安全 component diagnostic。
- operational、plugin diagnostic、metrics 与 audit 不复用 writer、schema、policy object或运行时 handle，只复用 `agent-local-file-roll` 的无领域语义机制。`agent-log` 分别拥有 operational 与 plugin diagnostic 两个独立 handle，`LocalMetricHistoryExporter` 只拥有 metrics family，LOCAL audit gateway 只拥有 audit family；四个文件族使用不同 base、handle、active destination、derived exact selector 和 lifecycle state，互相不得发现、压缩、老化或删除对方文件。Workbench 不读取 audit/plugin diagnostic file。
- RuntimeLogger 的四级调用均采用 Pino 风格 `fields, msg?`；只有异常终止边界或明确消费/降级边界才把捕获值放在标准 `err` 字段中，继续抛出或包装后抛出的中间层不得调用 logger。禁止 caller 进行日志专用类型判断或把异常拆成 message/name/stack。`AgentError` 继续由 `agent-common` owning，并使用标准 `cause` 语义保留包装链；不新增 `agent-contracts` 异常 DTO。operational writer 统一识别 `AgentError`、普通 `Error` 和 non-Error throw，并集中处理字段与 message：非 INTERNAL AgentError 只输出稳定 code/category/retryable；INTERNAL AgentError 和普通 Error 额外生成 allowlisted `exceptionType`、安全异常码、bounded `exceptionFingerprint`、最多 4 个 Error 节点、整链最多 5 个 NextAgent-owned `exceptionFrames` 和显式 chain truncation evidence；non-Error throw 只输出 category和 `exceptionType=NonErrorThrow`，不得回显原始值。producer 必须提供 code-owned `event`、`failureStage`、适用的 trusted correlation和只含 code-owned template + 已验证低风险变量的可选 `msg`；只有存在独立于 event/failureStage 的稳定领域子原因时才提供 `safeReasonCode`。`fallbackReasonCode` 与通用 `UNEXPECTED_FAILURE` 均被删除；logger 不推断业务阶段、严重度或是否应记录。prompt、模型输出、parser 原文等禁止内容不得作为“等待 logger 脱敏”的原始业务对象传入。
- Tool loop 在 normal 与 debug diagnostic detail 下都为已形成有效输出的 Tool 调用输出 info `tool.payload.captured` direct diagnostic，并在既有失败/结果校验 diagnostic 中补充 canonical `toolInput` / `toolOutput`。两字段由 `agent-log` 作为 Tool payload 专用字段执行容量归一化，只窄匹配脱敏 credential 与认证类 token，保留 prompt/path/command/content 和正常 token/credential 诊断元数据；该行为不由 `diagnosticDetail` 关闭，也不增加第二套配置或写入路径。该 direct diagnostic 只表达 payload 已被本地诊断采集，不表达 Tool lifecycle outcome，不创建 observation 或 timeline fact，也不替代 canonical capability outcome。
- accepted request 的未知执行异常由 `agent-runtime` request termination boundary 以 `event=request.execution.exception_captured`、`failureStage=REQUEST_EXECUTION` 记录一次，随后进入既有 SafeError 与 terminal commit；model/tool/context adapter 仍可先形成 canonical safe failure fact，但只要继续抛出就不得再记录 direct exception。terminal commit 自身失败是新的独立失败操作，使用 `request.terminal_commit.failed` 和 terminal-owned failureStage，不能被外层误记为 scheduler dispatch failure。
- `runtime.submit.orphan_session` 是独立的 pre-acceptance degradation fact，不是 caught exception diagnostic：只在 sessionless submit 已创建内部 session、但尚未 durable accept 任一 RequestRun 即失败时输出一次，字段只含可信 session/parent refs和 derived safe failure reason，不含 `err`/exception chain；原 submit exception 继续传播。RequestRun 一旦 accepted，后续 checkpoint/event/enqueue failure 不得再把 session 标成 orphan。
- `todo.runtime.replace.failed` 与 `todo.gateway.replace.failed` 都属于中间层 log-and-rethrow，必须删除；Todo runtime/gateway 可保留 start/completed，失败由 capability/request 终止 owner 的 canonical outcome或 exception diagnostic表达。
- Web/Task channel 的顶层 error handler 只处理尚未被 runtime 转成 terminal fact 的同步 transport/request exception：non-INTERNAL `AgentError` 与 Fastify/TypeBox schema validation 等 boundary-owned expected failure 映射既有 safe 4xx/状态且不追加 exception diagnostic，INTERNAL/未知异常记录一次安全 direct diagnostic并返回 safe 500。Fastify access record 可继续表达 transport outcome，但不得再次附带同一个 caught 的 exception chain。
- composition/start/close、background callback 与 process fatal 各自有显式终止 owner。composition/listen/gateway 等内层只 cleanup并传播；`agent-app` startup wrapper 用 `AgentError(code=APP_START_FAILED, cause, safeDetails.failureStage)` 保留 allowlisted startup stage，并从 package root 暴露唯一的 app-owned classifier 供 LOCAL/REMOTE deployment boundary验证，禁止复制 allowlist或 private import；未知/非法 wrapper固定回退 `APP_STARTUP`。deployment在 app 已创建时通过当前 operational logger记录一次并终止启动，app 尚未创建时只走 bounded emergency reporter。shutdown finalizer catch 记录并继续后续 finalizer即视为消费该独立异常，`close()` 不得在结束时重抛同一异常对象。后台 owner 在吃掉异常并继续 loop 时记录一次。deployment entrypoint 的 `uncaughtException`/`unhandledRejection` handler 只作为最后防线，进行一次有界安全报告、bounded flush 和非零终止，不承担业务恢复。
- 公共 writer 的敏感键和值过滤必须支持窄的 code-owned semantic allowlist：normalized usage 的 `inputTokens/outputTokens/totalTokens` 仅接受非负安全整数；其它 token/path/credential 类字段继续拒绝。Fastify access fields 由 boundary adapter 按原生 safe shape 投影，不依赖通用 `routeTemplate` allowlist。
- routine policy allow、context success、hook success、sandbox success 和 first-visible 使用 info，便于默认级别下定位内部 run 进展；context budget/micro-compact 成功和 task trajectory enqueue/build/skip 可继续使用 debug；degradation/denial/drop 使用 warn，failure 使用 error。Skill scan 含失败时使用独立 degraded warn event；category-question source unavailable 按 agent+locale 状态转换限频并在恢复时输出一次 recovered signal。
- app composition 默认使用产品版本；LOCAL/REMOTE runtime package 使用 `version + candidateId` 派生的 bounded deployment serviceVersion，使日志中的安全 frame/fingerprint 能够关联到实际 candidate，而不是所有部署固定输出同一硬编码版本。
- Skill discovery 等读取用户或第三方文档的 owner 不得把 parser diagnostic message、原文字段名/值或路径写入 operational log/readiness evidence；manifest invalid 只保留 stable reason-code list、count 和 owner-defined safe outcome message。
- local runtime package 的启动提示属于显式 CLI 用户交互边界，不进入 operational logger；`agent-app` 产品路径不得散落 `console.*`。生成的 self-check entrypoint 只能通过该边界输出 allowlisted diagnostic code 与 package-relative evidence ref，不得输出 diagnostic message、配置值、路径、stack 或 credential。
- REMOTE/PaaS entrypoint 必须显式提供 OTLP metric exporter，并按 OTel 标准环境变量读取 `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT`（或 general endpoint fallback）及可选 headers/compression；remote package 只允许安全 resource allowlist。`agent-app` core 不读取这些值、不 import concrete OTLP package，也不在 REMOTE 模式 fallback 到本地文件。exporter 配置缺失或运行失败只使 metrics readiness degraded，不改变业务 ready/result。
- app lifecycle 顺序固定为：trusted config freeze 后先启动 operational infrastructure，再启动 deployment audit gateway 与 metrics SDK/exporter，最后启动 projectors/business producers；shutdown 先停止 producer 并 bounded drain projector，再分别 bounded close audit gateway、force-flush/shutdown metrics 及关闭 `LocalMetricHistoryExporter` file lifecycle，最后写出 shutdown terminal diagnostic 并 bounded flush/close operational writer。每个 finalizer 位于独立 failure-isolation 边界，前一步失败不得跳过后续关闭。
- Agent Dev Workbench 迁移现有 log-evidence consumer：app 从 `agent-log` active ownership 注入当前 active operational path/reader，workbench 不扫描/猜测 family active member；entry source 由解析后的 `surface` 映射。closed source、`.gz` archive、metrics、audit、legacy 和 unknown files均不读取。
- 新增 direct dependencies 冻结为 `pino@10.3.1`、`pino-roll@4.0.0`、`sonic-boom@4.2.1`、`@opentelemetry/sdk-metrics@2.9.0`、`@opentelemetry/resources@2.9.0` 和 `@opentelemetry/exporter-metrics-otlp-proto@0.220.0`。`agent-local-file-roll` 独占 direct `pino-roll`/`sonic-boom`/zlib 文件机制依赖；`agent-log` 直接声明 Pino，`agent-observability` 直接声明 OTel SDK，remote deployment直接声明 OTLP exporter。同步 root/workspace manifests、lockfile、dependency policy 与 `docs/NextAgent 开源组件清单.md`。

## 明确非目标（Non-Goals）

- 不建设远端日志平台、集中检索 UI、SIEM、长期合规归档或不可篡改审计存储。
- 不要求每条 runtime diagnostic 都对应 `RunTimelineEvent`、`ObservabilityObservationEvent` 或 catalog event，也不为了日志新增生命周期事实。
- 不对全仓所有 catch block 或所有内部函数做无差别日志审计；只验证本 change coverage catalog 的 owner 边界和具体禁止的日志旁路。
- 不建立封闭的全局日志 event enum；StructuredLogProjector 只把已批准 observation 的内部 operation/outcome规范化为具体稳定 event，catalog 外 direct diagnostic 仍由各 owner 定义窄 vocabulary。
- 不在本 change 增加 trace-log enrichment、Prometheus endpoint、OTLP Collector 的部署/运维配置、PaaS audit service client 或新的 metric inventory；PaaS exporter 的 endpoint/credential 由 remote deployment owning，不进入 core app config。
- 不把 developer hook trace plugin 的显式 trace artifact、CLI 用户提示或审计文件并入 operational log；这些输出必须由各自 contract owning。
- 不在本 change 为 audit 定义用户可配置 retention、长期合规归档或查询 API；LOCAL audit 只实现独立 fixed size-or-daily rotation、atomic gzip、startup reconciliation 和固定 7 elapsed-day aging。
- 不承诺磁盘字节总量上限或 storage watermark；唯一允许的未满时间保留期提前淘汰是 operational committed gzip archive 超过配置的 `maxArchiveFiles` 时按最旧优先删除。
- 不暴露可配置 time-rotation policy；首版固定 daily safety rotation，不允许用户覆盖 frequency。
- gzip 为固定归档格式，不增加 compression algorithm 或 enable/disable 配置。
- 不承诺 operational log 是完整 durable replay source；canonical persisted timeline 仍是生命周期真相，默认 info log 只提供安全问题定位骨架。
- 不把原始 stack、原始 error message 或第三方/provider frames 写入任何 operational surface，也不新增第二个 crash-log writer。若安全异常证据无法生成，日志只能降级为 type/fingerprint/stage，不能回退输出原始异常。
- 不让 Agent Dev Workbench 读取 closed/archived operational segment，也不扩展成日志全文索引、实时 tail、跨文件扫描或 gzip 浏览器；它只提供当前 active segment 的 owner/run-scoped bounded evidence view。

## Capability 影响（Capabilities）

### 新增 Capability

无新增用户 API。

- `local-file-roll`：新增受限 Node-only technical foundation `agent-local-file-roll`，只复用 rolling-file mechanism；不新增泛化 `agent-utils` 或能够理解业务输出语义的通用 `agent-file-output` package。

### 修改的 Capability

- `runtime-logging`：增加异步 level/sink、Pino implementation boundary、单 operational file、component-scoped direct diagnostic、owner-scoped exception termination、bounded cause-chain projection、size-or-daily rotation、gzip archive、7-day aging 和 non-fatal lifecycle semantics。
- `ts-minimal-agent-kernel`：在 implementation dependency firewall 中增加唯一的 Node-only technical-foundation allowlist，并冻结 accepted request/channel/app/background/process execution root 的异常终止 ownership；不得把 technical-foundation 例外推广为 implementation-to-implementation 依赖，也不得引入跨 owner 全局异常 handler。
- `app-config-schema`：把 operational logging 与安全诊断细节收敛到唯一 `observability.logging` 配置对象，保持既有 app config baseline 完整。
- `structured-logging`：把 observation-derived trajectory 迁移到统一 operational file，并固定 `surface=observation_derived`；明确默认 info 是定位骨架而非完整 replay。
- `local-runtime-package`：增加 package-relative operational/metrics/audit 独立 file families；三者分别提供 daily+size rotation、压缩和 7-day retention evidence，audit 由 gateway owning append/lifecycle 且不进入 SQLite。
- `agent-runtime-metrics` / `otel-observability-adapter`：移除 metric-to-log output，建立 LOCAL rolling NDJSON history exporter 与 REMOTE/PaaS OTLP exporter 的标准 OTel SDK composition；LOCAL 文件族使用 30 MiB/daily OR 轮转和最多 10 个压缩归档。
- `audit-sink`：明确 audit 只通过 `AuditEventWriter` 和 write-only gateway sink 输出；LOCAL 使用独立 audit NDJSON family、30 MiB/daily OR 轮转、最多 10 个压缩归档并固定 7 elapsed-day aging，删除 SQLite audit store/query 和 RuntimeLogger audit mirror。
- `plugin-developer-diagnostic-artifacts`（`FN-10.32 管理插件开发诊断产物`）：保持独立敏感调测产物边界与 3 elapsed-day retention，将文件轮转阈值统一为 30 MiB，并最多保留 10 个压缩归档。
- `gateway-store-provider-ownership`：把 audit 从 `SqliteGatewayStoreBindings` 移到顶层 deployment-selected `GatewayBindings.audit`，保留 SQLite provider 的其它既有 stores。
- `dev-agent-workbench`：只读取 app 注入的当前 active operational segment，按 `surface` 分类，不读取 closed/archive。

## 影响范围（Impact）

- `agent-local-file-roll`：新增安全 async append、pino-roll/SonicBoom destination、rotation、gzip/reconciliation/retention、active identity 和 bounded lifecycle；只导出窄 factory/policy/handle types。
- `agent-log`：新增 Pino operational adapter、console destination、component logger和 operational policy，并 owning 一个独立 local-file-roll handle。
- `agent-log`：其独立 plugin diagnostic artifact writer 同步使用 30 MiB/daily OR 轮转和最多 10 个压缩归档，不与 operational handle 共享状态。
- `agent-common`：保留 structural contract；移出产品 I/O factory；冻结 `AgentError.cause` 的标准异常链语义，不承载全局 handler 或日志去重状态。
- `agent-app`：配置、single-writer composition、component logger 装配、development/package defaults、startup/periodic maintenance、owner-scoped lifecycle termination 和 bounded shutdown flush。
- `agent-observability`：扩展/迁移 `TimelineObservationMapper`，删除 generic runtime bridge、重复 model wrapper、metric log sink 和 logging audit mirror；增加 OTel MeterProvider/PeriodicExportingMetricReader；`LocalMetricHistoryExporter` owning metrics schema/policy/exporter lifecycle和一个独立 local-file-roll handle。
- `agent-platform-gateway-local`：删除 `SqliteAuditStore`、`audit_events` schema/query 和 sqlite binding；新增 write-only file audit gateway，owning audit append/schema/policy/failure mapping和一个独立 local-file-roll handle。
- local/remote deployment entrypoint：LOCAL 注入 file audit gateway 和 metrics rolling-history exporter；REMOTE/PaaS 注入 audit service gateway（另行提供）和 OTLP metric exporter，core app composition 只消费 gateway/exporter abstraction。
- `agent-dev-workbench`：删除旧文件名推断和目录扫描，消费 app 注入的 current active operational source并按 surface classification；不读取 archive。
