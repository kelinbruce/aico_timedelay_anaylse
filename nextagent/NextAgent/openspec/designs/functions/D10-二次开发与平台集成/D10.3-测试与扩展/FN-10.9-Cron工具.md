## 描述

系统提供使用进程本地时区解释、且下一次命中严格保持未来顺序的 Cron 定时任务能力，并通过 Cron task management API 管理当前可信范围内的定时任务。Agent Web 看板使用当前语言下的定时任务页面名称，任务卡片展示创建人并保持单一更多操作菜单。

## 前置条件

- Cron 工具已启用。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| Cron 操作 | 是 | 定时任务定义或触发 |

## 输出

Cron 执行结果，以及任务管理 API 返回的 public task DTO；DTO 可包含来自可信身份上下文的 `createdByName`，旧任务缺失该值时返回 `null`。

## 处理过程

1. 系统按 Cron 定义调度或触发任务。
2. 系统按五段 cron 日历字段查找下一次命中，跳过 DST 缺口，并对 DST 重叠分钟只采用较早 offset 的单次命中。
3. 下一次日历命中必须严格晚于输入起点；candidate 不晚于起点时继续查找下一个不同的日历命中。

## 结果

- 正常：成功计算时产出严格晚于输入起点的唯一下一次日历命中。
- DST 春季缺口中不存在的本地分钟不产生当日命中。
- DST 秋季重叠中同一本地日历分钟只采用较早 offset 一次，不从第二个重复小时回到过去。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| 下一次命中顺序 | `nextRunAt` 严格晚于输入起点 | `cron-tools`：`Cron 本地日历匹配保持未来顺序` |
| DST 春季缺口 | 目标本地分钟不存在时跳过，继续查找后续日历命中 | `cron-tools`：`Cron 本地日历匹配保持未来顺序` |
| DST 秋季重叠 | 同一本地日期和分钟对应两个 offset 时只采用较早 offset；该 instant 不晚于起点时继续查找下一个不同日历命中，不返回较晚 offset 的重复分钟 | `cron-tools`：`Cron 本地日历匹配保持未来顺序` |
| Cron 日历时区 | Node.js 进程本地时区，进程生命周期内固定；未配置任务时区时不从 locale、请求内容或浏览器环境推断 | `cron-tools`：`Cron 本地日历匹配保持未来顺序` |
| Cron Tool 调用指导 | 模型可见描述区分 delay、一次性 cron、周期 cron、list 和 delete；说明五段数字 cron 子集、本地时间与分钟精度、recurring 默认、delay 总量边界和 scope 容量；不把单轮副作用调用限制表述为总任务上限；顶层披露 action/cron/delay/prompt/recurring/id 且 oneOf 继续校验；prompt 只移除调度时间并保留原任务语义 | `cron-tools`：`Cron Tool 调用指导` |
| Cron ACTIVE task 容量 | 每个 trusted `(tenantId, subjectId, agentId)` scope 最多 50 个 `ACTIVE` task；`COMPLETED` 和 `DELETED` 不占用额度；Web create 超限时返回 409 容量契约 | `cron-tools`：`Cron 创建执行 ACTIVE 任务容量限制` |
| 创建者显示名称 | `createdByName` 为 optional string 或 `null`，来源为创建时的 `IdentityContext.displayName`，不参与 Owner Scope、Agent Scope 或权限校验 | `cron-task-management-api`：`Cron task management API persists creator display name` |
