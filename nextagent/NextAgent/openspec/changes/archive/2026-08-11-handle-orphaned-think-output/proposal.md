## Why

思考模型在响应被截断或供应方标签生成异常时，可能只返回孤立的 `</think>`，并把未带 `<think>` 开启标签的推理内容放在该标签之前。当前清洗仅删除闭合标签，导致推理内容可能被解析为推荐问题并展示给用户。对于电信网络诊断场景，这会产生无关、不可直接追问的推荐内容，并暴露本应隐藏的推理文本，因此需要补齐异常输出的安全清洗边界。

## 目标与非目标（Goals / Non-Goals）

**目标：**

- 当模型输出包含孤立 `</think>` 时，系统丢弃该标签及其之前的全部内容，只解析标签之后的推荐问题。
- 当孤立闭合标签之后没有有效问题时，系统返回空推荐列表。
- 保持完整 `<think>...</think>`、未闭合 `<think>`、无思考标签输出及既有推荐解析行为不变。

**非目标：**

- 不改变问题推荐的 prompt、模型选择、超时或深度思考配置。
- 不改变问题推荐 API、返回结构、缓存、前端渲染或运行生命周期。
- 不尝试从孤立闭合标签之前恢复候选问题，因为系统无法可靠区分裸露推理与最终答案。

## What Changes

- 修改问题推荐结果清洗行为：遇到一个或多个孤立 `</think>` 时，以最后一个孤立闭合标签为边界，丢弃该标签及其之前的全部内容。
- 增加缺失 `<think>` 开启标签、大小写混合闭合标签及闭合标签之后无有效问题的行为验证。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

无。

### 修改的 Function

- `FN-1.20 查看推荐问题` → `specs/question-recommendation/spec.md`
  - 功能边界：补充模型推理标签异常时的推荐结果清洗边界，保证只返回孤立闭合标签之后的有效问题。
  - 系统质量属性：安全、可靠性/恢复、可测试性。
  - 映射说明：`question-recommendation` 是 canonical spec，本 change 修改其 `Recommendation Output Cleaning` Requirement。

## 影响范围（Impact）

- 用户在模型返回异常思考标签时不再看到裸露推理文本组成的推荐项。
- 问题推荐结果解析及其 focused tests 受影响；公共 API、配置和部署方式不受影响。
