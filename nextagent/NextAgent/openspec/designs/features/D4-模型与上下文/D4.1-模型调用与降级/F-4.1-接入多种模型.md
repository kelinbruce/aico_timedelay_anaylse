## 用户价值

开发者可以为不同 Agent 和任务配置多种模型，而核心请求、Tool-use、流式输出和安全错误保持同一语义；更换厂商不要求业务层理解厂商私有请求、响应或错误结构。

## 主要用例

- 按稳定 model id 选择已配置模型并执行流式或非流式推理。
- 使用 provider-neutral ToolChoice 控制模型是否可选择 Tool。
- 在兼容模型错误报告停止原因但存在高可信 Tool call 截断证据时，复用统一有界恢复并确保残缺 Tool call 不执行。
- 单个远程模型不可用时安全失败或按已定义策略降级，不污染其他模型。

## 黑盒边界

- 开发者使用稳定的模型标识配置和调用不同来源的模型，不需要处理厂商私有请求或响应格式。
- 流式输出、Tool calls、唯一终态和失败结果具有一致语义。
- 停止原因与输出完整性是独立事实；只有明确超限或预算饱和的结构残缺 Tool call 进入恢复，普通参数错误、策略拦截和 provider error 保持安全失败。
- Tool 选择统一使用 provider-neutral `AUTO | NONE | REQUIRED`；`NONE` 保留 Tool descriptors，selected provider 只负责原生映射。
- 某个需要远程查询信息的模型不可用时，只影响该模型，不使其他有效模型失效。

## 适用质量属性

- 模型接入信息、凭据和厂商原始错误不会暴露给调用方或用户。
- 同一模型的流式与非流式调用返回一致的规范化终态。
- 输出恢复次数有界，恢复成功只交付完整结果，原调用与恢复阶段的残缺 Tool call 均为零执行。
- Prompt、Skill patch、trusted request 和 Hook 不能通过 provider-private 字段建立第二套 Tool-choice authority。
