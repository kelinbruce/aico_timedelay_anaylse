# 修正长期记忆导入导出交互

## Why

长期记忆管理用户目前会遇到四类可观察问题：导入容量提示混合待导入数量和删除引导，不能直接理解个人还可导入多少条；相同文件被永久映射到相同幂等键，用户主动再次导入时无法新增；个人与归档导出使用相同操作和成功提示，归档结果缺少明确语义；删除后通用刷新会把后续页重置到第一页。这些行为降低了批量管理的可理解性，也使界面行为与用户本次操作不一致。

## 目标与非目标

### 目标

- 导入预览明确显示个人导入上限、已有个人记忆总数和当前可导入数。
- 每次选择文件建立新的导入批次；同一未知结果批次的原样重试继续保持精确幂等。
- “我的记忆”和“已归档”提供各自语义明确的导出操作与成功提示，共享记忆库不呈现个人导出操作。
- 删除成功后重新加载当前页；只有当前页因删除变为空页时才回退到最后一个有效页。
- 恢复记忆只读展示对 Unix/Windows 宿主绝对路径的既有脱敏保证。

### 非目标

- 不修改批量新增 Web API、服务端容量裁决、Owner Scope、Agent Scope 或持久化契约。
- 不修改 JSON/CSV 文件格式、字段校验、CSV 注入防护或导出筛选范围。
- 不改变筛选、搜索、切换 Tab 和修改每页条数时回到第一页的既有分页规则。
- 不为相同文件提供跨批次去重；服务端幂等只保护同一提交批次的精确重试。

## What Changes

- 记忆管理页分别读取 ACTIVE 与 ARCHIVED 状态下 `knowledgeSourceType = CONFIGURED` 的总数，计算已有个人设定记忆数，并显示“个人导入记忆限制50条，已有 X 条，可导入 Y 条。”；智能沉淀等非 `CONFIGURED` 记忆不占用该提示中的个人导入容量。
- 文件每次被选择时生成新的客户端批次标识，批次内使用原文件元素序号形成稳定幂等键；未知结果重试复用该批次标识。
- 导出按钮和成功提示按当前个人 Tab 区分；共享记忆库隐藏导出按钮。
- 删除成功后直接重载当前列表页和 Tab 数量，复用既有空页校正逻辑。
- 恢复共享展示 helper 中已被误删的绝对路径匹配与 `[REDACTED_PATH]` 投影。
- 更新中英文资源和前端行为测试。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

无。

### 修改的 Function

- `FN-8.14 导入和导出长期记忆`
  - canonical spec：`long-memory-import-export`
  - 变更边界：修改导入容量反馈、文件批次幂等身份、导入结果提示和个人/归档导出呈现。
  - 系统质量属性：可靠性/恢复、可维护性、可测试性。

`FN-8.15 管理长期记忆` 的删除后页码和路径脱敏修复不改变该 Function 的既有黑盒契约；它们落实 `add-ts-long-memory-manage` 中服务端分页、当前 Tab 重载、空页校正和只读内容保护语义，因此不新增平行 capability delta。

## Feature 影响

无。`F-8.2 长期记忆` 的用户价值、Function 组成和覆盖边界保持不变。

## 影响范围（Impact）

- `frontend/agent-web` 的记忆管理页面、导入转换 helper、中英文资源和相关测试。
- `long-memory-import-export` 的增量规格、设计和任务追踪。
- 不影响后端 package、公共 Web API、`agent-contracts`、宿主模式入口或持久化 owner。
