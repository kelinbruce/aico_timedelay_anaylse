| 主规格 | `lifecycle-hook-execution` |
| 接口 | 系统内部，钩子执行端口 |

## 描述

开发者注册钩子，系统在批准的生命周期阶段执行，钩子可观察、控制或转换处理过程。

## 前置条件

- 钩子已在启动期注册并冻结。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| 钩子阶段 | 是 | 生命周期阶段 |
| 处理上下文 | 是 | 当前处理上下文 |

## 输出

钩子执行结果（成功、超时或失败）。合法结果可同时原样输出 Hook 提供的 `resultSummary` JSON 结果；非成功 invocation 不输出伪造的控制结论或结果对象。Hook 显式提供且满足公开边界的执行后 JSON 结果既作为单次 invocation 事实，也可随同一请求终态被平台集成方取得；省略时不合成结果。成功模型调用的 `AFTER_MODEL_RESULT` 输出包含端到端耗时 `modelE2ELatencyMs`，在出现可识别模型反馈（非空 content、reasoning 或 tool call）时包含首次反馈耗时 `firstContentLatencyMs`，并在 provider 提供 usage 时精确投影已提供的 `inputTokens`、`outputTokens` 和 `totalTokens`；未提供的字段保持缺失。

## 处理过程

1. 系统在批准的生命周期阶段调用已注册钩子。
2. 钩子可观察、控制或转换处理过程。
3. 钩子不得修改运行时状态机、伪造终态或绕过终态提交。
4. 模型调用前钩子只允许替换已批准的消息、工具和推理选项，包括 canonical `toolChoice`；不得修改所选模型、可信调用范围、Agent-owned loop limits 或外部访问权限。
5. planning Hook 不接受 `maxRounds`、`maxCalls`、`maxTurns` 或 `maxToolCallsPerTurn` mutation；model-only/finalizing 在 Hook merge 后仍强制 `toolChoice=NONE`。
6. 系统从 concrete provider invocation 开始测量成功结果和首次可识别反馈，分别投影 `modelE2ELatencyMs` 和 `firstContentLatencyMs`；成功 `ModelFinalResult` 携带 `usage` 时原样投影其已提供的 token 计数字段，未携带时省略。这些诊断事实只供观察，不参与 hook mutation，模型调用失败时不合成 `AFTER_MODEL_RESULT` boundary。
7. 请求路径不扫描钩子。
8. 系统只校验 Hook 结果及可选 `resultSummary` 的 JSON/容量边界；合法对象原样进入 invocation fact，非法结果不应用任何同批 Hook effect，并按 resolved failure mode 继续或失败；timeline fact 保持内部可观察且不默认进入用户对话 stream。
9. 结果后 Hook（`AFTER_CAPABILITY_RESULT`）可取得同次 runtime Capability 调用实际使用的有效输入，并只能在当前 accepted Agent 的已激活 Hook 边界内消费；命中按 runtime Capability 身份与有效输入的精确组合条件决定，不改变 Capability 执行或请求 truth。

## 结果

- 正常：钩子执行完成；成功模型调用的 `AFTER_MODEL_RESULT` 提供非负耗时与精确 usage 诊断事实。
- 超时：安全处理。
- 失败：安全处理；模型调用失败时不合成 `AFTER_MODEL_RESULT` boundary。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| 支持的 Hook 点 | `BEFORE_REQUEST_ACCEPT`、`BEFORE_PLANNING`、`BEFORE_MODEL_INVOKE`、`AFTER_MODEL_RESULT`、`BEFORE_CAPABILITY_INVOKE`、`AFTER_CAPABILITY_RESULT`、`BEFORE_CONTEXT_COMPACT`、`AFTER_CONTEXT_COMPACT`、`BEFORE_AGENT_TERMINAL` | `lifecycle-hook-execution`：`Lifecycle hooks execute only at runtime-owned lifecycle stages` |
| 作用模式 | `OBSERVE`、`TRANSFORM`、`CONTROL` | `lifecycle-hook-execution`：`Hook effects define execution strategy and stable ordering` |
| 同一 Agent 单 Hook 点上限 | 最多 8 个生效 Hook，超限时装配失败，不截断 | `lifecycle-hook-execution`：`Per-stage hook count is bounded by maxHooksPerStage` |
| `AFTER_MODEL_RESULT` 诊断事实 | 成功调用包含 `modelE2ELatencyMs`；出现可识别反馈时包含 `firstContentLatencyMs`；provider 提供 usage 时原样投影已提供字段，未提供保持缺失；诊断字段为 observe-only，不参与 mutation | `lifecycle-hook-execution`：`Stage-specific boundaries and mutations are minimal runtime contracts` |
| Northbound Bash action Hook | `northbound-output-normalization-hook` 仅支持 `AFTER_CAPABILITY_RESULT`，只在 `capabilityId="Bash"` 且有效 `command` 或任一 `args` 字符串包含区分大小写的配置文本时原样返回 `structuredPayload` 作为 `resultSummary` 和 `mutation: { structuredPayload }`；检查字符串由 Agent Hook activation config 显式提供且非空 | `lifecycle-hook-execution`：`Northbound output normalization Hook 仅匹配目标 Bash action`、`Northbound Hook 原样返回已批准的 Bash 结构化结果` |
| Hook resultSummary | Hook 通过 `resultSummary` 直接提供执行后 JSON 结果输出，Runtime 不做二次加工；Hook 明确负责 timeline 安全性；满足公开边界时随请求终态作为 `hookResults` 快照返回 | `lifecycle-hook-execution`：`Hook 结果可以直接携带执行后结果输出`、`Hook 结果输出必须由 Hook 明确负责 timeline 安全性`、`Hook 结果输出必须满足请求终态公开边界` |
| 主动召回 Hook 安全诊断码 | `user-query-memory-recall` Hook 保持既有聚合 `diagnosticCode`，并以固定新增码区分坐标不完整、Assembly/RequestRun/根消息读取失败、L1/L2 失败或取消、上下文准入和幂等跳过；诊断字段不得包含 Query、记忆 ID、记忆正文、Owner Scope 或原始异常 | `lifecycle-hook-execution`：`Every hook invocation produces a timeline-only observability fact` |
