| spec 导航 | `tool-loop` |

## 用户价值

当工具调用失败、模型一次请求过多工具或不断尝试不同方案时，系统既允许模型利用安全错误修正计划，又保证运行最终有界收敛。用户能看到基于已执行事实的最终说明，而不会因局部错误计数被过早终止或因超限调用产生隐藏副作用。

## 主要用例

- Tool 参数或下游调用失败后，把完整安全结果交给下一模型轮选择修正动作。
- 单轮 Tool calls 超限时只执行有序前缀，并告知模型拆分剩余工作。
- 普通轮次耗尽后执行一次无 Tool 权限的 finalizing model turn。
- pause、resume 或 crash recovery 后继续同一轮次预算。

## 黑盒边界

- 重复失败、空 Tool 名称和单轮超限都不建立局部终止阈值。
- 超限 Tool-call 尾部不保存、不执行；已接纳前缀闭合后向模型反馈拆分事实。
- 达到 `maxTurns` 后只允许一次 `toolChoice=NONE` 的 finalizing turn，且任何 Tool call 零执行。
- 取消、正式授权 pending 和 lifecycle block 保持各自控制语义，错误 message 不能伪装控制指令。

## 适用质量属性

- 可靠性：所有 admitted Tool calls 与 results 闭合配对，恢复不重复 finalizing。
- 容量：accepted `maxTurns` 和 `maxToolCallsPerTurn` 是唯一数量边界。
- 安全性：omitted suffix 零保存、零执行；finalizing 中 Tool call 零执行。
- 可解释性：模型获得完整安全失败和明确的超限/收尾事实。
