## 用户价值

开发者可以在不修改内核的情况下提供自定义 Tool 和 Prompt Template，并让它们通过与内置能力相同的启动校验、Agent binding、模型治理和安全调用边界接入主路径。

## 主要用例

- 注册带输入/输出 schema 的自定义 Tool，并绑定到指定 Agent。
- 为不同 Prompt purpose 提供模板和受治理模型选项。
- 在启动期拒绝未知 provider、无效 schema、越权 binding 或冲突 model options。
- 其它 model-facing consumer 通过唯一 `PromptTemplateResolverPort` 复用 Agent-scoped 模板选择与渲染，并显式区分已解析与无匹配模板。

## 黑盒边界

- 自定义工具经定义框架注册，进入能力治理。
- 提示词可以使用稳定模型标识声明兼容条件，但不能自行决定最终模型。
- 提示词中的模型选项必须符合统一调用契约。
- Prompt Template 可声明 canonical `toolChoice: AUTO | NONE | REQUIRED`，但不能声明 named-tool choice、Agent loop limits 或 provider-native alias。
- 公共 resolver 契约不暴露 registry、loader、compiler、template source 或 internal assembler；consumer-owned default content（如 router 默认提示词）不进入 Context Engine。

## 适用质量属性

- 无效工具或提示词定义在进入请求路径前被拒绝。
- 自定义内容遵循与内置能力相同的范围、安全和模型治理规则。
- Prompt Template 渲染中的 `timezone` 与 `currentDate` 表达同一个进程本地日历事实，非 UTC 时区跨日窗口内不出现 UTC 日期与本地时区混用。
