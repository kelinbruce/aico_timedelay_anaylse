# 系统集成验证用例

## TC-SI-112 外部 ESM consumer

**目的**：证明外部项目只依赖 packed package public exports 即可编译和运行。

**前置**：`NEXTAGENT_EXTERNAL_PACKAGES_ROOT` 包含 remote deployment 与 remote gateway artifacts。

**步骤**：

1. 在隔离目录生成最小 ESM TypeScript consumer。
2. 只按 package name 安装/链接 artifacts，不配置源码 alias。
3. 导入外部依赖汇总要求的 public exports，执行 `tsc` 和 Node ESM import。
4. 注入一个 private subpath import 反例。

**断言**：公共导入编译和运行成功；声明文件与 runtime exports 一致；private subpath 无法解析；日志不包含本机绝对路径。

## TC-SI-113 Remote gateway loopback

**目的**：证明 remote gateway public API 能与真实 HTTP 服务组合并保持 schema、trusted scope、Workflow 输入分离、安全和取消语义。

**步骤**：

1. 在随机 loopback 端口启动 sandbox、RAG、Workflow RAG、问题推荐 endpoints。
2. 通过 packed public exports 创建 clients/adapters。
3. 分别执行正常响应、额外/缺失字段、非法 JSON、HTTP failure、延迟后取消。
4. 捕获服务端收到的可信 scope/correlation 字段、Workflow `inputText`/`inputVariables` 和客户端安全结果。

**断言**：正常映射正确；trusted scope/correlation 不被远端覆盖；`inputText` 与 `inputVariables` 保持分离；非法响应 fail closed；取消可观察；原始远端错误、URL、credential 和 canary 不进入公共输出。

## TC-SI-114 SkillHub HTTP/文件系统

**目的**：证明 SkillHub 候选查询、下载、校验和受控落盘形成真实组合。

**步骤**：

1. 启动真实 SkillHub loopback HTTP。
2. 返回最小合法 catalog 和 Skill package。
3. 在解压或 folder normalization 前验证声明 hash，再校验 manifest、entry 和路径。
4. 校验 staged folder 后原子提交 provider-neutral installed fact，再验证 catalog 可见性。
5. 分别注入 traversal entry、hash mismatch、HTTP failure、取消和失败替换。

**断言**：合法包原子可见；非法/失败/取消不发布半成品，失败替换不破坏先前已提交 Skill；candidate 和 external artifacts 不被修改；运行后清理安装根。
