## 背景与问题（Why）

长期记忆管理用户需要批量录入网络事实、领域概念、运维流程和个人工作偏好，并在迁移、核查或备份时按当前筛选导出个人记忆。现有导入在选择 Excel/CSV 文件后立即提交，用户无法在写入前核对或删除条目，也无法确认当前 50 条用户设定记忆容量是否足够。

系统已经提供长期记忆批量新增和分页查询能力。本变更需要在不放宽可信身份、内容安全、容量和幂等约束的前提下，为用户提供可检查、可恢复的 JSON 批量导入流程，并提供与当前个人记忆筛选一致的安全 CSV 导出。

## 目标结果

- 用户可以下载包含四类记忆说明和示例的中英文 JSON 模板，并直接编辑后上传。
- 系统在写入前完整校验文件，展示待导入内容、容量信息和明确错误；用户可以删除条目、重新选择文件或取消。
- 用户确认后，系统以稳定幂等身份批量处理当前保留条目，并准确区分成功处理、部分失败、明确拒绝和结果未知。
- 用户可以按当前语言导出“我的记忆”或“已归档”Tab 的完整筛选结果，且任一分页失败时不会得到不完整文件或可执行的表格公式。

## 变更范围（What Changes）

- 导入仅接受不超过 5 MiB、包含 1 至 50 条记忆的 UTF-8 `.json` 文件；移除 `.xlsx`、`.xls`、`.csv` 导入。
- 下载模板使用 `_instructions + memories` 结构，按当前界面语言提供 `FACTUAL`、`CONCEPTUAL`、`PROCEDURAL`、`USER_CHARACTERISTICS` 的解释和四条电信运维示例，同时兼容既有纯数组 JSON。
- 每个元素使用 `briefIndex`、`content`，可选配置 `memoryType`、`labels`、`confidence`；空可选字段使用手工新增同形默认值。文件不得指定身份、Agent、实例、来源、状态或其它权威字段。
- 合法文件先进入 transient preview；用户可以删除条目，清空后可以在当前弹框重新选择同名 JSON 文件，确认前不产生写请求。
- 预览和首次确认前读取 ACTIVE 与 ARCHIVED 的 `CONFIGURED` 总数。未超限时明确显示导入后还可新增数量；超限时只显示一条包含超出数量的警告并禁止确认。服务端 50 条容量门禁仍为最终权威。
- 确认后只提交一次当前 1 至 50 条记录。幂等键由原文件字节、JSON 契约版本和原元素序号生成；未知结果保留原集合供精确重试。
- 导出继续生成 UTF-8 BOM CSV，表头、类型、来源和状态跟随当前界面语言，包含记忆来源与更新时间，并对半角/全角公式前缀、前导控制字符及其组合执行 CSV 注入防护；不声明导出文件可以直接回导。

## 非目标

- 不新增服务端文件上传、导出或容量预检 API。
- 不修改长期记忆 API v2、Gateway contract、可信 Owner Scope、Agent Scope、内容安全护栏或服务端容量规则。
- 不导入共享记忆、原记忆 ID、状态、来源、版本、访问统计或服务端时间。
- 不增加后台任务、自动重试、批量删除、批量归档或容量上限配置。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

- `FN-8.14 导入和导出长期记忆`
  - 对应 spec：`long-memory-import-export`
  - 变化边界：定义 JSON 模板下载、文件校验、预览确认、容量提示、单批幂等提交、结果恢复和个人记忆筛选 CSV 导出。
  - 系统质量属性：本变更不新增独立的系统质量属性 Requirement；安全、容量和恢复机制作为上述功能行为的约束和实现关注点验证。

### 修改 Function

无。

## Feature 影响

- **修改** `F-8.2 长期记忆`：Function 组成增加 `FN-8.14 导入和导出长期记忆`，用户可依赖的长期记忆管理边界增加批量迁移和备份能力；既有 `FN-8.2`、`FN-8.3` 行为不变。

## 影响范围（Impact）

- 前端：长期记忆文件转换、管理页面、样式、中英文资源和相关测试。
- Web API：继续消费既有批量新增和分页列表接口，不增加或修改 wire contract。
- 后端：继续执行可信 scope 注入、内容安全、ACTIVE/ARCHIVED 合计 50 条 `CONFIGURED` 容量裁决和持久化幂等。
- 兼容性：导入格式从 Excel/CSV 收窄为 JSON；导出仍为 CSV，但范围改为当前个人记忆 Tab 的筛选结果并增加本地化列。
