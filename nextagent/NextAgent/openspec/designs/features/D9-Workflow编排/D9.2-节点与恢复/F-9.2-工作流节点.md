## 用户价值

Recipe 作者可以组合网关、并行网关、能力、交互、知识和模型六类节点，表达顺序、分支、并发、外部动作、用户确认、检索和推理，而每类节点仍共享一致的 scope、取消、失败和安全输出边界。

## 主要用例

- 用 gateway/parallel-gateway 表达条件路由、并发分支和 join policy。
- 用 Capability 节点调用 Tool/Skill/Agent，并按显式 exception 处理最终失败。
- 用 interaction 节点暂停等待用户输入，用 knowledge/LLM 节点完成检索和推理。
- DATA_ANALYSIS 模型节点在受治理路径中调用 Python 子能力。

## 黑盒边界

- 节点执行经运行时拥有的状态接口与运行时协作。
- 节点不拥有请求生命周期。
- Capability nodes 与 `DATA_ANALYSIS` Python 子调用只消费统一边界的最终结果；节点声明的 retry 只下沉到该边界内部，不得重放最终失败。
- parallel-gateway 首版只保证单实例内存态 fork/join，不承诺跨实例 barrier 或 durable branch recovery。
- 节点 output、exception、waiting 和 cancellation 使用 closed contract，不以任意内部 marker 扩大公共状态词汇。

## 适用质量属性

- 组合性：六类节点可通过统一 Recipe/FlowGraph contract 组合。
- 隔离性：Capability、model、knowledge 和 interaction 各经正式 owner boundary。
- 可靠性：retry、exception、waiting 与取消互不混淆，最终失败不重复执行节点。
- 可测试性：每类节点具备独立黑盒 handler tests，并由 Workflow integration tests 验证组合路径。
