## Why

推荐问题的现有 system prompt 从助手视角生成“可推荐给用户的问题”，并把上下文不足时的输出目标定义为“具体的澄清问题”。这容易产生“是否需要”“建议您”等助手口吻，也弱化了用户得到当前回答后最自然的下一步追问，导致推荐结果与真实用户后续输入不一致。

现在处理该问题，是因为下一步问题推荐的价值取决于问题是否站在用户视角预测真实追问，而不是向用户提供引导性提示。

## 目标与非目标（Goals / Non-Goals）

**目标：**

- 推荐生成的 system prompt MUST 将任务定义为“用户追问预测助手”，基于本轮对话上下文预测用户在得到当前回答后最可能提出的 3 个追问。
- 问题选择 MUST 优先预测当前任务最自然的下一步追问，其次预测确认结果、追问原因或补充条件的追问。
- 上下文不足时，Prompt MUST 要求继续预测用户可能提出的追问，而不是返回空内容。
- 输出问题 MUST 使用用户口吻和当前会话的语言术语，每条问题只表达一个意图。
- Prompt MUST 禁止助手引导口吻，包括“是否需要”“是否想要”“建议您”。
- 当产品能力范围非空时，追加的选择规则 MUST 指示推荐问题与产品能力范围相关；该规则同时提及追问偏好，但本 change 不新增追问偏好数据源。

**非目标：**

- 不修改推荐问题触发、缓存、REST API、模型调用、输出解析或空结果降级行为。
- 不新增 prompt 配置项、外部 prompt 文件或新的 public contract。
- 不新增“追问偏好”的服务端数据源、user message 段或解析行为。
- 不修改产品能力范围与 Skill 上下文的既有解析和填槽行为。

## What Changes

- 修改 `FN-1.20 查看推荐问题` 的推荐生成 system prompt：
  - 任务从生成可点击的后续问题改为站在用户视角预测 3 个追问。
  - 问题选择规则改为优先预测当前任务最自然的下一步追问，其次预测确认结果、追问原因或补充条件的追问。
  - 上下文不足时改为预测用户可能提出的追问。
  - 增加用户口吻、单一意图、禁止助手口吻和不编造事实的约束。
- 修改产品能力范围非空时追加的选择规则：
  - 规则编号从 6 调整为 7。
  - 规则内容改为当提供产品能力范围和追问偏好时，推荐问题应与之相关，并优先参考追问偏好中同类意图的推荐方向。
  - 本次不新增追问偏好数据源，也不会在 user message 中发送追问偏好段。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

无。

### 修改的 Function

- `FN-1.20 查看推荐问题` → canonical spec `question-recommendation`
  - 功能边界：推荐生成 system prompt 的任务定位、问题选择策略、上下文不足策略、口吻约束和产品能力范围附加规则发生变化。
  - 系统质量属性：可测试性。
  - 映射说明：canonical spec。

## 影响范围（Impact）

- **前端用户**：完成回答后看到的推荐问题更接近用户自然追问，减少助手引导式表述。
- **Agent 开发者**：无 public API 或配置变化。
- **运维人员**：无部署、配置或数据迁移变化。
- **代码**：`packages/agent-session/src/services/suggested-question-service.ts` 与既有推荐问题服务测试；不改长期 stable spec，归档前按 design 刷新计划同步。
