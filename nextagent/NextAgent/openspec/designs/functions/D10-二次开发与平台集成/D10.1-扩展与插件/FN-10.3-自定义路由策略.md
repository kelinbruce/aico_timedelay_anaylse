# FN-10.3 自定义路由策略

> 能力域 D10 二次开发与平台集成 · 子域 [D10.1 扩展与插件](.) · 返回 [功能树](../../index.md)

| 项 | 值 |
|---|---|
| 覆盖特性 | [F-10.3](../../../features/D10-二次开发与平台集成/D10.1-扩展与插件/F-10.3-自定义路由策略.md) |
| 主规格 | `agent-routing-core` |
| 接口 | 系统内部，路由策略扩展点；官方插件 `pluginId=agent-router-plugin`、`policyId=agent-router-plugin.auto-routing` |

## 描述

开发者自定义路由策略，经受控契约接入，依赖不可用时安全失败。开发者可激活并配置系统提供的模型驱动路由插件，使系统按目标类型限制与 optional RAG 预筛，在当前 Agent 显式绑定且当前请求可用的 Skill、Workflow 中选择一个受治理处理路径，依赖失败时安全拒绝。

## 前置条件

- 路由策略已注册；使用官方 router plugin 时，插件已加载并被目标 Agent 显式激活。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| 请求和装配事实 | 是 | 路由决策输入，包括 accepted user input、当前 Agent policy config、enabled Skill/Workflow bindings、当前请求治理可用性、optional governed RAG result 和当前 Agent 初始模型选择结果 |

scope 与候选不得由客户端、模型或 RAG 结果扩大。

## 输出

路由决策结果。

## 处理过程

1. 开发者通过受控契约提供路由策略。
2. 系统在请求受理后调用策略决策。
3. 模型驱动插件先按配置限制目标类型并形成 binding 与治理可用能力的交集；启用且需要 RAG 预筛时把候选缩小到配置上限。
4. effective final candidate set 非空时使用当前 Agent 初始模型做一次无 Tool 直接语义选择，无可辩护的唯一匹配时返回 no-match，并校验结果只指向受控候选。
5. 选中目标进入既有受治理路径，no-match 进入模型驱动循环，依赖失败安全拒绝。

## 结果

- 正常：选中一个 effective final candidate 中的 bound Skill、选中一个 bound Workflow 或 no-match。
- 依赖不可用、RAG/模型/治理/取消或输出校验失败：返回安全拒绝，且不改选其它能力。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| 模型路由候选范围 | `SKILL`、`WORKFLOW`、`SKILL_OR_WORKFLOW` 三种配置范围内，当前 Agent enabled 显式 bindings 与当前请求治理可用能力的交集；默认 `SKILL_OR_WORKFLOW` | `agent-routing-core`：`agent-router-plugin按配置限制目标类型`、`agent-router-plugin仅选择当前Agent绑定的可用能力` |
| 模型路由结果集合 | 一个 bound Skill、一个 bound Workflow、no-match 或安全拒绝 | `agent-routing-core`：`agent-router-plugin仅选择当前Agent绑定的可用能力`、`agent-router-plugin依赖失败时安全拒绝` |
| 每次插件路由的模型调用 | 候选非空时使用当前 Agent 初始模型执行恰好一次无 Tool 调用；候选为空时不调用模型 | `agent-routing-core`：`agent-router-plugin使用当前Agent初始模型执行一次受控选择` |
| RAG 预筛上限 | `ragPrefilter` 为 optional；未配置时跳过 RAG 预筛，配置后 `topK` 为每次预筛最多保留的候选数，范围 1–10，默认 5 | `agent-routing-core`：`agent-router-plugin可通过受治理RAG Tool预筛候选` |
