## Why

运维人员目前无法仅凭运行指标完整回答模型调用量、首字符时延、增量 token 速率、单次 token 分布、请求排队与并发、对话级 token 用量以及异常类型等容量和性能问题。部分指标虽已存在，但调用计数口径可能把开始与结束重复计数，token 只保留累计值而无法得到单次平均值和最大值，排队、并发和流控缺少可查询事实，导致容量评估、性能回归定位和电信级运行保障依赖日志拼接或推断。

这些缺口会让相同运行事实得到不同统计结论，也无法以黑盒方式验证指标是否完整，因此需要在同一运行指标 Function 内统一测量边界、聚合语义和缺失数据处理。

### 术语

- **模型调用**：一次模型调用从开始到成功或失败终止的完整生命周期；请求次数只在该生命周期终止时计一次。
- **对话**：一次已接受并到达终态的 request run，即一个用户轮次，不等同于 session 数量。
- **界面首字响应时间**：从 request run 被接受到首个用户可见内容或思考进入可供 Web 界面投影的 canonical stream 的时长；不包含 canonical stream 之后的网络传输和终端设备绘制耗时。
- **模型增量 token 速率**：模型终态提供的 `outputTokens` 除以首个可见模型内容到模型调用终止之间的秒数，表示该次调用可见生成阶段的平均输出 token 速率，不表示单个 stream chunk 的瞬时速率。
- **并发采样值**：request run 每次进入或离开执行态后，当前 app runtime 实例中处于执行态的 request run 数量；它不是多 runtime 实例的集群全局并发值。

## 目标与非目标（Goals / Non-Goals）

**目标：**

- 运维人员能够从指标聚合结果获得模型调用次数，以及模型首字符响应时间、增量 token 速率、输入/输出 token 数和总耗时的平均值与最大值，并获得输入/输出 token 总数。
- 运维人员能够从指标聚合结果获得对话次数，以及界面首字响应时间、对话总耗时、排队时间、并发采样值和对话级输入/输出 token 数的平均值与最大值，并获得对话级输出 token 总数。
- 运维人员能够分别查询异常终止、超时和流控次数，且每个指标事实有唯一、可验证的计数边界。
- 相同模型调用、对话或异常事实只计一次；缺失 usage 或时序数据时省略对应样本，不补零、不估算。
- 新指标继续满足低基数、安全、非阻塞和 local/remote 输出语义一致的质量保证。

**非目标：**

- 不测量 canonical stream 之后的公网、浏览器调度、DOM 提交或设备像素绘制时延。
- 不新增按 `modelId`、provider、tenant、subject、session、request、run、path 或其他高基数字段分组的指标。
- 不改变 request lifecycle、模型调用、调度容量、失败处置、重试或流控策略；本 change 只补齐这些既有运行事实的观测结果。
- 不根据缺失的 usage、首字符时间或错误原因推算 token、速率、时延或异常类别。

## What Changes

- 修改模型调用指标，使调用次数只按成功或失败终态计数，并补充可导出单次平均值、最大值和累计值的模型 token 分布指标，以及模型增量 token 速率指标。
- 修改对话指标，以一次终态 request run 作为对话计数边界；补充排队时间、并发采样值和对话级输入/输出 token 分布，并保持既有界面首字响应时间与总耗时口径可聚合。
- 新增异常观测指标：异常终止按失败 request run 终态计数，超时按具有权威 timeout 终态的运行操作计数，流控按具有权威 rate-limit 结果的模型调用计数。
- 修改非秒数直方图的聚合契约，使 token 数、token 速率和并发采样值分别使用与量纲匹配的固定显式桶，并保留 `count`、`sum`、`min`、`max` 聚合结果。

## Feature 影响（Features）

### 修改的 Feature

- `F-7.4 运行指标`：运维人员可依赖的容量与性能监控范围扩展到模型与对话的 token 分布、生成速率、排队、并发和异常分类，同时保持安全低基数边界。

## Function 影响（OpenSpec Capabilities）

### 新增 Function

无。

### 修改的 Function

- `FN-7.5 采集指标` → `specs/agent-runtime-metrics/spec.md`
  - 功能边界：补齐模型、对话、排队、并发和异常运行事实的确定性采集与聚合口径，并修正模型调用的唯一终态计数边界。
  - 系统质量属性：性能/容量、安全、可靠性/恢复、可测试性。
  - 映射说明：`agent-runtime-metrics` 是 canonical spec；本 change 不触及 legacy spec。

## 影响范围（Impact）

- 运维查询和告警可直接使用累计 counter 与 histogram 的 `count`、`sum`、`min`、`max`，无需从运行日志重建统计。
- local 指标历史与 remote OTLP 输出将出现新增指标序列；既有指标名称和 exporter 选择方式保持不变。
- 指标采集、聚合桶、运行时生命周期观测和相关 contract/architecture 测试会受到影响；公共 Web API、stream schema 和配置不变。
