1. 执行摘要

两套系统的目标不同：DeepSeek Harness 优先运行时组合和模型执行效率，NextAgent 优先可信作用域、生命周期一致性和电信级治理。

5 阶段建议的唯一实施路线

200+ packagesDeepSeek Harness 高颗粒 workspace 规模

DeepSeek Harness 更突出

  • Provider overflow 后压缩自恢复
  • 逐 Tool 调用并发安全分类
  • 有界 rolling pool 和 exclusive barrier
  • 最终模型请求可从 durable log 验证

NextAgent 更突出

  • Agent Scope + Owner Scope
  • same-session lane 和 terminal commit
  • 压缩 CAS、幂等和 composite transaction
  • OpenSpec、contract 和架构治理
推荐目标态：稳定可信内核 + 有界且冲突感知的 Tool 并行 + Provider overflow 压缩恢复 + 最终模型请求证据 + 确定性 Workflow 归并。

3. 架构与职责边界

DeepSeek Harness

Profile / Bundle / Patch ↓ Cordis Plugin Tree ↓ Session → Agent Loop → LLM / Tools ↓ Projection / Capability seams

插件、服务、事件和可逆 effect 构成扩展主轴。动态性强，但需要更严格地治理顺序、短路和卸载。

NextAgent

Channel / Trusted Identity ↓ Request Runtime / Session Lane ↓ Agent Core / Context / Model ↓ Capability / Gateway / Terminal

每个关键事实具有唯一 owner，适合多租户、恢复、幂等和安全审计。

不可照搬：Runtime、identity、terminal commit、Gateway transaction、Capability authorization 和 sandbox boundary 不应插件化。

4. 上下文动态压缩

NextAgent 已有成熟压缩；真正需要补的是 Provider 确认窗口溢出后的恢复闭环。

NextAgent 当前路径

History selection → Micro-compact → Large-content guard → Budget evaluation → Summary generation → CAS composite commit
  • 原始 Message 保留
  • Owner/Agent scope 完整
  • summary 与 ActiveContext 原子替换
  • 同一 run 防级联压缩

DeepSeek 增量价值

Provider overflow → Force pruning / compaction → Verify durable surface progress → Retry original model route once
  • 不依赖估算完全准确
  • Tool call/result 边界保护
  • 无进展不重试
  • 取消始终优先

推荐 change：harden-context-overflow-compaction-recovery

Normalized CONTEXT_WINDOW_EXCEEDED → Context Engine force compact → sourceVersion / targetVersion / reductionEvidence → targetVersion > sourceVersion ? retry once : preserve original failure
禁止按 provider 原始错误文本猜测 overflow；禁止重新选择默认 Agent、默认模型或新 assembly。

5. 上下文拼接与最终模型请求

DeepSeek 的优势

  • sections、contexts、tools、variables 显式有序
  • scoped contribution 可覆盖 global
  • 动态上下文进入 durable surface
  • 模型调用前校验 messages/system/tools/options

NextAgent 的优势

  • ActiveContext 是历史选择权威
  • Capability 来自 run-bound assembly
  • Prompt、Memory、Attachment 各有明确 owner
  • 身份和 provider secret 不进入 prompt authoring

推荐 change：add-final-model-request-evidence

不直接持久化完整原始请求，而是保存 message refs、ActiveContext version、Prompt ref、Tool schema digest、Attachment disclosure digest、Hook result digest 和最终 request digests。

目标是获得 DeepSeek 的“请求可证明性”，同时保留 NextAgent 的数据分层、脱敏规则和可信作用域。

7. 异常、取消和恢复

DeepSeek 更细

  • durable compaction bracket
  • scheduler failure 与业务失败分离
  • started work drain
  • caller cancel 与本地 timeout 分离
  • unstarted Tool synthetic result

NextAgent 更完整

  • SafeError code/category/retryable
  • Capability 统一 timeout/retry
  • terminal commit 与 checkpoint
  • 幂等与恢复
  • terminal pending 阻塞 Session lane

建议的异常优先级

Caller cancellation > Runtime cancel / supersede > Local timeout > Policy / hook interruption > Capability safe business failure > Scheduler / internal failure
合并 signal 后不能只检查最终 signal；应优先识别上层原始取消来源，避免把用户取消误判为内部 timeout。

8. 并行执行

跨请求

NextAgent 的 same-session lane、priority、全局并发和 terminal pending 已明显适合生产系统，应保持不变。

单轮 Tool

保留 ordered finalizer，增加 per-call disposition、rolling pool、barrier 和 unstarted 闭合。

Workflow

已有 fork/join；建议让每个 branch 使用私有 nodeResults，再按声明顺序归并。

Workflow 推荐路径

Branch-local variables + nodeResults → allSettled under maxParallelBranches → merge by branchNodeIds declaration order → apply explicit duplicate-key policy → commit one join result

10. 唯一实施路线

顺序体现依赖关系：先稳定 Tool 调度基础，再补窗口恢复和请求证据，最后收敛 Workflow 与开发者诊断。

1

Tool 调度收敛

harden-tool-call-concurrency-scheduling：execution disposition、maxParallelToolCalls、rolling pool、barrier、ordered finalization、取消闭合。

2

上下文溢出恢复

harden-context-overflow-compaction-recovery：provider overflow、强制压缩、版本进展证据、原路由最多一次重试。

3

最终模型请求证据

add-final-model-request-evidence：request digest、Hook evidence、Tool schema digest、调用前 invariant。

4

Workflow 并行确定性

harden-workflow-fork-join-determinism：branch-local results、声明顺序归并、分支并发上限。

5

配置解释能力

add-effective-agent-assembly-explain：本地只读解释配置来源、模型、Capability、Prompt 和 sandbox 决策。

11. 建议验收指标

目标验收结果
Tool 调度安全排他调用与兄弟调用不重叠；未知 Capability 默认排他
Tool 调度容量实际同时执行数量不超过 `maxParallelToolCalls`
Tool 顺序任意完成顺序下，持久结果和模型上下文仍按模型调用顺序
取消闭合started 调用 drain；unstarted 调用产生 canonical skipped/canceled result
Overflow 恢复仅 provider-confirmed overflow 且 ActiveContext version 前进时重试
Overflow 有界每次实际 model invocation 最多恢复一次
Scope 安全全程保持原 Owner/Agent Scope、assemblyRef 和 model route
请求可证明实际 provider request digest 与 evidence 一致
Workflow 确定性分支完成顺序不改变最终 node result 顺序和变量归并

12. 最终结论

NextAgent 已具备更适合电信生产系统的可信边界、请求生命周期、持久化事务和恢复能力。下一步应提高现有内核的执行效率和可证明性，而不是扩大动态插件范围。

Stable Trusted Kernel + Bounded Conflict-aware Tool Parallelism + Provider Overflow Compaction Recovery + Final Model Request Evidence + Deterministic Workflow Merge + Explainable Agent Assembly
若只做一个 change：优先 harden-tool-call-concurrency-scheduling。
若连续推进两个：Tool 调度收敛 → Provider overflow 压缩恢复。
