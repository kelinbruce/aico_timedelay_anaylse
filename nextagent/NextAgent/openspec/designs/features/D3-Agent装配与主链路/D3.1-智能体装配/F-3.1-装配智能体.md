## 用户价值

开发者通过配置文件装配智能体，绑定模型、提示词、能力、策略和运行参数，无需修改内核代码即可构建面向不同领域的专属智能体。多个产品 agent 可在同一进程中并存服务，用户通过请求 header 指定 agentId 与不同 agent 对话；进程启动后 pub 新增的 agent 无需重启即可被发现和使用。

## 主要用例

- 为不同电信领域任务定义独立 Agent package、模型 profile、Prompt 和 Capability binding。
- 启动期编译并校验配置，在请求到达前发现无效引用或越权组合。
- 通过 `maxTurns` 和 `maxToolCallsPerTurn` 为每个 Agent 建立确定的循环容量边界。
- 配置 `readDirectories`/`writeDirectories` 文件目录策略；编译为 root-qualified canonical directories（`.` 为 `workspace`，普通目录为 `workspace/<directory>`，已知 root 保持前缀），运行时稳定执行同一授权语义。
- 运行时通过 header `x-agent-id` 选择 agent 创建 session，session 绑定后自动路由到对应 agent 资源。
- pub 新增 agent 目录后 registry 自动发现，无需重启进程。

## 黑盒边界

- 配置在启动期编译为运行时装配，请求路径不重新解析配置。
- runtime settings 只使用 `maxTurns` 与 `maxToolCallsPerTurn` 两个 canonical limits；非法显式值在启动期拒绝，request 和模型不能覆盖。
- 智能体归属在会话绑定和请求受理时固化，不可被请求体覆盖。
- Agent Selection Policy 在 createSession 链中同步执行，经格式校验和 assemblyRegistry 校验后绑定 agentId 到 session；session 绑定后不再从 header 取。
- registry 运行时动态刷新检测 `agentsRoot` 顶层 agent 目录变化并重建 assembly 集合；已 accepted request 的 frozen assembly 不受重建影响。
- 装配后的执行链路：上下文装配 → 提示词装配 → 模型调用 → 能力调用 → 工具循环。
- 文件目录策略编译区分缺省与显式空集合语义，装配结果不可由请求扩大。

## 适用质量属性

- 可维护性：请求路径只消费 runtime-ready assembly，不重复解释 authoring 配置；registry 动态刷新无需重启即可发现新 agent。
- 安全性：模型、能力和 scope 授权在启动/受理边界固化；agent scope 信任链闭合（header -> policy 校验 -> assembly 校验 -> session 绑定）。
- 容量：loop 与单轮 Tool-call 上限显式、可验证且不能由请求覆盖。
- 可诊断性：无效配置在 startup ready gate 前以安全证据失败；agent 选择结果通过 structured log 记录。
