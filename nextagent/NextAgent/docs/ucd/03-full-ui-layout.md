## 2. 区域拆解与标注

把全屏总览的每个区域放大，标注其内部结构与契约来源。

### 2.1 侧边栏 header（local/left 布局）

local 和 immersive-left 布局下，产品标识在侧边栏 54px header 中，导航按钮在 header 下方。

```
┌────────────┐
│ 🛰️ NextAgent│  ← 54px header，品牌图标 + 产品名称（来源：aicoConfig.name）
├────────────┤
│ [💬 新会话] │  ← 导航按钮（紧贴 header 下方）
│ [🔍 搜索]   │
│ [⭐ 收藏]   │
│ [⚙️ 操作]   │  ← OperatorsArea（配置驱动）
│ [⏰ 定时任务]│  ← Cron 管理入口（agent 级，跨会话，带 badge）
│            │
│ 最近会话    │  ← 会话列表标签
│ ▸ 会话 A   │
│ ●会话 C    │
│ ▸ 会话 D   │
│            │
│ [⚙ 设置]   │  ← 本地控件（仅 local 模式 showLocalControls=true）
│ [❓ 帮助]   │
│ [退出]     │
└────────────┘
```

- **品牌标识**：侧边栏顶部 54px header（品牌图标 + 产品名称，来源：`aicoConfig.name`，默认 "NextAgent"；折叠时仅显示图标）。
- **导航按钮**：紧贴 header 下方——新会话、搜索、收藏、操作区、定时任务（Cron 管理入口，agent 级跨会话，带 badge）；immersive-right 布局下这些按钮移至顶部栏右侧。
- **会话列表**：导航按钮下方，带"最近会话"标签；可切换为收藏列表。
- **本地控件**：侧边栏底部——设置、帮助、退出（仅 local 模式 `showLocalControls=true` 时显示；immersive-left 布局隐藏）。
- 侧边栏不随 turn 状态变化（run 状态指示在对话区内呈现）。

### 2.2 顶部栏（immersive-right 布局）

当 `operatorPosition === "RIGHT"` 时，使用全宽顶部栏替代侧边栏。以下为 immersive-right 布局专用区域。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  🛰️ NextAgent          [➕] [🕐] [⭐] [🔍] [⚙️ 操作] [⏰]                │
└──────────────────────────────────────────────────────────────────────────┘
```

- **产品标识**：左侧品牌区（品牌图标 + 产品名称，来源：`aicoConfig.name`，默认 "NextAgent"）。
- **导航入口**：右侧导航按钮组——新会话（➕）、最近会话（🕐）、收藏（⭐）、搜索（🔍）、定时任务（⏰，Cron 管理入口，agent 级跨会话）；点击触发面板覆盖或弹窗，非侧边栏导航。
- **操作区（OperatorsArea）**：配置驱动的操作按钮（来源：`aicoConfig.operators`），可包含 MODAL/PANEL 类型操作；按 position（OUTER/INNER）分组，INNER 操作折叠到"更多"菜单。
- 顶部栏不随 turn 状态变化（run 状态指示在对话区内呈现，不在顶部栏）。
- immersive-right 布局下无侧边栏，会话列表通过"最近会话"（🕐）和"收藏"（⭐）按钮以面板覆盖形式打开。

### 2.3 会话列表（左侧栏）

```
┌────────────┐
│ 会话列表   │
│            │
│ ▸ 会话 A   │  ← 历史会话（无 active run），▸ 表示折叠预览
│ ▸ 会话 B   │
│ ●会话 C    │  ← 当前选中会话，● 标记有 active run 或刚完成
│ ▸ 会话 D   │
│ ▸ 会话 E   │

```

- **▸**：历史会话（无 active run），点击加载历史消息。
- **●**：live 会话（有 active run）或当前选中会话，高亮显示。
- 每项展示：会话标题、最后活动时间、preview marker。
- 组件规范见 `05-component-specs/session-list-item.md`。

```
│  │  | 设备 | 角色 | 状态 | CPU | 内存 | 丢包率 |                     │ │
│  │  | Core-SW-01 | 核心交换 | 正常 | 42% | 58% | 0.01% |            │ │
│  └────────────────────────────────────────────────────────────────────┘ │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

**turn 内部结构的关键规则**：

| 元素 | 渲染位置 | 格式 | 契约来源 |
|---|---|---|---|
| USER 消息气泡 | turn 顶部 | 用户原文 + 附件指示 | `message-bubble.md` |
| 过程面板 | USER 气泡与 ASSISTANT 气泡之间 | 可折叠容器 | `conversation-ui-state.md` 第 1 节 |
| 💭 思考条目 | 过程面板内 | PLAIN_TEXT（非 markdown） | `LLM_THINKING_DELTA` |
| 🔧 能力卡片 | 过程面板内 | running → 结果态 | `capability-card.md` |
| ⚠️ 降级提示 | 过程面板内 | 独立条目 | `degradation-notice.md` |
| 📦 压缩通知 | 过程面板内 | 独立条目 | `CONTEXT_COMPACTED` |
| ASSISTANT 消息气泡 | turn 底部 | MARKDOWN 解析渲染 | `LLM_CONTENT_DELTA` |

> ⚠️ **思考与内容严格二分**：💭 思考条目在过程面板内（PLAIN_TEXT），🤖 助手回复在消息气泡内（MARKDOWN）。两者不交叉。来源：`conversation-ui-state.md` 第 1 节、场景 7。

### 2.8 当前会话预览轨道（已实现）

预览轨道位于会话列表与主对话区之间，用于长会话内的快速扫描和定位，不是 session list item 的扩展。

```
┌─ 会话列表 ─┬─ 预览轨道 ─┬─ 当前会话对话区 ─────────────────────┐
│ 会话 A     │ ● Turn 1   │  Turn 118                            │
│ 会话 B     │ │           │  用户：继续检查核心链路              │
│ 会话 C     │ ● Turn 80  │  执行详情 · 已完成                   │
│            │ │           │  助手：……                            │
│            │ ◉ Turn 118 │                                      │
└────────────┴─────────────┴──────────────────────────────────────┘
```

- Hover marker：显示有界摘要，不触发 process Event 请求。
- Click marker：必要时加载目标 Message 页并定位；目标进入可视区后提升其 Event history 优先级。
- 快速滚动和 scrollbar drag：不为每一个中间位置触发请求。
- 数据与 DOM 均窗口化，适用于 200～300 轮长会话。
- 组件规范见 `05-component-specs/conversation-preview-rail.md`。

Sidebar 内嵌摘要或 session hover card 仍是未交付目标，必须另行定义批量数据与容量边界，不能复用本轨道形成 N+1 请求。

## 3. 单 turn 交互时序全屏演变

一个完整 turn 的 4 个关键阶段，每个阶段展示**整个 UI**（不只对话区）的状态变化，体现区域联动。

### 阶段 3.1：用户刚发送消息（run 受理，思考开始）

```
┌────────────┬─────────────────────────────────────────────────────────────┐
│ ▸ 会话 A   │  ┌─ Turn 1 ─────────────────────────────────────────────┐  │
│ ▸ 会话 B   │  │  > 🧑 用户                                           │  │
│ ●会话 C    │  │  > 网络健康诊断                                       │  │
│ ▸ 会话 D   │  │                                                       │  │
│ ▸ 会话 E   │  │  > 🤖 助手 · 已受理 ⏳                               │  │
│            │  │  ┌─ 📋 过程面板（auto-expanded ▼）─────────────────┐ │  │
│            │  │  │ 💭 思考 #1 · ⏳ 进行中                             │ │  │
│            │  │  │  阶段一：建立可见执行计划……（持续增长）          │ │  │
│            │  │  └──────────────────────────────────────────────────┘ │  │
│            │  └───────────────────────────────────────────────────────┘  │
│            │  ┌─ Composer ──────────────────────────────────────────┐   │
│            │  │ [📎]  输入消息……                            [停止]  │   │
│            │  └──────────────────────────────────────────────────────┘   │
└────────────┴─────────────────────────────────────────────────────────────┘
```

**区域联动**：
- 会话列表：会话 C 标记 ●（有 active run）
- 对话区：Turn 1 出现，过程面板 **auto-expanded**（run 活跃），思考条目 ⏳ 进行中
- Composer：`[发送]` → `[停止]`（run 进行中）

### 阶段 3.2：能力调用执行中

### 全屏对比要点

核心原则：**完成后呈现相同的持久化事实**，仅实时过程效果不同。

| 区域 | live 模式 | history 模式 |
|---|---|---|
| 会话列表标记 | ●（live） | ▸（历史） |
| 过程面板 | collapsed（完成后自动折叠，可展开查看 think/capability/降级/压缩） | collapsed（默认折叠，可展开查看相同的已持久化过程事实） |

| Composer | `[发送]` 可用 | `[发送]` 可用（发起新回合） |
| 过程动画 | running/settling/settled 动画 | 无动画，直接呈现终态 |

> history 模式通过 Message history 与 Event history 合并恢复助手终态、完成的 thinking、能力生命周期、降级提示和压缩通知。think/answer 字段级安全过滤的 owner、策略配置及各 surface 一致性仍为 B17/B18 clarify，不能把“dev 全显/prod 过滤”当作当前契约。稳定差异是 history 无打字机、running 动画、未完成 delta 或渐进式披露。
