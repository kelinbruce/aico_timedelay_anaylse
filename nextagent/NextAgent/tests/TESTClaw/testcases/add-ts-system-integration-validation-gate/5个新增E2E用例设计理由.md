# 5 个新增 E2E 用例设计理由

## TC-SI-115 Remote deployment 主链

已有 package/source 级组合不能证明外部部署形态通过真实 HTTP/SSE 对候选进程完成 acceptance、stream terminal 和 history。该用例以平台集成方最小主链为边界，补齐“可启动”到“可完成一次真实请求”的差距。

## TC-SI-116 电信 RAG + Sandbox 诊断

RAG 检索正确和 sandbox 执行正确分别通过，不代表一次电信运维诊断能在 trusted scope、治理、终态、history 和 audit 上保持一致。该用例选择典型网络诊断作为跨服务组合场景，同时验证故障定位证据不泄漏。

## TC-SI-117 SkillHub 获取到执行

下载、校验、安装、catalog 和 Skill invocation 的分段测试可能遗漏“安装完成但后续请求不可见”或“非法包半发布”。该用例把获取和后续真实执行闭合为一个用户可观察流程。

## TC-SI-118 Remote failure/cancel

远端边界的高风险不只在成功路径。非法 schema、HTTP failure 和主动取消可能产生重复 terminal、stream/history 分叉或 raw error 泄漏，因此三类分支由一个 case 统一验证同一安全终态不变量。

## TC-SI-119 三宿主真实后端

route fixture 能验证 UI 布局，但不能证明 local、immersive、collaborative 共享同一 canonical backend truth。该用例通过同一候选后端比较 session、submit、stream、pending input 和 refresh 恢复，确保宿主差异只影响投影，不生成平行业务语义。
