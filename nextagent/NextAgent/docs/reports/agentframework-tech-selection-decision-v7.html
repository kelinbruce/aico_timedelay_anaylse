AGENTFRAMEWORK TECHNOLOGY SELECTION

AgentFramework 技术选型与设计思路

选型结论

不直接采用或二开同类项目，生产控制面自研

同类项目已具备部分通用 Agent 能力，但网络智能体需要交付电信级高可靠、可审计、可解释、可运维，支持多租多用户，并具备网络运维专家思维能力的领域智能体；在既有项目上二开会改到核心执行链路、上下文管理、系统网关和数据存储，成本接近重构。

机制可借鉴 底座不复用 能力持续吸收

面向网络运维的差异化黑盒能力

多租多用户

多客户、多组织、多账号同时使用，历史、附件、记忆和审计相互隔离。

网络运维经验

记住告警处置、KPI 阈值、网元区域、厂家版本和班组经验，可遗忘可审计。

长时诊断不断线

跨多轮、跨系统、跨小时排障，断连、重启后能续接原任务。

人机协同可控

高风险操作先澄清、确认、审核；专家可接管，任务上下文不丢失。

过程结论可追溯

能回看判断依据、工具调用、处置过程和最终结论，便于复盘与问责。

能力统一接入

API、思维链、Skill、存量 Agent、周边服务和 OSS 能力统一纳管。

OpenClaw

开源 / 自托管 / 多渠道
公开资料显示：OpenClaw 强调开源、自托管、多渠道、技能生态和用户偏好，适合参考通用 Agent 平台的入口和能力组织方式。
可借鉴点 多入口、统一网关、扩展钩子、用户偏好和技能生态，适合参考平台入口、能力编排和偏好管理。
无法直接用 面向个人通用智能体，Token 消耗、安全控制和记忆系统都较粗；客户/账号隔离、告警/KPI 经验和运维审计需要重建。
引入方式
多渠道入口Gateway 适配自研控制面
Token 消耗大 安全性不足 记忆系统粗糙 过程结论留痕 网络系统网关
判断：可参考“平台骨架”，不宜作为网络运维生产底座。

Claude Code

商用产品 / 代码开发场景
官方定位是 agentic coding system，强项是读代码、改文件、跑测试和工具调用，适合参考编码 Agent 的执行体验。
可借鉴点 执行循环、上下文管理、缓存优先、权限控制、技能/子任务调用和断点恢复体验。
无法直接用 面向开发者的 Coding Agent，不是平台底座；缺少面向多租多用户、多会话并发、审计解释和运维责任闭环的设计。
引入方式
执行循环上下文策略运行时自研
缺少多租多用户 多会话并发不足 审计解释不足 客户系统集成
判断：可参考“Agent 执行技法”，不能作为可二开的电信平台底座。

Hermes Agent

开源 / 学习沉淀 / 多入口
公开文档显示：Hermes 强调自学习闭环、持久记忆、Skills、MCP、多入口和 Skill 自改进，适合参考经验沉淀机制。
可借鉴点 主动学习、记忆沉淀、Skill 总结、跨会话召回和能力自优化，适合参考“经验闭环”。
无法直接用 能学能记，但记忆对象偏个人/通用；网络运维经验需要结构化沉淀，并支持授权、遗忘、审计和隔离。
引入方式
经验沉淀记忆治理离线/在线学习
网络经验治理 可遗忘可审计 租户隔离 NMS/OSS/BSS 接入
判断：可参考“学习沉淀机制”，不能替代电信级运行底座。
一句话：自研不是重复造 Agent，而是把通用机制升级为电信网络运维生产底座：可隔离、可恢复、可审计，并可持续吸收新能力。
