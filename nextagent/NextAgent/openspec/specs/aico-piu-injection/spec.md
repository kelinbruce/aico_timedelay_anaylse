# aico-piu-injection Specification

## Purpose
Define AICOConfig PIU rendering injection behavior for custom operators, answer actions, quick input area, composer input operator, welcome guide area, and custom modal/panel lifecycles.
## Requirements
### Requirement: PIU rendering injection via Prel.autoLoad and piu.emit

Each PIU injection point SHALL render external PIU content through a unified mechanism: `window.Prel.autoLoad(piuName, piuVersion)` followed by `piu.emit(renderFunc, emitPayload)`. The `piuName`, `piuVersion`, `renderFunc`, and `data` fields come from the `PIUInfoItem` associated with the injection point.

The `emitPayload` MUST always include:
- All fields from `PIUInfoItem.data`
- `theme`: the current host theme value (`"lightday"` or `"evening"`), captured at render time
- `containerId`: a unique DOM element ID generated by the frontend for the PIU rendering container

The frontend MUST create a container DOM element with the generated `containerId` and pass it to the PIU via the emit payload. The PIU is responsible for rendering into that container.

When `window.Prel` is unavailable (e.g., local dev mode), the frontend MUST render a placeholder element and MUST NOT crash.

#### Scenario: PIU injection renders external content
- **GIVEN** a PIUInfoItem with `piuName: "customWidget"`, `piuVersion: "1.0.0"`, `renderFunc: "render"`
- **WHEN** the injection point activates
- **THEN** the frontend MUST call `Prel.autoLoad("customWidget", "1.0.0")`
- **AND** after autoLoad resolves, the frontend MUST call `piu.emit("render", { ...data, theme, containerId })`
- **AND** a DOM container with the `containerId` MUST exist in the document

#### Scenario: PIU injection in local mode shows placeholder
- **WHEN** `window.Prel` is not available and a PIU injection point is activated
- **THEN** the frontend MUST render a placeholder element
- **AND** the frontend MUST NOT throw an error

### Requirement: Custom operators injection

`operators` SHALL be an array of custom operator buttons injected into the toolbar. In local/immersive `operatorPosition: LEFT` mode, operators MUST be inserted in the sidebar below the favorites button and above the settings/help/logout group. In local/immersive `operatorPosition: RIGHT` mode and in collaborative mode, operators MUST be inserted in the top bar header alongside the default action buttons.

Each `Operator` has:
- `lightIcon` / `darkIcon`: base64-encoded icons for light/dark themes
- `enName` / `zhName`: display text; the frontend MUST select `zhName` or `enName` based on the current locale (zh-cn uses `zhName`, en-us uses `enName`). In sidebar expanded mode, the text is shown as button label. In collaborative/RIGHT header, OUTER operators show the text as a tooltip on hover. INNER operators inside the "more" menu also display the locale-appropriate name alongside the icon.
- `position`: `OUTER` (displayed alongside default buttons) or `INNER` (displayed inside a "more" menu)
- `type`: `MODAL` (opens a modal dialog) or `PANEL` (replaces the conversation panel)
- `data`: `PIUInfoItem` for rendering

When the number of `OUTER` operators exceeds the available space:
- In the sidebar (LEFT mode): the operator section MUST have a maximum height with vertical scrolling
- In the collaborative/RIGHT header: the operator section MUST support horizontal scrolling

#### Scenario: Operators appear in sidebar below favorites
- **GIVEN** local/immersive mode with `operatorPosition: LEFT` and AICOConfig provides two OUTER operators
- **WHEN** the sidebar renders
- **THEN** the custom operators MUST appear below the favorites button
- **AND** the settings/help/logout group MUST remain below the custom operators

#### Scenario: Operators appear in collaborative header
- **GIVEN** collaborative mode with AICOConfig providing OUTER operators
- **WHEN** the panel header renders
- **THEN** the custom operators MUST appear alongside the default header buttons (new session, history, float/dock, maximize, close)

#### Scenario: INNER operators go into more menu
- **GIVEN** an operator with `position: INNER`
- **WHEN** the toolbar renders
- **THEN** the operator MUST appear inside a "more" menu (three-dot icon)
- **AND** the more menu MUST display the operator icon and name

#### Scenario: Sidebar operator overflow scrolls vertically
- **GIVEN** more OUTER operators than fit in the sidebar's available height
- **WHEN** the operator section overflows
- **THEN** the operator section MUST scroll vertically
- **AND** the rest of the sidebar (favorites above, settings below) MUST remain visible

### Requirement: Operator MODAL type opens a single modal dialog

When an `Operator` with `type: MODAL` is clicked, the frontend MUST open a modal dialog containing a PIU rendering container. The modal size MUST use `PIUInfoItem.width` and `PIUInfoItem.height` if provided; otherwise it MUST use a default modal size of 800px wide by 600px high. Only one modal MUST be open at a time; clicking another MODAL operator MUST replace the current modal.

The emit payload for MODAL operators MUST be `{ ...data, theme, containerId }`.

#### Scenario: MODAL operator opens modal dialog
- **GIVEN** an operator with `type: MODAL` and `data: { piuName, piuVersion, renderFunc, width: 600, height: 400 }`
- **WHEN** the operator button is clicked
- **THEN** a modal dialog MUST open with width 600px and height 400px
- **AND** the PIU MUST be loaded and rendered inside the modal

#### Scenario: Second MODAL replaces first
- **GIVEN** a MODAL operator's modal is currently open
- **WHEN** another MODAL operator is clicked
- **THEN** the first modal MUST close
- **AND** the second modal MUST open with the new operator's PIU content

### Requirement: Operator PANEL type replaces conversation area with backFunc

When an `Operator` with `type: PANEL` is clicked, the frontend MUST switch the panel state from `CONVERSATION_PANEL` to `CUSTOM_PANEL`. The custom panel MUST replace the entire conversation area including the header, message list, input area, and disclaimer (and in `operatorPosition: RIGHT` mode, also the header bar) with a PIU rendering container. Only the sidebar (in LEFT mode) remains visible.

The emit payload for PANEL operators MUST include `{ ...data, theme, containerId, backFunc }`. The `backFunc` MUST be a function that, when called by the PIU, switches the panel state back to `CONVERSATION_PANEL` and unmounts the PIU container.

In `operatorPosition: LEFT` mode, the sidebar remains visible during CUSTOM_PANEL; the user can return to conversation via `backFunc` or by clicking "new session" in the sidebar. In `operatorPosition: RIGHT` mode, the header is also replaced; the only way back is `backFunc`.

Only one PANEL MUST be active at a time. Clicking another PANEL operator MUST first unmount the current custom panel, then load the new one.

#### Scenario: PANEL operator switches to custom panel
- **GIVEN** an operator with `type: PANEL`
- **WHEN** the operator button is clicked
- **THEN** the panel state MUST switch to `CUSTOM_PANEL`
- **AND** the conversation area MUST be replaced by a PIU rendering container
- **AND** the emit payload MUST include a `backFunc` function

#### Scenario: backFunc returns to conversation
- **GIVEN** a custom panel is active (panel state is `CUSTOM_PANEL`)
- **WHEN** the PIU calls `backFunc`
- **THEN** the panel state MUST switch to `CONVERSATION_PANEL`
- **AND** the PIU container MUST be unmounted
- **AND** the conversation area MUST be restored

#### Scenario: LEFT mode preserves sidebar during custom panel
- **GIVEN** local/immersive mode with `operatorPosition: LEFT` and a custom panel is active
- **THEN** the sidebar MUST remain visible
- **AND** clicking "new session" in the sidebar MUST return the panel to `CONVERSATION_PANEL`

#### Scenario: RIGHT mode replaces header during custom panel
- **GIVEN** local/immersive mode with `operatorPosition: RIGHT` and a custom panel is active
- **THEN** the header bar MUST be replaced by the PIU container
- **AND** the only way to return to conversation is via `backFunc`

### Requirement: answerOperator replaces assistant BubbleActions

When `answerOperator` is provided, it MUST completely replace the default `BubbleActions` component (copy, like, dislike, favorite, fork, share) for assistant answer messages. The PIU MUST be rendered for each assistant answer block.

The emit payload for `answerOperator` MUST include:
- All fields from `PIUInfoItem.data`
- `theme`: current host theme
- `containerId`: unique DOM element ID for this answer block
- `sessionId`: the current session ID
- `runId`: the run ID of the answer turn
- `answer`: the concatenated plain text of all text-type answer segments (markdown text and TEXT structured segments), excluding structured segments (PIU, DSL, FILE, ACTION, OPERATOR)

#### Scenario: answerOperator replaces default actions
- **GIVEN** AICOConfig provides `answerOperator`
- **WHEN** an assistant answer is rendered
- **THEN** the default BubbleActions MUST NOT be rendered
- **AND** a PIU container MUST be rendered in its place
- **AND** the emit payload MUST include `sessionId`, `runId`, and `answer`

#### Scenario: answer text excludes structured segments
- **GIVEN** an assistant answer contains a text segment, a FILE segment, and a PIU segment
- **WHEN** `answerOperator` renders
- **THEN** the `answer` field MUST contain only the text segment content
- **AND** FILE and PIU segment content MUST NOT be included in `answer`

### Requirement: quickInfo controls input-above area

`quickInfo` SHALL control the area above the input box. The `type` field determines what renders:
- `SKILL_LIST`: renders the default SkillSelector (current behavior)
- `CATEGORY_RECOMMEND`: renders the default CategoryQuestions
- `SELF_DEFINE`: renders a PIU container using `quickInfo.data` as the PIUInfoItem

When `quickInfo` is absent, the default `SKILL_LIST` behavior MUST be used.

#### Scenario: SELF_DEFINE quickInfo renders PIU
- **GIVEN** `quickInfo: { type: "SELF_DEFINE", data: { piuName: "customQuick", piuVersion: "1.0.0", renderFunc: "render" } }`
- **WHEN** the input area renders
- **THEN** a PIU container MUST replace the default skill selector
- **AND** the emit payload MUST include `{ ...data, theme, containerId }`

#### Scenario: SKILL_LIST quickInfo uses default
- **GIVEN** `quickInfo: { type: "SKILL_LIST" }`
- **WHEN** the input area renders
- **THEN** the SkillSelector MUST render as the default behavior

### Requirement: inputOperator replaces composer slash-hint area

When `inputOperator` is provided, it MUST replace the slash-hint area (the "输入 / 查看命令" text at the bottom of the composer). The PIU container MUST have a height matching the adjacent action button row and a width spanning from the left edge to 16px left of the retry button (or the leftmost action button if retry is absent).

The emit payload for `inputOperator` MUST be `{ ...data, theme, containerId }`.

When `inputOperator` is absent, the default slash-hint MUST be displayed.

#### Scenario: inputOperator replaces slash-hint
- **GIVEN** AICOConfig provides `inputOperator`
- **WHEN** the composer renders
- **THEN** the slash-hint MUST NOT be displayed
- **AND** a PIU container MUST be rendered in its place
- **AND** the container height MUST match the action button row height

#### Scenario: Absent inputOperator shows slash-hint
- **WHEN** AICOConfig does not provide `inputOperator`
- **THEN** the default slash-hint ("输入 / 查看命令") MUST be displayed

### Requirement: guideInfo controls welcome page guide area

`guideInfo` SHALL control the welcome page guide area (currently `GuideArea`). The `type` field determines what renders:
- `HIGH_FREQUENCY_RECOMMEND`: renders the default HighFrequencyQuestions (current behavior)
- `SELF_DEFINE`: renders a PIU container using `guideInfo.data` as the PIUInfoItem

When `guideInfo` is absent, the default `HIGH_FREQUENCY_RECOMMEND` behavior MUST be used.

#### Scenario: SELF_DEFINE guideInfo renders PIU
- **GIVEN** `guideInfo: { type: "SELF_DEFINE", data: { piuName: "customGuide", piuVersion: "1.0.0", renderFunc: "render" } }`
- **WHEN** the welcome page renders
- **THEN** a PIU container MUST replace the default HighFrequencyQuestions
- **AND** the emit payload MUST include `{ ...data, theme, containerId }`

#### Scenario: HIGH_FREQUENCY_RECOMMEND uses default
- **GIVEN** `guideInfo: { type: "HIGH_FREQUENCY_RECOMMEND" }`
- **WHEN** the welcome page renders
- **THEN** HighFrequencyQuestions MUST render as the default behavior
