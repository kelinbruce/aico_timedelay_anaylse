# FN-10.32 管理插件开发诊断产物

> 能力域 D10 二次开发与平台集成 · 子域 [D10.1 扩展与插件](.) · 返回 [功能树](../../index.md)

| 项 | 值 |
|---|---|
| 当前状态 | 稳定 |
| 覆盖特性 | [F-10.2](../../../features/D10-二次开发与平台集成/D10.1-扩展与插件/F-10.2-装配插件.md) |
| 主规格 | `plugin-developer-diagnostic-artifacts` |
| 接口 | 插件内部 `DeveloperDiagnosticArtifactSink.emit(input)`；不新增产品公共 API |

## 描述

系统在 LOCAL 和 REMOTE 部署中统一接收已通过启动校验的插件提交的开发诊断记录，并输出独立、有界且与主输出面隔离的短期物理产物，确保开发诊断不会形成绕过标准观测与安全边界的平行输出路径。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| artifactType | 是 | 插件提交的开发诊断记录类型 |
| 可选可信运行坐标 | 否 | 与记录关联的可信运行坐标 |
| payload | 是 | JSON-compatible 载荷 |

输入不得包含 `pluginId`、文件目录、文件名、轮转、压缩或保留策略；`pluginId` 由系统从已校验的插件 manifest 绑定。

## 输出

- 每次调用返回 `ACCEPTED` 或 `DROPPED`；`DROPPED` 时返回 `INVALID_RECORD`、`RECORD_TOO_LARGE`、`QUEUE_OVERLOADED` 或 `OUTPUT_UNAVAILABLE` 中恰好一个稳定 reason code。
- 已接受记录对应独立的 NDJSON 物理记录，位于 `paths.logDirectory` 下 `nextagent-plugin-diagnostic` 文件族，不与 operational log、audit 或 metrics 共享 active destination、文件 selector、maintenance state 或 retention lifecycle。

## 处理过程

1. 从已校验的插件 manifest 绑定 `pluginId`，校验 `input` 只包含 `artifactType`、可选可信运行坐标和 JSON-compatible `payload`；插件尝试控制物理输出或自声明 `pluginId` 时返回 `DROPPED` 且 reason code 为 `INVALID_RECORD`。
2. 以有界异步 enqueue 把已接受记录写入 `nextagent-plugin-diagnostic` 文件族；物理文件句柄 lazy 创建：首条合法记录触发 active destination，无记录时无文件副作用；不在插件 Hook、Tool 或 Policy 路径执行同步文件 append、flush、gzip、目录扫描或 retention。
3. 对文件族应用固定 daily boundary 或 active segment 达到 `30 MiB` 时轮转，closed segment 经 `.gz.tmp` 原子提交 `.gz`，并按 elapsed retention 与 archive count 独立删除条件回收；单条记录超过 `4 MiB` 时以 `RECORD_TOO_LARGE` 丢弃且不部分写入。
4. 记录非法、超限、队列过载、destination 不可用、maintenance 失败或 close 超时时，不改变插件贡献的业务结果、request terminal result 或 Agent activation，且不把该失败写入 operational log、audit、metrics、timeline、stream 或 Web 公共响应。
5. 维护受信本地开发诊断状态，只暴露 `availability`、saturating `droppedCount` 和可选 `lastFailureCode`，不包含 artifact payload、原始异常、宿主路径、credential、token、tenant identity 或 subject identity。
6. 仅在 system config 启用 artifact 输出且 Agent activation 启用相应调测插件时生成记录；文件族视为潜在敏感内容，不读取、投影或镜像到 operational log、audit、metrics、timeline、stream、Web 公共 API 或普通 readiness payload。
7. 内置调测插件 `developer-hook-trace` 与 `context-monitor` 按各自 lifecycle stage 提交统一 `artifactType` 记录，保留原始 boundary 内容，不接受或使用 `logDirectory`、`logFile`，不直接创建、追加、覆盖、轮转或删除宿主文件。

## 结果

- 正常：LOCAL 和 REMOTE 部署一致接受合法记录并写入独立物理产物，返回 `ACCEPTED`。
- 拒绝：非法输入、超限记录、队列过载或 destination 不可用时返回 `DROPPED` 与稳定 reason code，且不创建或修改插件指定的文件。
- 隔离：原始调测内容不进入主输出面；主输出维护扫描遇到该文件族成员时保留该文件，只有该文件族 lifecycle 可轮转、压缩或删除。

## 规格

| 规格项 | 规格值 | Requirement 来源 |
|---|---|---|
| 部署支持范围 | LOCAL、REMOTE 及后续受支持部署模式默认可写；同一 manifest 绑定的 `pluginId` 在两部署一致 | `plugin-developer-diagnostic-artifacts`：`系统统一接收插件开发诊断记录` |
| 物理产物边界 | 直接位于 `paths.logDirectory` 的独立 NDJSON 文件族，`nextagent-plugin-diagnostic` 专属前缀，不创建额外子目录；不与 operational/audit/metrics 共享 active destination、selector、maintenance state 或 retention lifecycle | `plugin-developer-diagnostic-artifacts`：`开发诊断记录使用独立的短期产物文件族` |
| 有界容量与生命周期 | daily boundary 或 `30 MiB` 先到先轮转；closed segment 保留 `3` elapsed days 且最多 `10` 个 committed gzip archive；单条记录上限 `4 MiB` | `plugin-developer-diagnostic-artifacts`：`产物写入具有有界容量和生命周期` |
| 主输出面隔离 | 文件族视为潜在敏感内容；不读取、投影或镜像到 operational log、audit、metrics、timeline、stream、Web 公共 API 或普通 readiness payload | `plugin-developer-diagnostic-artifacts`：`原始调测内容与主输出面隔离` |
