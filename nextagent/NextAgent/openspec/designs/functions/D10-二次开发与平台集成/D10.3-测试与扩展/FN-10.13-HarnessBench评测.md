## 描述

系统以 `node tests/harnessbench/run.mjs` 为唯一标准全量评测入口，接收固定 HarnessBench commit 和真实模型运行条件，覆盖该基线完整 task catalog，通过真实 NextAgent 产品边界执行评测，输出逐任务终态结论、框架效果得分（`frameworkEffectScore`）和可追溯的安全报告。本能力不属于发布门禁默认阻断，不定义发布阈值。

## 前置条件

- 已固定 HarnessBench commit（完整 40 位提交哈希）并加载其完整 task catalog。
- 已完成当前工作树的 NextAgent 构建。
- 候选模型与 grader 的 provider/model/credential 安全引用和评测运行环境已就绪。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| HarnessBench commit | 是 | 固定的完整 40 位提交哈希；评测开始后不得改变 |
| 候选模型标识与安全引用 | 是 | provider、model id 与 credential 安全引用；不得来自 task 输入或评测清单 |
| grader 标识与安全引用 | 是 | provider、credential 与 model id 的显式安全引用 |
| 运行预算 | 是 | 模型调用、超时和执行边界预算 |

计分模式固定为全量 catalog 评测；定向运行范围固定为版本控制内的非计分 profile。

## 输出

全部 task 的终态结论、评分覆盖及覆盖缺口、跨 adapter 轮次归并的安全失败诊断、模型输出上限观测、逐 task 评分和两组显式总体的互斥计分统计，以及内容一致的 schema version 4 JSON 报告和 Markdown 摘要。完整计分运行无论评分覆盖是否完整均输出 `frameworkEffectScore`；覆盖退化时同时标记 `evaluationValidity=degraded` 和 `coverageGap`。

## 处理过程

1. 解析并固定 HarnessBench commit、NextAgent commit、模型标识和完整 task catalog，生成与上游 catalog 恰好一致的不可变全量评测清单；每个 task id 恰好出现一次，状态为 `execute` 或具有非空原因的 `unsupported`。评测开始后不得增加、删除或改变清单项。
2. 分别校验候选模型与 grader 的 provider、credential 和返回结构；任一前置条件无效时在第一个计分 task 前终止且不产生 `frameworkEffectScore`。
3. 对状态为 `execute` 的 task 通过当前 NextAgent local runtime 的公开会话、请求和 stream 行为提交任务并等待 terminal result；状态为 `unsupported` 的 task 以 `0` 分形成终态结论并排除出 `scoringDenominator`。mock 模型、固定答案、直接领域 service 调用、伪造 terminal result 或 NextAgent 之外的结果生成不得构成评测证据。
4. 为每个非成功 task 汇聚全部 adapter 轮次的结构化安全证据，给出唯一的安全失败阶段和闭集原因码；已知 stream 等待失败区分 HTTP 响应失败、terminal 前关闭和 transport 失败，携带合法 cursor 的 idle-close stream 在同一 accepted run 上续接且不重置总等待预算。模型输出达到候选上限只形成独立观测事实，不改变 terminal、重试或计分结论。
5. 纯基础设施失败（无模型请求、无工作区结果、无上游结果）至多自动重试一次；其他失败不重试。重试记录非敏感 attempt ledger，不改变固定计分规则。
6. 验证每个获得非零 `taskScore` 的 `execute` task 至少有一次成功上游模型请求和大于 0 的总 token 用量；缺失时该 task 以 `model_evidence_missing` 零分结束并计入分母。
7. 汇总全部 task 终态结论和评分覆盖，按全部 `execute` task 的 `taskScore` 与 `terminalStatus=scored` task 的 `combinedScore` 分别生成显式总体和互斥分档，生成 JSON 报告与 Markdown 摘要；发布前扫描禁止内容，命中时拒绝发布并返回失败。

## 结果

- 正式发布：全部 task 形成终态结论的完整计分运行发布 `frameworkEffectScore` 和完整报告；评分覆盖退化时仍发布得分并显式给出 `coverageGap`。
- 不发布正式总分：非法基线、替代执行路径、前置条件失败、定向运行、运行未完成或报告命中禁止内容时，不产生 `frameworkEffectScore`；部分报告说明原因且标准入口退出码非 `0`。

## 规格

| 规格项 | 规格值 | Requirement 来源 |
|---|---|---|
| 评测模式 | 全量计分与定向非计分两类；定向 profile 显式声明 `nonScoring` 且不生成 `frameworkEffectScore` | `harnessbench-evaluation`：`评测运行固定版本与任务边界`、`定向回归运行不得计分` |
| 评测范围 | 默认 106 task（固定 HarnessBench commit 的完整 catalog）；`unsupported` 排除出分母，全部 `execute` task 无论终态如何均计入 `scoringDenominator` | `harnessbench-evaluation`：`统一计算逐任务分数与框架效果得分` |
| 框架效果得分 | `frameworkEffectScore = round(sum(taskScore) / scoringDenominator, 4)`，输出四位小数；完整计分运行即使评分覆盖退化仍发布，并附带 `coverageGap` | `harnessbench-evaluation`：`统一计算逐任务分数与框架效果得分` |
| 报告与诊断 | schema version 5 JSON 报告 + 内容一致 Markdown 摘要（增加 reasoning-only 输出耗尽独立观测事实及聚合计数）；包含多轮安全诊断、模型输出上限观测、两组显式总体及互斥分档；stream 等待失败使用 `STREAM_HTTP_FAILED`、`STREAM_CLOSED_WITHOUT_TERMINAL`、`STREAM_TRANSPORT_FAILED` 或 `TASK_TIMED_OUT` | `harnessbench-evaluation`：`评测报告可追溯且可恢复`、`模型输出上限仅形成观测事实`、`计分报告提供显式总体的互斥统计`、`stream 等待失败使用可行动的闭集原因码` |
| HarnessBench 执行预算 | 隔离 candidate 的每次模型调用 `300,000 ms`；每个 `execute` task 的 terminal 等待 `1080 s`、generic CLI 子进程 `1200 s`，CLI runtime cleanup 和 workspace export 余量恰好 `120 s` | `harnessbench-evaluation`：`候选模型调用与任务执行采用分层预算`、`任务执行为结果收集保留确定预算` |
| 候选模型调用预算 | 标准全量与全部固定定向回归的 candidate profile 固定使用 `16384 tokens` 基础输出预算和 `540 s` 单次调用超时；不得按 task 动态改写 | `harnessbench-evaluation`：`候选模型使用固定的基础输出预算`、`候选模型使用固定的单次调用超时` |
| 本机 mock endpoint 暴露方式 | `HARNESSBENCH_PUBLIC_URL_TEMPLATE={local_url}`；不要求公网 tunnel | `harnessbench-evaluation`：`本机 mock endpoint 不依赖公网 tunnel` |
| Windows 上游 Python 解释器 | Windows 评测运行前置验证上游 `python3` 命令与已预检解释器身份一致，任一前置失败不执行 task；上游 task 与 Oracle 通过本次运行可见的 `python3` 使用已预检解释器，不改变主机全局环境 | `harnessbench-evaluation`：`Windows 上游 Python 命令使用已预检解释器` |
| HarnessBench 候选 sandbox 模式 | 全部 `execute` task 和全部执行 attempt 固定 `sandbox.enabled=false`；评测外产品配置不变 | `harnessbench-evaluation`：`候选运行时禁用本地沙箱` |
| 多轮会话连续性 | 同一 HarnessBench session id 的全部顺序轮次复用同一 NextAgent 候选持久化边界和 session；不同 session id、task 或 run 不共享状态 | `harnessbench-evaluation`：`多轮任务保持会话连续且跨任务隔离` |
| 定向回归 | `failure-recovery-regression` 与 `stream-failure-regression` 均为固定 `nonScoring=true` profile，不发布 `frameworkEffectScore` | `harnessbench-evaluation`：`剩余失败类型具有固定恢复回归入口`、`stream 失败具有固定非计分回归入口` |
