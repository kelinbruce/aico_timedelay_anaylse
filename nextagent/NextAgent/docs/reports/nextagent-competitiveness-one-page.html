核心目标
匹配模型技术演进，建设 LAM 编排 Skill、Tool、SubAgent 的框架，提升网络智能体的泛化性和智能感。
实现电信级可靠性，支撑长时任务运行、人工接管、过程可观测、结论可解释和审计可追溯。
形成受治理的能力接入底座，让管控单元、客户系统和业界新技术快速纳入网络运维智能体生态。
01

业务诉求

任务泛化
网络任务形态复杂：需要模型能按场景组合 Skill、Tool、SubAgent、知识检索和客户 API。
长时可靠
诊断不是一次问答：跨告警、KPI、拓扑、工单和工具执行时，需要可暂停、可恢复、终态一致。
人机协同
高风险动作要可控：澄清、确认、授权、人工接管都要在同一运行生命周期内暂停、恢复和超时。
生态接入
能力来源持续变化：管控单元、客户系统、SOP、API 工具和业界新技术要快速接入且受治理。
业务结论：客户需要的是能编排能力、稳定运行、可被接管并接入生产网络的智能体框架。
02

同类项目缺口

Claude Code

缺口：面向软件研发提效，不负责电信生产运维的工具治理、权限隔离、审计追溯和运行恢复。

OpenClaw

缺口：通用入口、技能和多渠道有参考价值，但行业生产仍需重建权限、能力目录、审计和质量约束。

Hermes Agent

缺口：学习、记忆和 Skill 改进值得借鉴，但网络经验仍要结构化治理、授权隔离和可遗忘审计。

选型结论：三类项目机制可吸收，但缺口都落在生产控制面，直接二开会改到主路径。
03

策略与竞争力

  • 面向 LAM 演进，把 Tool、Skill、SubAgent、RAG、记忆和客户 API 统一纳入 Capability 编排。
  • 面向生产运行，让 runtime 拥有长任务生命周期、暂停恢复、人工输入、终态提交和可观测事实。
  • 面向生态接入，以 OpenSpec、Gateway、Sandbox 和验收门禁约束管控单元与新技术快速接入。
竞争力差异化规格 / 量化口径
LAM 编排统一 Capability：Tool / Skill / Agent 三类能力；SubAgent 以 governed AGENT descriptor 调用。
任务泛化覆盖告警、KPI、拓扑、工单、CLI/API、RAG、记忆等跨系统诊断输入。
长时可靠同 session lane 串行调度；支持 cancel / retry / edit / terminal commit / stream resume-replay。
人机接管3 类 PendingInput：QUESTION、CONFIRMATION、AUTHORIZATION；超时默认非批准。
隔离审计2 层 Scope：Agent Scope + Owner Scope；Session 绑定 agentId，Run 固化 assembly。
快速接入4 道接入门禁：OpenSpec、Gateway、Sandbox、schema/architecture validation。
