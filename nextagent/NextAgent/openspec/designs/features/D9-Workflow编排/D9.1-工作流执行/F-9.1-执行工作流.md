## 用户价值

系统将复杂运维任务编排为可追踪的工作流，支持配方匹配、执行和待确认输入桥接，把知识检索、模型推理、能力调用和用户交互组织成可追踪的执行流程。

## 主要用例

- 通过可信 directive、routing constraint 或 Agent 决策选择已注册 Recipe。
- 顺序或分支执行多个节点，并把安全结果传递给后续节点。
- 在需要用户输入时暂停 owning request，回答后沿同一 runtime lifecycle 继续。
- Capability 失败时按 Recipe exception 分支处理，未匹配时明确失败。

## 黑盒边界

- 工作流不拥有请求生命周期、取消、检查点、终态提交或待确认输入存储，这些归运行时。
- 工作流经运行时拥有的状态接口与运行时协作。
- Capability 最终失败不进入 Workflow 节点 retry，只求值显式 exception；取消直接中断，无匹配分支时 Workflow 失败。
- 合法 `NODE_WAITING` 使用成功控制结果表达，缺少 pending context 时不得伪装等待。
- 首版不承诺 distributed scheduling、durable Workflow snapshot/resume、rollback/degrade 或独立 Workflow history。

## 适用质量属性

- 确定性：同一 Recipe、输入和受治理依赖遵循明确节点与 exception 路由。
- 可靠性：取消、等待、失败和成功保持不同控制语义。
- 可审计性：工作流通过 runtime-owned canonical events 暴露过程，而不复制 lifecycle truth。
- 可维护性：Recipe orchestration、Capability invocation 和 runtime durability 各自保持单一 owner。
