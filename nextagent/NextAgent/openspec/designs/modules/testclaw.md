# TESTClaw Module

TESTClaw is the binary-package black-box testing module for NextAgent. It is not a production backend package and does not own runtime lifecycle, contracts, persistence or transport behavior. Its ownership is limited to package verification scaffolding, runner scripts, test helpers, report generation and local package test configuration under `tests/TESTClaw/`.

The module verifies an extracted package in `target/`. Binary package commands such as `nextagent-self-check`, `nextagent-start` and `nextagent-stop` execute from the package root because the packaged scripts resolve runtime files from `process.cwd()`. TESTClaw framework commands run from `tests/TESTClaw/` and must not silently switch into `target/` except where an individual test explicitly invokes a packaged command with the required working directory.

The unified runner `scripts/run-tests.ps1` owns local verification flow orchestration for TESTClaw: pre-flight self-check, API environment validation, service start/stop for E2E suites, reachability checks for `-NoStart`, terminal encoding setup, progress logging and timing summary. The runner is a test harness concern and must not become a product runtime lifecycle owner.

Vitest backend tests and Playwright E2E tests remain independent within TESTClaw. Vitest backend tests stay sequential because they can touch local SQLite-backed package state. Playwright E2E tests may run with bounded parallel workers because they exercise public HTTP/SSE behavior against the running packaged service.

TESTClaw reports are written to `test-output/` as JSON and HTML artifacts. Reports must contain enough totals and failure details for release diagnosis, while logs and reports still follow repository safety expectations: they must not intentionally capture credentials, raw provider errors, prompt text, model output or unbounded local paths.

TESTClaw consumes existing product contracts through the packaged CLI and HTTP/SSE surfaces. It must not introduce parallel public contracts, private package imports into production code, or source-workspace-only assumptions that would make binary package verification pass for the wrong reason.

TESTClaw is the sole execution owner of the system-integration validation gate (`FN-10.31 验证系统集成`，spec `ts-system-integration-validation-gate`). The gate consumes a version-controlled 122-case manifest (`TC-SI-001..122`：41 fixed gate + 49 backend E2E + 24 browser E2E 同步场景，加 3 个新增系统集成和 5 个新增 E2E 流程) and independently executes each case against the candidate package root (`NEXTAGENT_PACKAGE_ROOT`，缺省 `tests/TESTClaw/target`) and an external packages root (`NEXTAGENT_EXTERNAL_PACKAGES_ROOT`) containing remote package public artifacts and the `@nextagent/agent-web-test-hosts` hosting export. Standard command: `npm --prefix tests/TESTClaw run test:system-integration`；源码 checkout 追加 `test:system-integration:sync` 校验来源漂移。The gate MUST NOT import source code, private paths or `@nextagent/*/testing`，MUST NOT read source test reports, and MUST NOT count skip/todo/mock/source-report results as pass. It produces a machine-readable `report.json` (`checkId=system-integration`，`layers={INTEGRATION,E2E}`) with per-case results, bidirectional tracing and safe evidence refs; candidate local operational diagnostics stay in a restricted diagnostic root and MUST NOT be copied to the exported evidence boundary. Each run uses isolated ports, temp roots, Skill install root, browser state, restricted diagnostic root and evidence root, and `finally` stops processes and deletes the restricted diagnostic root.
