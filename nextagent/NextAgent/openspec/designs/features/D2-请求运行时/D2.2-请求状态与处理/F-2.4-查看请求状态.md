## 用户价值

- 用户可以区分请求的处理状态，通过受治理业务标题识别 Capability 步骤，并在不暴露原始输入输出或内部资源的前提下了解执行过程、安全结果和已确认的失败事实。扩展 Capability 的标题可以使用宿主提供的产品业务语言，平台固定名称、过程结构和结果安全边界保持不变。
- Workflow 执行过程只展示已配置业务标题及其实际状态，以及非失败无标题 occurrence 的产品正文；无业务标题的内部节点不暴露技术身份，执行期间和完成后不形成可见步骤跳变。
- 业务开发调测者可以在 `Skill`、`Agent` 和普通 Tool 生命周期下的 `ApiCall` 过程标题中识别实际执行的技术目标名称，同时结果披露和安全降级边界保持不变。
- 实时执行、刷新后的历史会话和三种 Agent Web 宿主使用同一安全投影，避免同一请求在不同入口出现冲突状态。
- 用户以固定、事实性的业务语言理解处理受限和上下文整理提示，不需要辨认内部事件名、Hook 身份或任意诊断文本；刷新后的 durable 提示保持相同语义。
- 跨会话列表持续显示等待输入、运行中、未读失败和未读结果，使后台会话无需逐个打开即可被发现。

## 主要用例

- 查看当前请求的执行身份、状态、摘要和受控详情。
- 查看 Grep 文件模式或内容模式的正确计数；详情只显示有界逻辑路径和内容匹配行号，不显示匹配正文。
- 以当前界面的业务语言识别普通 Tool、Agent、Skill 和 Workflow 过程步骤；未知或非法身份安全降级。
- 刷新后继续浏览历史请求的安全过程投影，不产生逐结果请求放大。
- 在折叠过程、完整运行图和实时上下文整理提示中识别一致的 warning/info 业务语义；主动展开时只查看允许披露的安全技术码。
- 在 Sidebar、搜索、History CardList 和 collaborative History 中定位需要注意的后台会话。
- 打开对应会话并真实呈现匹配终态后，清除该会话的未读结果或失败提示。

## 黑盒边界

- 状态来自后台权威记录，前端不创造与后台竞争的状态。
- 业务标题只由最小公开身份、集中映射和平台固定模板生成，不改变执行身份、过程结构或结果策略。
- 平台安全上限先于集成配置，集成方只能收窄或在安全上限内选择呈现级别。
- Grep 结果缺少可信模式或不满足模式专属 schema 时只显示状态，前端不从数组、消息或参数猜测模式。
- 普通 conversation Message 不作为 Capability 过程详情来源；浏览器不得解析原始或隐藏 Message 重建详情。
- 降级不作为单独状态，通过提示事件表达；系统过程提示只陈述事件事实，不推断请求终态、自动恢复、后续行动或最终答复内容。
- 状态展示是异步观察，不推进 Capability 执行、模型下一轮、重试、恢复或 request terminal。
- Session Activity 只观察已提交 canonical facts；列表 marker、hover、route selection、连接重建或本地 countdown 都不能推进 lifecycle 或消费终态。
- 受控原始诊断继续属于开发工作台等独立安全边界，不由普通 Agent Web 呈现策略开启。

## 适用质量属性

- 安全：结果披露受平台安全上限约束，普通 Agent Web 不暴露原始诊断内容或系统过程事件中的任意 payload 文本；详见 `ts-run-status-visibility`。
- 性能与容量：历史浏览使用有界过程投影，不产生逐结果请求放大；详见 `ts-run-status-visibility`。
- 可靠性与恢复：跨会话 Activity 使用权威快照、增量和重连语义，未读终态只在匹配内容真实呈现后消费；durable 系统过程事件在 live/history 中保持相同语义，live-only 提示不被伪造为历史；详见 `cross-session-activity-awareness`、`ts-run-status-visibility`。
- 可测试性：状态优先级、作用域隔离、多宿主一致性和未读消费条件均由稳定 spec 提供可观察验收边界。
