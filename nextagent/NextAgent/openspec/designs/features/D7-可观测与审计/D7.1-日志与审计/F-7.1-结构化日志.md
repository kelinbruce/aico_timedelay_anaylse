## 描述

系统输出结构化安全日志，业务模块通过观测事件输出，日志写入不阻塞请求终态。本地 operational physical destination 同时承载 `observation_derived` 安全 canonical lifecycle 和 `runtime_diagnostic` 本地原始诊断，使运维人员可以按可信 trace 关联复杂请求、读取 terminal 汇总、识别错误分类并定位实际部署与 package owner。

## 边界

- 日志经脱敏，不包含敏感内容。
- 业务日志与运行时诊断日志职责分离，两者写入同一 operational physical destination 但不互换 surface。
- 日志写入有背压策略，不阻塞请求终态提交。
- 启用 tracing 时，lifecycle、Model/Tool payload 与 execution exception entry 输出可信 `traceId`/`spanId`；trace 坐标不进入 Web、stream、audit、metric、public DTO 或 `ObservabilityObservationEvent`。
- terminal entry 输出 canonical `status`、聚合 usage、`toolCallCount` 和 `summaryStatus`，不重复原始异常正文。
- 每条 product entry 使用实际 deployment `serviceVersion` 和 owning package `component`。

## 规格

| 规格项 | 规格值 | 状态 | 来源 |
|---|---|---|---|
| 单请求最大日志事件数 | 200 | 建议评审值 | 建议补充 |
| 日志字段最大长度 | 2,000 字符 | 建议评审值 | 建议补充 |
| 日志采样率 | 错误 100%、信息 100%、调试默认 0% | 建议评审值 | 建议补充 |
| 日志文件保留策略 | 14 天，单文件 100 MiB，最多 20 个文件 | 建议评审值 | 建议补充 |
| 请求终态汇总 | `status`、Model token usage、`toolCallCount`、`summaryStatus=COMPLETE|PARTIAL` | 稳定 | `runtime-logging`：`Request terminal entry 提供可验证汇总` |
| 执行关联 | 启用 tracing 时可信 `traceId`/`spanId` 及 run/step/invocation 坐标 | 稳定 | `runtime-logging`：`Operational entry 使用可信执行关联坐标` |
