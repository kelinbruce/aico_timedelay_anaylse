# FN-10.4 自定义工具和提示词

> 能力域 D10 二次开发与平台集成 · 子域 [D10.1 扩展与插件](.) · 返回 [功能树](../../index.md)

| 项 | 值 |
|---|---|
| 当前状态 | 稳定 |
| 覆盖特性 | [F-10.4](../../../features/D10-二次开发与平台集成/D10.1-扩展与插件/F-10.4-自定义工具与提示词.md) |
| 主规格 | `prompt-template-assembly` |
| 遗留规格 | `builtin-tool-framework`、`capability-source-configuration` |
| 接口 | 工具定义框架 + 提示词模板装配 |

## 描述

开发者通过定义框架自定义工具，通过模板装配自定义提示词，经能力治理接入主路径。提示词模板通过唯一 public resolver contract 支撑 router 与其它 model-facing consumer，同时保持注册模板的选择、fallback 与渲染归 Context Engine；consumer-owned default content 不进入 Context Engine。

## 前置条件

- 工具或提示词模板已注册。

## 输入

| 参数 | 必填 | 说明 |
|---|---|---|
| 工具元数据和实现 | 是 | 自定义工具定义 |
| 提示词模板 | 否 | 自定义提示词模板 |
| resolver 请求 | 否 | `PromptTemplateResolverPort.resolve(request, signal)`：purpose、Agent scope、locale、string-only flow variables、closed selected model、optional `memoryEnabled` |

## 输出

注册的工具或提示词模板，进入能力治理；resolver 返回 `RESOLVED`（safe template identity、rendered sections/content、optional canonical model options handoff）或 `NOT_FOUND`。

## 处理过程

1. 开发者通过定义框架定义工具元数据和实现。
2. 自定义提供者承载工具。
3. 提示词模板使用规范模型标识作为匹配字段，并按用途装配、受控变量渲染。
4. 系统按同一次渲染的进程本地时区和时刻解析受治理的时区与日期变量：`timezone` 表示该进程的 IANA 时区，`currentDate` 表示该时区中渲染时刻对应的 `YYYY-MM-DD` 日历日期；不使用 UTC 日期与非 UTC 的 `timezone` 组成同一次渲染结果。
5. 模板只约束兼容模型，不建立第二套模型选择规则。
6. 模板封闭 `modelOptions` 可以声明 canonical `toolChoice: AUTO | NONE | REQUIRED`，不能声明 named-tool object、Agent loop limits 或 provider-native alias。
7. 模板模型选项遵循与模型调用一致的公共约束，工具和提示词经能力治理接入主路径。
8. 其它 model-facing consumer 只通过唯一 `PromptTemplateResolverPort` 使用 frozen Agent-scoped template selection/rendering；不公开 registry、loader、compiler、template source 或 internal assembler。
9. builtin `task_approach` 模板提供复杂 workspace task 的有界产物执行指导：先完成确定结构所需的最小检查，再尽早形成全部必需产物的最小有效版本、分段补全并在结束前验证；Agent package 覆盖优先级保持不变。
10. builtin `SYSTEM_PROMPT` 的 `task_approach` section 同时提供语义验收闭环指导：正确性依赖用户显式规则和本地来源证据的 workspace task 在宣称完成前逐项关联全部显式规则、来源证据和对应产出结果，复核规则覆盖、证据支持与结果间一致性；分类、聚合、交叉引用和审计结果从来源证据重新核对；发现不一致先修正结果，证据不足或规则冲突时明确保留可核查的限制说明；文件存在、语法可解析或格式验证通过不能单独证明语义验收完成，不得编造缺失事实。

## 结果

- 正常：工具或提示词注册成功；渲染结果中的 `timezone` 与 `currentDate` 表达同一个进程本地日历事实；resolver 匹配时返回 `RESOLVED`，无匹配模板时返回 `NOT_FOUND`。
- 定义无效：安全失败。

## 规格

| 规格项 | 规格值 | 权威来源 |
|---|---|---|
| Prompt 模板格式 | `prompts/{templateId}/template.yaml` 或 `prompts/{templateId}.yaml`，schema 为 `nextagent.prompt-template/v1` | `prompt-template-assembly`：`Prompt template sources are compiled before request path` |
| 内置 Prompt purpose | `SYSTEM_PROMPT`、`SUMMARY_GENERATION`、`MEMORY_EXTRACTION`、`AGENT_ROUTING_SELECTION`；开发者可以使用合法自定义 purpose | `prompt-template-assembly`：`Prompt templates are assembled by purpose` |
| 模板选择 | `agent` 来源优先于 `builtin`；同来源选择匹配 specificity 最高的单一完整模板，不拼接多个模板 | `prompt-template-assembly`：`Prompt template selection is deterministic` |
| 模板 Tool 选择 | `modelOptions.toolChoice` 可选 `AUTO | NONE | REQUIRED`，作为 Context Engine 的 optional override；不支持 named-tool choice | `prompt-template-assembly`：`Prompt template selection is deterministic` |
| 日历变量同源 | `timezone` 与 `currentDate` 从同一次渲染的进程本地日历事实解析；`currentDate` 为该时区 `YYYY-MM-DD`，不与 UTC 日期混用 | `prompt-template-assembly`：`Prompt 日历变量使用同一进程本地语义` |
| Skill 披露变量 | SYSTEM_PROMPT 注册表提供 `skillDisclosureList`、`skillDisclosureMode`、`skillDisclosureBody` 三个安全投影变量；`enabledSkills` 已删除，引用它的模板编译期 fail closed | `prompt-template-assembly`：`Prompt rendering supports governed template variables and optional substitutions` |
| Skill 披露定制 | Agent 可经 agent-over-builtin SYSTEM_PROMPT 覆盖机制定制 `skill_disclosure` section；覆盖内容受渲染门控约束（`Skill` tool 不可见或列表为空时省略） | `prompt-template-assembly`：`System prompt skill disclosure section` |
| 跨场景 template resolution | 其它 model-facing consumer 只通过唯一 `PromptTemplateResolverPort` 使用 frozen Agent-scoped template selection/rendering | `prompt-template-assembly`：`Prompt assembly has one decision boundary`、`Prompt assembly boundary guardrails` |
| 工具接入方式 | `defineTool` 只简化工具定义；工具仍须通过显式 provider 和能力目录注册进入执行路径 | `builtin-tool-framework`：`defineTool simplifies Tool authoring without creating a registration path` |
