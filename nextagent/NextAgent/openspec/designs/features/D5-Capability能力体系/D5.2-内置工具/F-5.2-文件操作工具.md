## 用户价值

Agent 可以在受控 execution view 中定位、分页读取、创建和精确修改电信运维文件。普通文件的默认位置和返回身份统一为 `workspace/...`（bare workspace path 是输入别名），成功结果返回 root-qualified canonical path 供调用方稳定复用。需要跨 run 保留的产物可以显式写入 `workspace/`，同时保留分页、快照冲突、授权和截断事实；显式有效 `.nextagent/skills/...` 路径独立于 workspace 目录权限保持只读访问。

## 主要用例

- Bash 或 Python 生成无 root 前缀的诊断结果后，Read、Glob 或 Grep 通过同一逻辑路径读取或搜索该结果。
- Write 或 Edit 将需要跨 run 保留的报告显式写入 `workspace/...`。
- Glob 或 Grep 缺省只搜索当前 Agent 获得授权的 workspace 范围，并跳过未授权系统资源；其他逻辑 root 只能通过显式、已授权的 root-qualified path 搜索。
- Grep 文件模式与内容模式返回自描述的实际输出模式；即使合法零匹配，消费方也无需根据空数组猜测搜索语义。
- Read 按 0-based offset 分页读取；Write/Edit 在完整读取或 snapshot 前提下执行原子替换或精确修改。

## 黑盒边界

- 本 Feature 包含 Read、Write、Edit、Glob、Grep 的路径解释、授权结果和逻辑路径输出，不包含 sandbox 隔离强度、附件 intake 或 Skill source 管理。
- 默认根统一不扩大系统管理 root、共享只读 root 或跨 execution scope 的访问权限。
- 模型可见结果不暴露物理 `scopeBase`、scope key、`/work` 映射或宿主绝对路径。
- 零匹配、声明预算截断、缺失、冲突、取消与内部失败保持各自可观察的安全语义。
- Grep 成功结果的模式、模式专属集合和总数保持一致，不返回物理路径或额外搜索输入。

## 适用质量属性

- 安全：由 `file-operation-tools` 的 `文件操作工具使用 execution view 默认根` 与 `file-search-tools` 的 `文件搜索工具使用 execution view 默认根` 承载路径隔离和物理路径不泄漏边界。
- 性能/容量：由 `file-search-tools` 的 Glob/Grep effective Read authority Requirements 承载单一全局排序与容量预算。
- 可靠性/恢复：Write/Edit 通过完整读取、snapshot conflict 与原子替换避免基于陈旧内容静默覆盖。
